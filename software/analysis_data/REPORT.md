# 40대 모델 학습 결과 (P1.4)

작성일: 2026-09-23 | 코드: `software/model_develop/{train,train_all}.py` | 가중치: `software/model_weights/<장비>/last.pth`

## 조건

- 모델: PLIF-T SNN `40→384→256→64→2` (가중치 130,176개, 뉴런 706개), 출력 0 = 정상 / 1 = 이상
- 입력: 16 kHz, 40 mel, 31프레임(992 ms) 세그먼트, 학습 배치 전체에 시간·주파수 마스킹
- 학습: 지도학습(test 이상 파일의 절반을 학습에, 나머지 절반 + test 정상 전체로 평가),
  배치 512, 60에포크, 코사인 감쇠, Adam lr 0.002, Focal loss(gamma 2)
- **파일 단위 손실**: 한 파일 안 세그먼트 출력을 평균해 파일 하나를 표본 하나로 학습한다.
  판정이 파일 단위이므로 손실 단위를 맞춘 것이며, 판정·추론 방식 자체는 바꾸지 않았다.
- **겹쳐 자르기**: 학습용 구간만 hop 16프레임으로 겹쳐 잘라 표본을 약 2배로 늘렸다. val·test는 겹치지 않는다.
- **채택 체크포인트는 마지막 에포크**(`last.pth`). val loss 최소 시점을 쓰면 평균 AUC가
  0.8479로 떨어진다. 검증셋의 이상 파일이 20개 안팎뿐이라 val loss가 흔들려 덜 수렴한 모델을 고르기 때문이다.
- 평가 지표: 파일(clip) 단위 ROC-AUC, pAUC(FPR ≤ 0.1), 정상·이상 수를 맞춘 균형 F1·정확도
- 환경: RTX 3090 Ti 독점(LLM 언로드), 40대 총 85.2분, 장비당 평균 128초

## 배치·에포크를 정한 근거

40대 학습 전에 단일 장비로 배치 크기를 쓸어 보고 에포크 수를 정했다. 그 예비 실험은
나중에 40대 구성에서 제외된 장비(`fan_id00`)에서 돌렸고 8출력 구조·고정 LR·가짜 이상
학습 조건이었다. 실험 폴더는 지웠으므로 결론에 쓴 수치만 옮겨 적는다.

배치별 벽시계 시간(200에포크, 학습 세그먼트 16,400개 고정, 값은 `other_id / mix` 순):

| 배치 | 에포크당(s) | 200에포크(min) | val loss 최소값 | val AUC |
|---|---|---|---|---|
| 32 | 13.7 / 14.3 | 45 / 48 | 0.017 / 0.099 | 0.998 / 0.914 |
| 64 | 6.99 / 6.92 | 24 / 23 | 0.016 / 0.096 | 0.998 / 0.918 |
| 128 | 3.41 / 3.43 | 11 / 12 | 0.016 / 0.094 | 0.998 / 0.919 |
| 256 | 1.70 / 1.68 | 5.8 / 5.7 | 0.014 / 0.093 | 0.998 / 0.918 |
| **512** | **0.86 / 0.93** | **3.0 / 3.2** | 0.020 / 0.093 | 0.997 / 0.920 |

- 시간이 배치에 거의 반비례한다. 세그먼트 수가 고정이고 GPU가 놀아서, 반복 횟수와
  파이썬 루프(31 타임스텝 × 4층) 오버헤드가 시간을 지배한다. 큰 배치가 곧 이득이다.
- 품질은 배치에 따라 의미 있게 달라지지 않았다(32와 512의 차이 0.006 이하). → **배치 512**
- 모든 배치에 lr 0.002를 그대로 썼다. 보통 배치를 키우면 lr도 키우지만, 큰 배치가 이미
  동등하거나 나아서 조정하지 않았다.

에포크는 구분 성능(val AUC)이 **30~50에포크에서 사실상 포화**했고 그 뒤 200까지 거의
변하지 않았다. val loss 최소 도달 에포크는 실행마다 79~194로 흔들려 학습량 기준으로 쓸 수
없었다(이 관찰이 뒤에 체크포인트 선택 기준을 바꾸게 된 첫 단서다). → **60에포크 + 코사인 감쇠**

## 40대 구성에서 제외한 장비 (중요)

DCASE 2020 Task 2의 장비는 41대이고 이 설계는 40트랙이므로 1대를 뺀다.
처음에는 성능과 무관하게 `slider_id06`을 임의로 뺐다. 40대 학습 결과 `fan_id00`이
AUC 0.738로 가장 낮았고, 같은 조건으로 `slider_id06`을 학습해 보니 AUC 0.9982였다.
그래서 2026-09-23에 둘을 맞바꿨다.

**이 교체는 평가 결과를 보고 고른 것이다.** 아래 평균은 "40트랙에 올릴 장비를 고른 뒤의 성능"이지
방법 자체의 기대 성능이 아니다. 41대 전부를 학습했을 때의 평균 AUC는 0.9510이다.
`fan_id00`의 wav와 학습 기록은 이후 삭제했고, 비교에 쓴 AUC 0.738만 이 문서에 남는다.

## 활성함수·뉴런 동특성 점검 (2026-09-23)

학습된 가중치로 test 세그먼트 512개를 흘려 측정했다.

- 발화율은 층별 0.21 / 0.46 / 0.47로 죽은 뉴런도 포화도 없다.
- 막전위 범위가 float 기준으로는 넓다. L1 −16.9~+26.7, L2 −58.3~+52.7, L3 −95.4~+152.4로
  임계값(약 0.7)의 200배를 넘는다. soft reset은 발화할 때만 임계값을 빼므로 음수 쪽에 바닥이 없고,
  억제된 뉴런의 막전위가 계속 쌓인다. L3 뉴런의 48%가 매 시점 −5 아래에 있다.
- **다만 하드웨어 정수 단위로 환산하면 문제가 아니다.** 선행 `export_weights.py`의
  `scale_W = max|W|/127`, `막전위_int ≈ V_float / scale_W`로 40대를 모두 환산했다.
  정수 단위에서는 임계값이 1이 아니라 110 근처이므로 비율이 그대로 옮겨지지 않는다.

  | 층 | 막전위 최대(정수, 40대 최악) | INT16(32,767) 대비 | vth_q 최대 |
  |---|---|---|---|
  | L1 | 3,446 | 10.5% | 110 |
  | L2 | 8,544 | 26.1% | 116 |
  | L3 | 16,707 | 51.0% | 118 |
  | L4 | 4,276 | 13.0% | 57 |

  INT16을 넘는 장비는 0/40이고, `vth_q`도 모두 127 이하라 선행과 같은 INT8 임계값을 쓸 수 있다.
  **막전위 폭 16 bit를 늘릴 이유가 없다.** 여유가 가장 적은 층은 L3(약 2.0배)이므로 P1.5에서
  포화 발생률을 함께 기록한다.
- 학습된 임계값이 하한 0.1 클램프에 걸린 뉴런이 L1 84/384, L2 42/256, L3 11/64개다.
- 출력층도 발화하며 soft reset으로 판독 막전위를 깎는다. 출력 발화율이 높은 장비에서 판독이
  압축된다(제외된 fan_id00: 발화율 0.537, 출력층 리셋을 없애면 로짓 폭 std 1.97 → 3.59,
  세그먼트 10.7%에서 판정이 바뀜). 그러나 40대 전부를 리셋 없이 재평가하면 평균 AUC
  0.9563 → 0.9543, 균형 F1 0.8231 → 0.8184로 오히려 내려간다(오른 장비 14, 내린 장비 24).
  리셋을 켠 채 학습한 모델을 끈 채 평가한 것이므로 확정하려면 재학습이 필요하지만,
  현재 근거로는 이득이 없다. 출력층 리셋을 없애도 L4 막전위 정수 최대는 4,276으로 동일하다.

## 결론: 뉴런 규칙을 바꾸지 않는다

- 막전위 비트폭: 16 bit 유지. 측정상 여유가 있고, 늘리면 BRAM 예산이 무너진다
  (막전위 512 × 706 × 3 B = 1,059 KiB로 전체 1,642.5 KiB의 64%를 먹어 부분 상주 비교 자체가
  좁아지고, 4 B면 1,412 KiB로 캐시 1벌 + 프리페치 1벌도 들어가지 않는다).
- 활성함수(발화·soft reset) 규칙: 선행 `plift_core.v`와 동일하게 유지. 출력층 리셋 제거는
  하드웨어 비용은 작지만 정확도 이득이 확인되지 않았다.
- 대신 P1.5 INT8 변환에서 층별 막전위 포화율과 float 대비 판정 일치율을 측정해
  L3 여유(약 2.0배)가 실제로 충분한지 확인한다.

## 주의

학습에 실제 이상 파일의 절반을 썼으므로 DCASE 공식 순위표(정상만으로 학습)와 직접 비교하지 않는다.
선행 SpikeSense-Edge와 같은 지도학습 조건이다.
