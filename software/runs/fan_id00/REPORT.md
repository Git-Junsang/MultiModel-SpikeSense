# fan id00 단일 모델 학습 — 배치·에포크 판단 자료

작성일: 2026-09-23 | 관련 task: [TASKS.md](../../../documents/design/TASKS.md) P1.4 | 코드: `software/src/{dcase_data,snn_model,train,analyze_runs}.py`

## 1. 조건

| 항목 | 값 |
|---|---|
| 모델 | `40→384→256→64→8` PLIF-T, 가중치 130,560개. 출력 8개 중 0=정상, 1=이상만 사용 |
| 대상 | fan id_00 (train 정상 911파일 = 8,200+910 세그먼트, test 정상 100 / 이상 407파일) |
| 입력 | 40 mel, 31프레임(992 ms) 세그먼트, 파일 단위 [0,1] 정규화 |
| 학습 | FocalLoss(γ=2), Adam lr 0.002, weight_decay 1e-5, grad clip 1.0, **고정 LR**, 200 에포크 |
| 마스킹 | 학습 배치 전체에 시간 4프레임·주파수 6mel을 각각 확률 0.5로 0 처리 |
| 균형 | 에포크마다 정상 전체 + 같은 수의 학습용 이상을 새로 생성 |
| 선택 | val loss 최소 시점의 체크포인트. test 라벨은 선택에 쓰지 않았다 |
| 환경 | RTX 3090 Ti 독점(LLM 언로드). 30분 주기 LLM 요청과 겹친 구간이 있으나 방법별 시간 차이는 1% 이내 |

학습용 이상 생성 두 방법과 진단용 한 가지:

- **other_id**: 같은 기종 다른 ID(fan id01~06)의 train 정상 소리를 이상으로 사용
- **mix**: 대상 ID 정상 세그먼트의 임의 시간·주파수 패치에 다른 ID 소리를 전력 합(이득 −6~+3 dB)으로 합성
- **real**(진단 전용, DCASE 조건 위반): 실제 이상 파일 절반(183개)을 학습, 나머지 204개 + test 정상 100개로 평가

## 2. 배치 크기 — 시간

200 에포크 기준 벽시계 시간이다. 값은 `other_id / mix` 순이다.

| 배치 | 에포크당(s) | 200에포크(min) | val loss 최소값 | val AUC |
|---|---|---|---|---|
| 32 | 13.7 / 14.3 | 45 / 48 | 0.017 / 0.099 | 0.998 / 0.914 |
| 64 | 6.99 / 6.92 | 24 / 23 | 0.016 / 0.096 | 0.998 / 0.918 |
| 128 | 3.41 / 3.43 | 11 / 12 | 0.016 / 0.094 | 0.998 / 0.919 |
| 256 | 1.70 / 1.68 | 5.8 / 5.7 | 0.014 / 0.093 | 0.998 / 0.918 |
| **512** | **0.86 / 0.93** | **3.0 / 3.2** | 0.020 / 0.093 | 0.997 / 0.920 |

- 시간은 배치에 거의 반비례한다. 세그먼트 수가 고정(16,400개)이고 GPU가 놀고 있어, 반복 횟수와 파이썬 루프(31 타임스텝 × 4층) 오버헤드가 시간을 지배한다. 즉 **큰 배치가 곧 이득**이다.
- 학습 품질(val loss·AUC)은 배치에 따라 의미 있게 달라지지 않았다. 32와 512의 차이는 0.006 이하다.
- **권장 배치는 512**다. bs32 대비 15배 빠르고 품질 손해가 없다. 40개 모델을 각각 학습해도 3분 × 40 = 약 2시간이다.
- 주의: lr 0.002를 모든 배치에 그대로 썼다. 배치를 키우면 보통 lr도 키우는데, 여기서는 큰 배치가 이미 동등하거나 더 나아서 조정하지 않았다.

## 3. 에포크 — 얼마나 필요한가

| 기준 | other_id | mix |
|---|---|---|
| val AUC가 최종값의 99%에 도달 | 8~11 에포크 | 17~53 에포크 |
| val loss가 최소값의 1.05배 이내 진입 | 79~193 | 35~117 |
| val loss 5에포크 이동평균의 포화(+2% 이내) | 91~194 | 76~193 |

- 구분 성능(val AUC)은 **30~50 에포크면 사실상 포화**한다. 그 뒤 200까지는 loss가 조금씩 오르내릴 뿐 AUC는 거의 변하지 않는다.
- val loss의 최소 도달 에포크는 실행마다 79~194로 크게 흔들린다. 고정 LR에서 후반 변동이 잡음 수준이라는 뜻이며, 이 값을 학습량 기준으로 삼기 어렵다.
- **권장: 배치 512에서 60 에포크 + 코사인 감쇠.** 40 에포크면 대부분 도달하고, 60이면 여유가 있다. 200 에포크는 낭비다.
- 곡선: `curves_other_id_const.png`, `curves_mix_const.png`, `curves_real_const.png`

## 4. 학습용 이상 생성 방법 — 실제 이상에는 통하지 않았다

test는 fan id00의 실제 정상·이상이며 파일 단위 AUC다.

| 방법 | val AUC(학습한 가짜 이상) | test AUC | test pAUC |
|---|---|---|---|
| other_id | 0.997~0.998 | **0.384~0.423** | 0.49~0.50 |
| mix | 0.914~0.920 | **0.396~0.481** | 0.49~0.51 |
| real(진단) | 0.665 | **0.689(선택 시점) / 0.755(200에포크)** | 0.695 / 0.677 |

참고: 학습 없는 기준선(파일 평균 mel의 Mahalanobis 거리) AUC 0.564, DCASE 2020 공식 AE 기준선은 이 장비에서 약 0.54다.

- 두 방법 모두 **가짜 이상은 거의 완벽하게 구분(0.92~0.998)하지만 실제 이상에서는 0.5 아래**다. other_id는 일관되게 0.4 근처로, 실제 이상을 오히려 정상 쪽으로 판정한다. "다른 ID처럼 들리면 이상"이라는 규칙이 이 장비의 실제 고장 방향과 어긋난다는 뜻이다.
- mix가 other_id보다 조금 낫지만(0.40~0.48 대 0.38~0.42) 여전히 쓸 수 없는 수준이다.
- **진단 결과가 중요하다.** 실제 이상을 학습에 넣으면 같은 모델·같은 특징으로 AUC 0.69~0.77이 나온다. 기준선 0.54~0.56을 크게 넘는다. 즉 **`40→384→256→64→8` 구조와 40 mel 입력은 이 장비의 실제 이상을 구분할 능력이 있다.** 막힌 곳은 구조가 아니라 학습용 이상의 정의다.
- 진단 실행에서는 val loss가 6에포크 이후 계속 나빠지는데도 test AUC는 200에포크까지 올랐다. val 이상 샘플이 20파일뿐이라 선택 기준으로 쓰기에 불안정하다.

## 5. 다음에 정할 것

1. **학습용 이상 생성 방법을 다시 정해야 한다.** 현재 두 방법 모두 실제 이상과 무관한 방향을 학습한다. 후보:
   - 정상만 학습하는 방식으로 전환(재구성 오차나 One-Class). 2진 분류 출력 구조와 맞출 방법을 함께 정한다.
   - 실제 이상 일부를 학습에 쓰는 지도학습으로 전환(DCASE 조건에서 벗어남을 명시).
   - 합성 이상을 물리적으로 더 그럴듯하게(대역 잡음, 충격음, 고조파 증가) 만든다.
2. **대상 장비 선택**: fan id00은 기준선 0.56의 최난도 장비다. 방법 비교는 slider id00(공식 기준선 약 0.96)이나 ToyCar id01(약 0.81)처럼 신호가 분명한 장비에서 함께 봐야 판단이 선다.
3. **입력 특징 점검**: 파일 단위 최댓값 정규화는 음량 변화 정보를 지운다. 고장이 레벨 변화로 나타나는 경우를 놓칠 수 있다.
