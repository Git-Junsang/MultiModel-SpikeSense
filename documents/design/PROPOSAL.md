# 다중 모델·다중 트랙 실시간 SNN 추론 가속기

**부제: 효율적 메모리 접근을 통한 FPGA 기반 다채널 이상음 탐지 가속기 카드**

작성일: 2026-09-04 (rev.2 — 실보드 AX7203B 사양 반영) | 상태: 제안 단계

---

## 0. 한 줄 요약

512개 이상의 산업 설비를 **설비별 개인화 SNN 모델**로 동시에 감시하되, 모델 전체가 온칩 메모리에 들어가지 않는 상황에서 **32ms 하드 데드라인**을 지키는 PCIe FPGA 가속기 카드를 설계한다. 핵심 기여는 **모델 재사용 최대화와 데드라인 준수가 충돌하는 지점에서 동작하는 하드웨어 스케줄러**다.

---

## 1. 배경과 문제 정의

### 1.1 출발점 — 현 시스템의 실측 한계

선행 프로젝트 SpikeSense-Edge는 Artix-7 100T에서 PLIF-T SNN(40→128→32→2, 9,280 INT8)을 시분할로 구동한다.

```
동작 클럭            50 MHz
타임스텝당 클럭      9,607 clk
→ 처리량            50e6 / 9,607 = 5,204 timestep/s

채널당 요구 레이트   hop 512 / 16kHz = 32 ms 주기 → 31.25 timestep/s
→ 최대 채널 수      5,204 / 31.25 = 166 채널
```

**166채널이 물리적 상한이다.** 이 연구의 동기는 인위적으로 만든 것이 아니라 기존 시스템이 실제로 못 하는 지점에서 출발한다.

### 1.2 채널 수만 늘려서는 메모리 연구가 되지 않는다

정직하게 짚어야 할 점이다. 현 구조는 가중치 1벌을 모든 트랙이 공유한다. 채널을 늘려도:

```
가중치 트래픽 = 9.28KB × (512 × 31.25) = 148 MB/s   ← DDR3 대역폭의 7%
막전위 총량   = 512 × 162 × 2B = 166 KB              ← BRAM에 여유롭게 수용
```

메모리 병목이 생기지 않는다. **병목은 "모델 수(M)"를 늘릴 때 비로소 발생한다.**

### 1.3 모델 수를 늘리는 응용적 필연성

같은 기종의 설비라도 개체마다 마모 상태, 설치 조건, 배경 소음이 다르다. 산업 예지보전에서 **설비별 개인화 모델**은 정확도를 높이는 실제 방향이다.

> **M(모델 수)을 늘리는 것은 정확도 향상 수단이고, 그것이 곧 메모리 병목을 만든다.**

이 연구의 축은 **정확도(M↑) ↔ 메모리 대역폭**의 트레이드오프다. 메모리 문제를 만들기 위해 워크로드를 조작한 것이 아니라, 응용을 개선하려는 시도가 자연스럽게 메모리 문제로 이어진다.

### 1.4 선행연구 대비 위치 (중요)

**"SNN 가중치를 오프칩 DRAM에 두고 온칩 캐시로 접근한다"는 구성 자체는 신규가 아니다.** Minitaur(TVLSI 2014)가 Spartan-6 + DDR2 128 MB로 이미 구현했고, 그 논문은 *"memory bandwidth, rather than compute time, fundamentally limits the performance"* 라고 명시한다.

따라서 본 제안의 기여는 **세 축에 한정해 주장한다**:

1. **캐시의 단위가 모델이다** — Minitaur의 지역성은 한 네트워크 안의 뉴런 지역성이지만, 여기서는 모델 정체성이다. 같은 모델을 쓰는 트랙을 묶는 것이 최적화 대상
2. **주기적 하드 데드라인** — 32 ms 위반이 곧 탐지 누락. Minitaur에도, 데이터센터 다중 DNN 문헌에도 없는 제약
3. **모델 fetch 비용이 들어간 스케줄링** — 재사용과 데드라인이 충돌하는 지점에서 동작하는 하드웨어 스케줄러

자세한 근거는 [RELATED_WORK.md](RELATED_WORK.md) §7 참조.

## 2. 타겟 하드웨어 — ALINX AX7203B

| 항목 | 사양 | 의미 |

| LUT / FF | 134,600 / 269,200 | |
| DSP48E1 | 740 | SNN은 대부분 미사용 |

| **DDR3** | **1 GB (8Gb), 32-bit, 800 MT/s** | 피크 **3.2 GB/s**, 실효 60~70% → **~2.0 GB/s** |
| **PCIe** | **Gen2 ×4** (~1.6 GB/s 실효) | 호스트 연동, 모델 갱신 경로 |
| Ethernet | **Gigabit ×2** (KSZ9031RNX) | 센서 수집 경로 |
| Flash | QSPI 16 MB | 부트 |
| 확장 | 40-pin ×2, HDMI, MicroSD | |

**이 보드는 PCIe 가속기 카드 폼팩터다.** 호스트 PC에 꽂히는 형태이므로 "가속기"라는 프레이밍이 문자 그대로 성립하고, 다음 두 경로가 동시에 열린다.

- **PCIe**: 호스트가 개인화 모델을 DDR3로 푸시(온라인 모델 갱신) + 판정 결과 회수
- **GigE ×2**: 센서 집선 장비에서 mel 프레임 직접 수집(호스트 없는 엣지 배치)

> DDR3 32-bit @ 800MT/s와 1GB 용량은 초안(16-bit / 512MB 가정)보다 유리하다. 대신 **최소 전송 단위가 32 B(BL8 × 4 B)로 커져** 부분 사용 시 낭비 배수도 커진다.

## 3. 목표 시스템 스펙 (도출 과정 포함)

### 3.1 모델 크기 S — 역산으로 결정

```
[조건 1] 온칩 캐시 용량 초과
  BRAM = 1,642.5 KB, 캐시 가용분 ≈ 0.7 MB
  M=20에서도 초과하려면  S > 717 KB / 20 = 35.9 KB

[조건 2] 대역폭을 의미 있게 소모
  DDR3 실효 ≈ 2.0 GB/s
  N=512 완전 개인화에서 한계 도달 →  S = 2.0 GB/s / (512 × 31.25) = 125 KB

→ S ≈ 128 KB 채택
```

네트워크 구조:

```
40 → 384 → 256 → 64 → 8

  40 × 384 =  15,360
 384 × 256 =  98,304
 256 ×  64 =  16,384
  64 ×   8 =     512
 ─────────────────────
 합계       = 130,560 INT8 = 127.5 KB
 뉴런 수    = 384 + 256 + 64 + 8 = 712
 출력       = 8 클래스 (정상 + 결함 7종)
```

출력 8클래스로 **다중 결함 진단**이 들어가며, 이것이 모델을 키운 응용 측 명분이 된다.

### 3.2 트랙 수 N — 병목 경계에 맞춤

초안의 N=300은 이 보드에서 **여유롭게 통과한다**(1.2 GB/s / 2.0 GB/s = 60%). 목표를 병목 경계 위로 올린다.

**N = 512** (주 목표), **N = 1,024** (스트레치)

응용 근거: 중형 공장 다개 라인 또는 대형 단일 라인. 설비 종류 8종 × 기종 변형 4 × 개체 16대 = 512대.

### 3.3 모델 수 M — 핵심 스윕 파라미터

| M | 의미 | 공유도 N/M |
|---|---|---|
| 20 | 기종별 1개 모델 | 25.6 |
| 128 | 기종 + 설치환경별 | 4 |
| **512** | **개체별 완전 개인화** | **1** |

### 3.4 연산 처리량

```
초당 트랙-타임스텝 = 512 × 31.25 = 16,000 회/s
회당 연산량        = 130,560 ops
필요 연산량        = 16,000 × 130,560 = 2.089 G-ops/s

연산 레인 32개 @ 100 MHz = 3.2 G-ops/s
이용률 = 2.089 / 3.2 = 65.3%               ← 여유 34.7%

트랙 1회 처리 = 130,560 / 32 = 4,080 cycles = 40.8 µs
라운드 1회    = 512 × 40.8 µs = 20.9 ms  < 32 ms 데드라인  (여유 11.1 ms)
```

-2 속도등급이므로 100 MHz는 보수적 목표다. 타이밍이 잡히면 150 MHz로 올려 여유를 더 확보할 수 있다.

**연산 자원 특성**: 레이어 1(40×384 = 15,360)만 실제 곱셈이고, 나머지 **88.2%는 스파이크 구동 조건부 덧셈**이라 곱셈기가 불필요하다. DSP 32개면 충분하며, 이는 740개의 **4.3%**에 불과하다. SNN을 쓰기 때문에 가능한 수치이며, **연산은 병목이 아님을 보드 자원으로 증명**한다.

### 3.5 온칩 메모리 예산

```
[막전위] 트랙 상태는 31 타임스텝(992 ms) 동안 유지되어야 함
  512 × 712 × 2 B = 729,088 B = 712 KB

[BRAM 배분]
  총량              1,642.5 KB
  − 막전위             712.0 KB   (43.3%)
  − MIG / 기타 로직    100.0 KB
  − 프리페치 버퍼      127.5 KB   (모델 1벌)
  ──────────────────────────────
  = 모델 캐시          703.0 KB
  → 수용 모델 수 = 703 / 127.5 = 5.5 → 5벌
```

**M=512 중 5벌만 상주 가능**하다. 히트율이 스케줄링 정책에 전적으로 좌우된다.

막전위가 BRAM의 43%를 점유한다는 점에 주목. **막전위와 모델 캐시의 BRAM 쟁탈전**이 이 설계의 구조적 긴장이다.

### 3.6 DRAM

```
모델 저장 총량 = 512 × 127.5 KB = 65.3 MB / 1 GB    ← 최대 8,200 모델 수용 가능
```

| M (N=512) | 라운드당 fetch | 대역폭 | 실효 2.0 GB/s 대비 |
|---|---|---|---|
| 20 | 20 | 79.7 MB/s | 4% |
| 128 | 128 | 510 MB/s | 26% |
| **512** | **512** | **2.04 GB/s** | **102% — 초과** |
| 512 (N=1,024) | 1,024 | **4.08 GB/s** | **204% — 명백 초과** |

### 3.7 두 개의 구조적 벽 (보드 사양에서 직접 도출)

**벽 1 — DRAM 대역폭 (재사용 없는 완전 개인화 기준)**
```
N_max = 실효대역폭 / (f_ts × S)
      = 2.0 GB/s / (31.25 × 127.5 KB)
      = 2.0e9 / 4.08e6 = 490 트랙
```

**벽 2 — 온칩 막전위 상주 한계**
```
막전위 가용 BRAM = 1,642.5 − 127.5(캐시 최소 1벌) − 127.5(프리페치) − 100(기타)
                 = 1,287.5 KB
N_max = 1,287.5 KB / (712 × 2 B) = 926 트랙
```

> **N = 512는 벽 1(490)을 막 넘어선 지점이다.** 재사용 스케줄링 없이는 데드라인을 지킬 수 없고, 벽 2(926)까지는 온칩 막전위로 버틸 수 있다. **512~926 구간이 이 연구의 주 무대**이며, 1,024를 넘으면 막전위도 오프칩으로 나가 문제의 성격이 바뀐다.

### 3.8 입력 인터페이스

```
N=512:   512 × 41 B × 31.25 = 656,000 B/s = 5.25 Mbps
N=1,024: 10.5 Mbps

GigE 1 Gbps 대비 0.5~1%,  PCIe Gen2 x4 대비 무시 가능
```

**입력 대역폭은 이 보드에서 완전히 해결된다.** 선행 프로젝트의 SPI 5 Mbps 제약은 사라진다.

## 4. 핵심 연구 문제

### 4.1 두 목표의 충돌

**목표 A — 모델 재사용 최대화.** 같은 모델을 쓰는 트랙을 연속 처리하면 모델 1회 fetch로 여러 트랙을 처리할 수 있다. M=20이면 이론상 트래픽 25배 감소.

**목표 B — 데드라인 준수.** 트랙마다 32 ms 하드 데드라인이 있다. 재사용을 위해 같은 모델 트랙을 몰아 처리하면 다른 모델을 기다리는 트랙이 데드라인을 놓치고, 그 채널의 이상 탐지가 지연·누락된다.

라운드로빈은 데드라인을 완벽히 지키지만 재사용률이 0%다. 재사용만 쫓으면 데드라인이 깨진다. **이 파레토 경계를 찾고 그 위에서 동작하는 하드웨어 스케줄러를 만드는 것**이 연구 내용이다.

### 4.2 예상 반론과 답

**"DDR3 2.0 GB/s면 그냥 되는 것 아닌가"**

1. **N=512, M=512에서 요구가 2.04 GB/s로 실효 한계를 넘는다.** 벽 1(490 트랙)을 의도적으로 넘긴 설계다.
2. **2.0 GB/s는 순차 전송 가정이다.** 모델 전환마다 DRAM 뱅크·row 전환이 발생하며, 순진한 구현은 실효 대역폭이 피크의 30~50%(1.0~1.6 GB/s)로 떨어진다.
3. **프리페치 마진이 얇다.** 모델 127.5 KB를 2.0 GB/s로 읽으면 63.75 µs. 트랙 1개 처리가 40.8 µs이므로 **fetch가 처리보다 1.56배 느리다.** 재사용 없이는 매 트랙마다 스톨이 발생한다.
4. **32-bit DDR3의 최소 burst가 32 B다.** 부분 접근 시 낭비 배수가 16-bit 구성보다 크다.

세 번째가 결정적이다. **재사용이 없으면 fetch가 연산을 앞지르지 못해 구조적으로 데드라인을 못 지킨다.**

### 4.3 부가 축 — 적응형 우선순위

이상 점수가 상승 중인 채널에 더 자주·더 정밀한 자원을 배분하고 안정적인 채널은 듬성듬성 처리하면, 같은 대역폭으로 더 나은 탐지 성능을 얻을 수 있다. 순수 아키텍처 연구에 없는, 응용과 결합된 각도다.

### 4.4 PCIe를 활용한 온라인 모델 갱신

호스트가 재학습된 개인화 모델을 PCIe로 DDR3에 푸시하는 동안 추론이 계속 돌아야 한다. **모델 갱신 트래픽과 추론 fetch 트래픽이 DDR3 대역폭을 두고 경쟁**하며, 갱신 중에도 데드라인이 지켜져야 한다. 실제 배치에서 반드시 필요한 기능이자 추가 연구 지점이다.

### 5.1 핵심 설계 원리

**① 트랙 배칭 (모델 스테이셔너리)**
모델 하나가 캐시에 올라와 있는 동안 그 모델을 쓰는 트랙들을 연속 처리한다. 스케줄러의 기본 동작이며, 데드라인이 배칭 길이를 제약한다.

**② 3단 파이프라인**
```
[프리페치: 모델 k+1 DRAM→캐시] ‖ [연산: 모델 k로 트랙 처리] ‖ [갱신: 막전위·판정]
```
fetch 63.75 µs > 트랙 처리 40.8 µs이므로, **한 모델당 최소 2트랙 이상 배칭해야 fetch를 숨길 수 있다.** 이 부등식이 스케줄러의 하한 제약이다.

**③ 뉴런 병렬 레인**
32 레인이 한 트랙의 출력 뉴런을 분담한다. 가중치 스트림을 레인별로 분배하고 스파이크 입력은 브로드캐스트한다. 레이어 2~4는 입력이 이진이므로 곱셈기 없이 게이트된 덧셈만 수행한다.

**④ 막전위 온칩 상주**
N ≤ 926에서만 성립한다(벽 2). 스트레치 목표 N=1,024는 이 벽을 넘으므로 막전위 압축 또는 오프칩 이동이 필요하다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| **0. 사전 검증** | MIG DDR3 루프백 대역폭 실측, 순차/랜덤 접근 패턴별 실효 대역폭 | **실측 대역폭 곡선** |
| **1. 모델 확장** | 40→384→256→64→8, 8클래스 학습, INT8 양자화 | 정확도, 가중치 바이너리 |
| **2. 워크로드 생성** | M 스윕용 모델 세트, 비동기 트랙 도착 트레이스, 골든 벡터 | 시뮬레이션 입력 |
| **3. 연산 코어** | 32 레인 어레이 + 막전위 뱅크, 단일 모델 검증 | RTL + tb PASS |
| **4. 메모리 경로** | MIG 연결, 모델 캐시, 프리페치 파이프라인 | RTL + 대역폭 실측 |
| **5. 스케줄러** | EDF / 재사용 그룹핑 / 하이브리드 정책 | RTL + 정책 비교 |
| **6. 호스트 연동** | PCIe DMA, 온라인 모델 갱신 | 드라이버 + 데모 |
| **7. 평가** | M·N 스윕, 파레토 곡선, baseline 대비 | 결과 데이터셋 |
| **8. 스트레치** | N=1,024, 막전위 오프칩/압축 | 확장 분석 |

**단계 0이 모든 것을 좌우한다.** DDR3 실효 대역폭이 1.4 GB/s 이하로 나오면 벽 1이 343 트랙으로 내려가고, N=512 목표와 모델 크기를 재조정해야 한다.

## 7. 평가 방법

### 7.1 지표

| 지표 | 정의 | 목표 |
|---|---|---|
| 마감 위반율 | 32 ms 내 완료 실패 트랙 비율 | **0% (하드 제약)** |
| 모델 캐시 히트율 | fetch 회피 비율 | 최대화 |
| DRAM 트래픽 | 초당 전송 바이트 | 최소화 |
| 실효 대역폭 이용률 | 실제 사용 / 이론 피크 | 참고 |
| 지원 채널 수 상한 | 위반 0%를 유지하는 최대 N | **최종 성능 지표** |
| 처리 지연 분포 | 프레임 도착 → 판정 완료 | p99 보고 |
| 전력 / 채널 | 보드 실측 ÷ N | 엣지 논거 |

### 7.2 비교 대상

1. **라운드로빈 + 캐시 없음** (naive baseline)
2. **EDF만** (데드라인만 고려, 재사용 무시)
3. **재사용 그룹핑만** (데드라인 무시)
4. **제안 하이브리드**
5. (선택) 호스트 CPU / GPU 소프트웨어 구현 — 전력·처리량 비교

### 7.3 결과의 형태

핵심 산출물은 **파레토 곡선**이다. 가로축 재사용률, 세로축 마감 위반율 평면에 각 정책을 배치하고, **"위반 0%를 유지하며 달성 가능한 최대 재사용률"**과 그로부터 도출되는 **지원 채널 수 상한**을 제시한다.

## 8. 예상 결과

전부 추정치이며 실측으로 검증해야 한다.

| 지표 (N=512, M=512) | 라운드로빈 | 제안 스케줄러 |
|---|---|---|
| 모델 캐시 히트율 | 0~5% | 50~75% |
| DRAM 트래픽 | 2.04 GB/s (초과) | 0.6~1.1 GB/s |
| 마감 위반율 | **다수 발생** | **0% 유지** |
| 지원 채널 수 | ~490 (벽 1) | **800~926 (벽 2까지)** |

**정성적 결과 예상**: M이 작을 때(≪N)는 재사용 그룹핑이 지배적으로 유리하고, M이 N에 접근하면 재사용 여지가 사라져 프리페치와 DRAM row 지역성이 성능을 결정한다. 두 구간의 전환점과, 하이브리드 정책이 양쪽에서 모두 견디는지가 결과의 핵심이 될 것이다.

## 9. 리스크와 검증 필요 가정

| 가정 | 위험 | 확인 방법 | 우선순위 |
|---|---|---|---|
| DDR3 실효 대역폭 60~70% (2.0 GB/s) | 낮으면 벽 1이 내려가 목표 재조정 필요 | **MIG 루프백 실측** | **최우선** |
| 32레인 @100 MHz 타이밍 클로징 | -2 등급이라 유리하나 미검증 | 조기 합성 시도 | 높음 |
| 40→384→256→64→8이 8클래스에서 유효 정확도 | 과적합 가능 | 학습 먼저 수행 | 높음 |
| M=512 개인화가 실제로 정확도를 올림 | 안 오르면 명분 붕괴 | 데이터로 검증 | 높음 |
| 8클래스 결함 라벨 데이터 확보 | MIMII/DCASE는 이진 중심 | 데이터셋 조사 | 중간 |
| **트랙 도착이 비동기** | 동기 도착이면 문제가 쉬워짐 | 시나리오 정의 명시 | **중간(중요)** |
| DDR3 page size / 뱅크 구성 | row 지역성 분석의 전제 | 탑재 칩 데이터시트 | 중간 |

**비동기 도착 주의**: 모든 채널이 동시에 프레임을 내놓고 32 ms 전체를 자유롭게 쓸 수 있다면, 모델 순으로 정렬하는 것만으로 재사용이 최대화되어 문제가 쉬워진다. **비동기 도착과 채널별 개별 데드라인**을 시나리오에 명시해야 연구 문제가 성립한다.

## 부록 A. 계산 요약

```
[보드] AX7203B / XC7A200T-2 / DDR3 1GB 32-bit 800MT/s / PCIe Gen2 x4 / GigE x2
BRAM   = 13,140 Kb = 1,642.5 KB
DDR3   피크 = 800 MT/s × 4 B = 3.2 GB/s,  실효 가정 2.0 GB/s

[워크로드]
f_ts   = 1 / 32ms = 31.25 회/s
N      = 512 (스트레치 1,024)
M      = 20 / 128 / 512
S      = 127.5 KB = 130,560 INT8,  뉴런 712,  8 클래스

[연산]
요구   = 512 × 31.25 × 130,560 = 2.089 G-ops/s
레인 32 @ 100MHz = 3.2 G-ops/s → 이용률 65.3%
트랙   = 130,560 / 32 = 4,080 clk = 40.8 µs
라운드 = 512 × 40.8 µs = 20.9 ms < 32 ms

[온칩]
막전위 = 512 × 712 × 2 = 712 KB (BRAM의 43.3%)
캐시   = 1,642.5 − 712 − 100 − 127.5 = 703 KB → 5 모델

[DRAM]
최악   = 512 × 31.25 × 127.5KB = 2.04 GB/s   (실효 2.0 초과)
최선   = 20 × 127.5KB / 32ms = 79.7 MB/s
저장   = 512 × 127.5KB = 65.3 MB / 1,024 MB

[두 개의 벽]
벽1 대역폭 = 2.0e9 / (31.25 × 130,560) = 490 트랙
벽2 막전위 = (1,642.5 − 127.5 − 127.5 − 100) KB / (712 × 2 B) = 926 트랙
→ 연구 주 무대 = 512 ~ 926 트랙 구간

[프리페치 부등식]
모델 fetch = 127.5KB / 2.0GB/s = 63.75 µs
트랙 처리  = 40.8 µs
→ fetch / 처리 = 1.56  →  모델당 최소 2트랙 배칭 필요

[입력]
512 × 41 B × 31.25 = 5.25 Mbps  (GigE의 0.5%)
```
