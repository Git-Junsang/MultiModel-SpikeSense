# 다중 모델·다중 트랙 실시간 SNN 추론 가속기

**부제: 가중치 재사용·부분 상주·마감 기반 스케줄링을 검증하는 FPGA 이상음 탐지 가속기**

작성일: 2026-09-23 (rev.4 — 출력 2클래스 확정, DCASE 2020 Task 2 데이터 확보 반영) | 상태: 설계·검증 계획

기준: [2026-09-17 중간보고](<../presentation/다중 모델, 다중 트랙 실시간 SNN 추론 가속기_중간보고_26.09.17.pptx>) 본문과 발표자 노트. 이 문서의 수치는 **목표·가정·계산값**이며 신규 가속기의 실측 결과가 아니다.

## 0. 한 줄 요약

**40개 개인화 SNN 모델을 공유하는 512트랙**을 FPGA에서 처리하고, 비동기 입력의 **생성부터 완료까지 32 ms 마감**을 지키는 것을 목표로 한다. 연구의 중심은 **Channel Window로 같은 모델의 요청을 묶는 스케줄러**와 **슬라이스 전송·가중치 부분 상주**를 함께 설계하고, 재사용·전송 대기·마감 준수의 관계를 검증하는 것이다.

전체 모델 캐시, 모든 모델 부분 상주, 혼합 방식의 세 가지 저장 정책을 비교한다. 부분 상주가 유리할 것이라는 예상은 검증할 가설이며, 캐시·프리페치 자체의 신규성이나 아직 측정하지 않은 성능 향상을 주장하지 않는다.

## 1. 배경과 문제 정의

### 1.1 선행 프로젝트의 처리량 기준

SpikeSense-Edge는 Artix-7 100T에서 `40→128→32→2` PLIF-T SNN을 사용하며, INT8 가중치 9,280 B를 온칩에 두고 연산기를 시분할한다.

```text
동작 클럭               50 MHz
타임스텝당 클럭         9,607 clk
타임스텝 처리량         50e6 / 9,607 ≈ 5,204.5 회/s
트랙별 입력 주기        512 samples / 16,000 samples/s = 32 ms
트랙별 요구 레이트      31.25 회/s
환산 가능한 트랙 수     5,204.5 / 31.25 ≈ 166.5 → 정수 기준 166
```

166트랙은 클럭과 타임스텝 비용으로 환산한 처리량 기준이다. **166개 트랙을 동시에 보드에서 실측했다는 뜻은 아니다.** 신규 프로젝트는 모델 수·크기와 트랙 수를 함께 늘리고, 온칩에 모든 가중치를 둘 수 없는 조건을 다룬다.

### 1.2 다중 모델과 다중 트랙

모델은 학습된 가중치 인스턴스이고, 트랙은 센서별 입력 스트림과 그 스트림의 막전위·판정 상태다. **N=512, M=40**이므로 여러 트랙이 같은 모델을 사용한다. 모든 설비가 서로 다른 모델을 쓰는 M=N 조건과 구분한다.

설비별 특성을 반영하는 개인화 모델을 준비하되, 40개 모델의 학습·공유 단위와 트랙↔모델 매핑은 데이터 확보 후 구체화한다. 개인화가 정확도를 높이는지는 별도 실험으로 검증한다.

40개 모델의 가중치는 총 5,207,040 B로 온칩 모델 저장 예산을 초과한다. 요청 순서에 따라 같은 가중치를 여러 번 전송할 수도, 한 번 가져와 여러 트랙에 재사용할 수도 있다. 재사용을 위해 같은 모델을 오래 처리하면 다른 모델의 요청이 마감을 놓칠 수 있다.

### 2.2 요청의 시각과 상태

트랙마다 32 ms 주기의 입력을 생성하되 생성 위상과 통신 지터가 다르다. 요청에는 최소한 트랙·모델 식별자, 시간 순서 정보, 입력 생성 시각 또는 그로부터 구한 마감, 40차원 입력이 필요하다. 필드 폭과 패킷 형식은 아직 정하지 않았다.

```text
t_gen      = 입력 생성 시각
t_arrival  = 가속기 요청 큐 도착 시각
deadline   = t_gen + 32 ms
남은 마감 여유 = deadline - 현재 시각
응답 시간  = t_complete - t_gen
```

도착 시점에 32 ms를 새로 부여하면 통신 지연을 누락하므로 기본 마감 정의와 맞지 않는다. 센서·Host·FPGA의 시각 동기화, 입력 생성 지점, 완료 판정 지점과 결과 회수 지연의 포함 범위는 실험 전에 명시한다. 도착부터 완료까지의 지연을 추가로 측정할 수 있지만 종단간 지표를 대체하지 않는다.

같은 모델을 공유해도 트랙별 막전위와 판정 상태는 공유하지 않는다. 한 트랙의 타임스텝 순서는 보존하며, 아직 생성되지 않은 미래 입력을 기다리는 시간축 배칭을 가정하지 않는다.

### 2.3 미확정 범위

출력은 **2클래스(정상/이상)**다. 데이터는 DCASE 2020 Task 2(기계 ID 41개)로 확정했고, 기계 ID 40개에 모델 1개씩을 학습한다. 결함 종류를 구분하는 다중 출력은 결함 라벨이 있는 공개 데이터가 기계 1~3대 규모뿐이라 기본 조건에서 제외했다. 이상 샘플을 학습에 쓰는 방식, 개인화 학습 방식, 모델별 트랙 분포, 세부 N 스윕, USB 마이크 개수, 데모 매핑과 실제 일정은 미정이다. 이전 제안의 M=20/128/512 스윕이나 N=1,024 스트레치를 최신 확정 목표로 사용하지 않는다.

## 3. 자원과 처리량 계산

용량은 B·KiB(`1 KiB = 1,024 B`), 전송률은 MB/s·GB/s(`10^6`, `10^9 B/s`)를 사용한다.

### 3.1 모델 크기

```text
40 × 384  =  15,360 B = 15 KiB
384 × 256 =  98,304 B = 96 KiB
256 × 64  =  16,384 B = 16 KiB
64 × 8    =     512 B = 0.5 KiB
합계      = 130,176 B = 127.125 KiB
뉴런      = 384 + 256 + 64 + 2 = 706
40개 모델 = 40 × 130,176 = 5,207,040 B = 5,085 KiB
```

이는 INT8 가중치만의 크기다. 추가 모델 파라미터·주소표·정렬 패딩·메타데이터가 필요하면 저장 예산에 별도로 포함한다.

### 3.2 BRAM 기준 예산과 세 가지 저장 방식

```text
막전위 = 512 × 706 × 2 B = 722,944 B = 706 KiB
BRAM 전체                              1,642.5 KiB
- 막전위                                 706.0 KiB
- MIG 및 기타 로직                       100.0 KiB
- 프리페치 버퍼 기준                      127.125 KiB
= 모델 가중치 저장 가용분                 709.375 KiB
```

막전위가 전체의 약 43.3%를 차지한다. 100 KiB의 기타 예산과 모델 1벌 크기의 프리페치 버퍼는 **기준 배분**이며, 슬라이스 크기와 더블버퍼 구조를 결정한 뒤 실제 IP 점유·BRAM 뱅킹·포트 폭·배치 낭비까지 다시 계산한다.

| 저장 정책           | 같은 709.375 KiB 예산에서의 예시                      | 검증할 효과와 비용                                        |
| ------------------- | ------------------------------------------------- | --------------------------------------------------------- |
| 전체 모델 캐시      | `floor(709.375 / 127.125) = 5`벌, 잔여 73.75 KiB       | 동일 모델 연속 실행의 재사용, 캐시 미스 시 전송 비용      |
| 모든 모델 부분 상주 | 균등 배분 시 모델당 17.734 KiB, 가중치의 약 13.95% | 넓은 모델 집합의 초기 대기 감소, 잔여 가중치 반복 공급    |
| 혼합                | 모델마다 일부 고정 상주 + 남은 공간의 가중치 캐시 | 초기 대기와 재전송 동시 완화 가능성, 분할 비율·교체 단위 |

구체적인 부분 상주 예시는 **첫 레이어 전체 상주**다.

```text
첫 레이어 40개 모델 = 40 × 15 KiB = 600 KiB
남는 저장 공간     = 709.375 - 600 = 109.375 KiB
```

109.375 KiB에 어떤 잔여 가중치를 어떤 단위로 저장할지는 미정이다. 이 구성은 단순한 전체 모델 5벌 캐시와 다르며, 부분 상주만으로 매 요청의 잔여 전송이 사라지는 것은 아니다. 트랙 상태 일부를 오프칩으로 보내 캐시를 넓히는 대안은 막전위 읽기·쓰기 비용과 함께 비교한다.

### 3.3 가중치 전송량

트랙별 입력 빈도는 `1 / 0.032 = 31.25 회/s`다.

| 비교 조건                           | 식                          | 가중치 전송률          | 2.0 GB/s 대비      |
| ----------------------------------- | --------------------------- | ---------------------- | ------------------ |
| 재사용 없이 요청마다 전체 모델 읽기 | `512 × 31.25 × 130,176` | **2.082816 GB/s** | **104.141%** |
| 주기당 모델별 1회 읽는 완전 그룹핑  | `40 × 31.25 × 130,176`  | **162.72 MB/s**   | **8.136%**    |

두 조건의 전송량 비는 `N/M = 12.8`이다. 완전 그룹핑은 각 모델의 해당 주기 요청을 모두 묶는 **이상적 비교 조건**이며, 비동기 도착과 개별 마감을 만족하는 실행이 자동으로 존재한다는 뜻은 아니다. 부분 상주·캐시 잔존·상태 이동·통신·제어 비용은 이 단순 비교에 포함되지 않았다. 따라서 162.72 MB/s를 모든 정책의 전역 최적 하한으로 사용하지 않는다.

전체 가중치를 매번 읽는 경우는 2.0 GB/s 예산을 넘지만, M=40 시스템 자체가 항상 대역폭을 초과하는 것은 아니다. **실제로 몇 번, 어느 부분을 읽는지가 스케줄링과 저장 정책의 평가 대상**이다.

### 3.4 연산과 전송 중첩

```text
요청 수/초       = 512 × 31.25 = 16,000
요구 연산량      = 16,000 × 130,176 = 2.082816 G-ops/s
32레인 @100 MHz = 3.2 G-ops/s
순수 연산 이용률 = 2.082816 / 3.2 = 65.088%
요청당 연산      = 130,176 / 32 = 4,068 cycles = 40.68 µs
512요청 연산     = 512 × 40.68 µs = 20.828 ms

전체 모델 전송   = 130,176 / 2.0e9 = 65.088 µs
첫 레이어 전송   = 15,360 / 2.0e9 = 7.68 µs
전송/연산 비     = 65.088 / 40.68 = 1.6
```

연산량은 가중치당 한 번의 연산을 세는 단순 밀집 처리 모델이다. 제어·뉴런 갱신·상태 접근·DMA 설정·버퍼 대기·스케줄러 비용이 없고 레인이 계속 일한다는 가정이므로, 20.828 ms를 실제 완료시간으로 보지 않는다.

전체 모델 하나의 전송을 다른 모델의 배치 연산과 겹치는 단순 구조에서는 **2트랙의 81.36 µs 연산 시간**이 65.088 µs 전송을 덮을 수 있다. 이는 버퍼·전송 경합이 없다는 조건부 계산이다. 캐시 적중·부분 상주·슬라이스 공급에서는 남은 전송량과 필요한 시점이 달라지므로 모델당 2트랙을 보편적인 하한으로 고정하지 않는다.

첫 레이어만 준비해 일찍 시작해도 전체 가중치의 약 75.3%가 있는 두 번째 레이어에서 기다릴 수 있다. 연산 시작 시각, 중간 대기, 완료 시각을 각각 측정한다.

첫 층 이후 88.2%의 가중치 연산은 이진 스파이크에 대한 조건부 누산으로 구성할 수 있다. 이는 연산 회로 설계의 근거이며, DSP 32개만 사용한다거나 연산이 병목이 아니라는 결과는 전체 구현의 자원·타이밍·성능 리포트로 확인해야 한다.

### 3.5 서로 다른 세 가지 경계

| 경계               | 계산                                                              | 해석                                                                     |
| ------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 재사용 없는 대역폭 | `2.0e9 / (31.25 × 130,176) ≈ 491.64`                          | 전체 모델을 매 요청 읽는 가정에서 정수 약 491트랙                        |
| 순수 연산          | `32,000 µs / 40.68 µs ≈ 786.63`                               | 32레인·100 MHz와 밀집 비용 모델의 정수 약 786트랙, 실제는 오버헤드 영향 |
| 막전위 용량        | `(1,642.5 − 127.125 − 127.125 − 100) × 1,024 / 1,424 ≈ 934.25` | 캐시 1벌·프리페치 1벌·기타 100 KiB 가정, 정수로는 934트랙              |

과거 문서의 약 926트랙은 8출력 기준(뉴런 712개) 계산값이며, 2출력에서는 934트랙이 된다. 물리적 BRAM 배치 효율을 적용하기 전에도 정수 용량 한계는 내림해야 한다. 또한 이때 캐시는 1벌이며 N=512의 5벌 캐시 조건과 다르다.

**메모리 용량 경계는 실시간 처리량 보장이 아니다.** 같은 32레인·100 MHz 비용 모델에서 800~934트랙의 마감 준수를 예상 성능으로 제시할 수 없다. N 스윕은 메모리와 연산·전송·통신 제약을 함께 고려해 정하고, 주 목표는 N=512로 유지한다.

### 3.6 입력과 식별자

Host 전처리가 만드는 40차원 입력의 정밀도와 패킷 형식을 확정한 뒤 입력 대역폭을 계산한다. N=512의 `track_id`는 최소 9 bit, M=40의 `model_id`는 최소 6 bit가 필요하며 시간 정보와 프레이밍도 포함해야 한다. 트랙↔모델 매핑 테이블로 일부 필드 전달을 생략할지는 프로토콜 설계 사항이다.

과거의 요청당 41 B 계산은 헤더가 확정되지 않은 상태의 예시였으므로 확정 입력 대역폭으로 사용하지 않는다. PCIe 링크 속도만으로 종단간 통신 지연이 해결되었다고 판단하지 않는다.

## 4. 핵심 설계 질문

### 4.1 Channel Window의 길이

동일 모델을 사용하는 준비된 요청들을 연속 실행하면 가중치 재사용을 늘릴 수 있다. 그러나 다른 모델의 요청이 기다리는 동안 마감 여유가 줄어든다. 스케줄러는 **어떤 모델부터 처리하고 같은 모델을 몇 개 요청까지 연속 처리할지**를 함께 결정한다.

중간보고의 Channel Window와 MW는 이 트랙 묶음을 뜻한다. 여러 미래 타임스텝이 이미 준비된 오프라인 시간창과 구분한다. M=N이고 모델을 공유하는 트랙이 없다면 이 방식의 트랙 간 재사용도 기대할 수 없다.

### 4.2 슬라이스 전송과 부분 상주

필요한 가중치를 DDR3에서 슬라이스 단위로 가져와 연산기에 공급하고, 현재 계산 중 다음 조각을 채운다. 가중치 부분 상주가 첫 계산을 앞당기는지, 잔여 공급이 완료시간을 지배하는지, Channel Window 내에서 같은 슬라이스를 재사용할 수 있는지를 SW 시뮬레이션으로 확인한다.

슬라이스·레이어·모델 중 어느 단위를 교체·재사용할지와 데이터플로우는 설계 변수다. 버퍼 유효성, DMA 완료, 연산 소비 순서, 역압 처리도 정해야 한다. 단순히 전송과 연산을 겹친 것만으로 전송 바이트가 감소했다고 주장하지 않는다.

### 4.3 점수 기반 요청 선택

점수의 입력 후보는 다음과 같다.

- 요청별 현재 마감 여유
- 캐시·부분 상주·진행 중 프리페치 상태
- 실제로 남은 가중치 바이트와 전송 시간
- 남은 연산·상태 처리 비용과 전송 중첩 가능성
- Channel Window 연장에 따라 다른 요청에 생기는 대기

**정확한 점수식, 가중치, 갱신 시점, 선점 단위는 미정**이다. Sparse-DySta의 정적·동적 비용 갱신 관점을 참고하되, 그 논문의 희소도 기반 비용 모델이나 성능 수치를 본 시스템의 결과로 옮기지 않는다.

남은 전송 시간을 완료시간 예측에 넣었다면 별도 패널티로 같은 시간을 다시 더하지 않는다. 전송·연산 중첩도 비용 모델에 반영하며, 모델의 미래 요청을 실제보다 더 알고 있다고 가정하지 않는다.

### 4.4 독립 상태와 마감 준수

모델 가중치 공유와 트랙 상태 공유는 별개다. 모델·트랙 전환 중 막전위와 판정 상태가 섞이지 않고, 각 트랙의 타임스텝 순서가 유지되어야 한다. 마감이 임박한 요청 때문에 배치를 끊었을 때의 비용과 이미 지연된 요청의 처리 방식도 명시한다.

32 ms 준수는 연구 목표다. FCFS·EDF·라운드로빈 중 어느 것도 해당 자원·도착 조건에서 검증 없이 마감을 보장한다고 쓰지 않는다.

## 6. 연구 진행 계획

중간보고의 5단계를 따른다. 날짜와 소요 기간은 정하지 않았다.

| 단계                    | 작업                                                             | 완료 확인에 필요한 산출물                                                  |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **1. 모델 준비**  | 데이터 수집, 706뉴런 모델 SW 구현, 개인 서버 학습, INT8 변환     | 데이터·라벨·모델 매핑 정의, 정확도, 모델·가중치 HEX, 참조 입출력        |
| **2. 설계 검증**  | 온칩·DDR3 대역폭 실측, MIG/IP 자원 확인, 아키텍처 SW 시뮬레이션 | 메모리 예산, 비용 모델, 저장 정책·스케줄러 비교, 슬라이스·배치 설계 근거 |

| **5. 평가·정리** | 부하·정책별 실험, 데모, 분석, 논문 작성                         | 원시 계측·재현 조건, 비교 결과, 시연, 논문                                |

전체 아키텍처 RTL을 고정하기 전에 대역폭과 자원 예산을 확인한다. 측정에 필요한 MIG 루프백 등의 최소 설계는 2단계에서 준비할 수 있다. 순차·슬라이스·모델 전환 패턴, 전송 길이와 버퍼 경합에 따라 실효 성능을 측정한다.

2.0 GB/s보다 낮은 대역폭이 나오면 실측값을 비용 모델에 넣어 저장 정책·배칭·중첩을 다시 평가한다. 재사용 없는 트래픽만으로 모델 크기를 자동 변경하지 않는다. 확정 목표를 바꿔야 한다면 계산 근거와 대안을 먼저 설명한다.

## 7. 평가 방법

### 7.1 핵심 지표

| 지표                         | 정의                                                        | 보고할 조건                                   |
| ---------------------------- | ----------------------------------------------------------- | --------------------------------------------- |
| **마감 위반율**        | 전체 대상 요청 중`t_complete > t_gen + 32 ms`인 요청 비율 | 입력 지연·미완료·폐기 요청의 집계 규칙 명시 |
| **가중치 DRAM 전송량** | 추론용 가중치 읽기의 총 바이트와 단위 시간당 전송량         | 초기 적재·워밍업과 정상 실행 구분            |
| **p99 응답 시간**      | 입력 생성부터 완료까지 지연의 99백분위                      | 시각 기준·측정 지점 명시                     |

마감 위반 0%가 목표다. p99가 32 ms 미만이어도 느린 나머지 요청이 마감을 넘을 수 있으므로, **최악 지연과 보수적인 부하 조건**을 함께 확인한다. 실험에서 위반이 없다는 결과와 모든 허용 입력에 대한 하드 마감 보장은 구분한다.

캐시 적중률, 연산 시작·전송 대기·완료 시간, 메모리 이용률, 자원·전력, 위반 없이 처리한 최대 N을 보조 지표로 기록한다. 부분 상주 정책은 전체 모델 적중률만으로 평가하기 어려우므로 가중치 바이트와 대기 시간을 우선 비교한다. ANTT를 추가한다면 단독 실행의 캐시 조건을 고정한다.

### 7.2 비교 정책과 공정성

기본 비교군은 **FCFS(도착 순서), EDF(마감 우선), 모델별 그룹핑, 제안 점수 기반 스케줄러**다. 라운드로빈·캐시 없음은 이전 설계와 연결되는 추가 비교군으로 사용할 수 있다.

전체 모델 캐시·부분 상주·혼합의 저장 정책과 요청 실행 순서 정책을 구분해 비교한다. 가능한 조합에서는 저장 정책을 고정하고 스케줄러를 바꾸며, 스케줄러를 고정하고 저장 정책을 바꿔 각각의 효과를 확인한다.

같은 비교에서는 트레이스·모델 매핑·메모리 예산·연산 자원·클럭·DDR 설정·캐시 초기 조건을 맞춘다. 구현 가능한 경우 동일 비트스트림에서 런타임 정책을 전환한다. 별도 비트스트림이 필요하면 자원·타이밍 차이를 명시한다.

### 7.3 워크로드

주 평가 조건은 **M=40, N=512**다. N과 부하는 실측한 처리 가능 범위에서 변화시키되 세부 지점을 사전에 기록한다. 모델별 요청 수는 균등·편중 조건을 구분하고, 트랙↔모델 매핑을 공개한다.

트랙별 위상과 통신 지터가 있는 비동기 도착을 포함한다. 모든 요청이 동시에 준비되는 조건은 정렬·그룹핑의 효과를 보는 비교용으로 사용할 수 있다. 이를 전체 실시간 시나리오의 대표로 삼지 않는다.

마이크 데모는 입력 수집부터 결과까지의 통합 동작을 보여준다. 소수 마이크의 성공을 512트랙 성능으로 확대 해석하지 않고, 별도 부하 생성·재생 실험으로 목표 규모를 검증한다.

### 7.4 결과 제시

재사용·가중치 전송량과 마감 위반율의 관계, p99·최악 지연, 저장 정책별 시작·대기·완료 시간을 제시한다. 파레토 곡선과 0% 위반이 관찰된 부하 범위는 결과의 표현 방식이며, 미리 정해 둔 성능 수치가 아니다.

## 8. 검증할 가설

| 가설                                                 | 지지 여부를 판단할 실험                                            |
| ---------------------------------------------------- | ------------------------------------------------------------------ |
| Channel Window가 재전송을 줄인다                     | 같은 저장 정책에서 FCFS·EDF·그룹핑·제안 정책의 전송 바이트 비교 |
| 부분 상주가 다양한 모델의 첫 계산을 앞당긴다         | 전체 캐시와 첫 연산 시작 시각 비교, 후속 층 대기와 완료시간도 측정 |
| 혼합 방식이 초기 대기와 재전송을 함께 줄일 수 있다   | 같은 BRAM 예산에서 상주 비율·교체 단위 변화                       |
| 점수 기반 정책이 재사용과 마감의 균형을 개선한다     | 비동기·지터·편중 조건에서 위반율·p99·전송량 비교               |
| 모델별 가중치를 공유해도 트랙 상태를 정확히 유지한다 | 트랙 인터리빙 결과와 독립 SW 실행의 상태·출력 비교                |

특정 적중률, 0.6~1.1 GB/s 전송량, 800~934트랙 처리 같은 과거 예상 수치는 현재 조건에서 검증되지 않았다. 수치 목표를 결과처럼 제시하는 대신 위 가설을 시험하고 실제 결과를 기록한다.
