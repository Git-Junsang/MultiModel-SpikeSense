# 온칩 메모리 구성안 — 32레인 공급과 BRAM 예산

작성일: 2026-10-09 | 개정: r1 | 관련 작업: [TASKS.md](TASKS.md) P3.4(구성안·BRAM 개수), P3.2(실측 반영). 최종 동결은 P3.9

이 문서는 32레인 연산기에 가중치·막전위를 공급하는 BRAM의 포트·폭·뱅크 구성을 정하고, 그 구성으로 BRAM 타일이 몇 개 드는지 계산한다. 수치는 세 종류로 구분한다.

- **실측**: P3.2 측정 설계(`hardware/board_test/p3_meas/`)의 구현 리포트, P3.1 보드 측정값
- **구현 확인**: 계획한 메모리 골격을 실제 크기로 합성·배치·배선한 결과(§8, `build_p3.tcl -fit`)
- **계산**: 아래 식으로 구한 값

계산 스크립트: [bram_plan.py](../../software/analysis_develop/bram_plan.py), 결과 [bram_plan.md](../../software/analysis_develop/p3_meas/bram_plan.md)

## 1. 결론 요약

1. **가중치 저장소 포트**: 읽기 256 bit(32레인 × INT8) 1 word/사이클, 쓰기 256 bit(MIG AXI 폭) 1 word/사이클. Simple Dual Port로 읽기 포트는 연산, 쓰기 포트는 DMA 채우기에 고정한다. 모델 엔트리 하나(4,096 × 256 bit) = **28.5 타일**(구현 확인).
2. **막전위 뱅크**: 층별 4개 뱅크, 16 bit 폭(뉴런 1개/사이클) 읽기-수정-쓰기. 512트랙 전체 **176.5 타일**(전체의 48.4 %, 구현 확인).
3. **타일 용량은 폭에 따라 다르다.** 256 bit처럼 넓은 word는 9 bit 열(4K × 9)로 쪼개 패리티 비트까지 데이터로 써서 타일당 36 Kibit을 모두 쓴다. 16 bit 막전위는 18 bit 폭에서 2 bit가 남아 타일당 32 Kibit만 쓴다.
4. **XDMA는 20.5 타일, MIG는 0 타일**(P3.2 실측). 제안서의 배분(막전위 + 모델 1벌 프리페치 + 기타)을 타일 단위로 다시 계산하면 가중치 가용분은 **709.375 KiB → 627.75 KiB**(139.5 타일)이고, β·임계값·요청 큐·트랙 메타까지 BRAM에 두면 **526.5 KiB**(117 타일)다.
5. **전체 모델 5벌은 구성에 따라 들어간다.** 제안서 배분(A)과 슬라이스 버퍼 + 부가 메모리 BRAM(B)은 4벌이다. 슬라이스 이중 버퍼를 두고 β·vth를 엔트리별로, 요청 큐·트랙 메타를 분산 RAM으로 옮기면(D) 5벌 + 잔여 15 타일이다. B(344 타일)와 D(352 타일) 골격을 MIG·XDMA와 함께 배치·배선해 계산과 같은 타일 수, 100 MHz 타이밍 통과를 확인했다(§8).

## 2. 요구 대역폭

| 대상 | 요구 | 근거 |
|---|---|---|
| 가중치 읽기 | 32 B/사이클 = 3.2 GB/s (100 MHz) | 32레인이 사이클마다 INT8 가중치 1개씩 |
| 가중치 채우기 | 최대 32 B/사이클 | MIG AXI 256 bit @ ui_clk 100 MHz. 실측 순차 읽기 3.015 GB/s = 0.94 word/사이클(P3.1, ROW_BANK_COLUMN) |
| 막전위 | 32뉴런 갱신 / 그룹 누산 시간 | 출력 고정 방식에서 가장 짧은 그룹은 층 1(입력 40개) → 40사이클에 32뉴런 = 0.8뉴런/사이클 |
| β·vth | 막전위와 같은 비율, 16 bit/뉴런 | β Q0.8 8 bit + vth 8 bit |
| 입력 | 요청당 40 B | 층 1 입력 7 bit × 40 (`snn_int8.py`) |

가중치는 계산기가 사이클마다 새 word를 읽어야 하므로 포트 폭 256 bit가 필수다. 막전위는 그룹이 끝날 때만 갱신하므로 좁은 포트로 충분하다.

## 3. 데이터플로우와 가중치 배치

32레인을 어떻게 나누느냐에 따라 가중치 word의 뜻이 달라진다. 두 후보를 비교했다.

| 항목 | 출력 고정(OS): 레인 = 출력 뉴런 32개 | 입력 병렬(IP): 레인 = 같은 뉴런의 입력 32개 |
|---|---|---|
| word 한 개의 내용 | 입력 j 하나에 대한 뉴런 32개의 가중치 | 뉴런 하나의 입력 32개 가중치 |
| 요청당 사이클(밀집) | L1 480 + L2 3,072 + L3 512 + L4 4 = **4,068** (L4는 아래 묶음 방식) | L1 768(40입력 → 2 word, 2번째 word는 8레인만 사용) + 3,072 + 512 + 4 = **4,356** |
| DDR3 배치 | P2.6 형식(행 우선 `[out, in]`)에서 **레인 교차 배치로 변경 필요** | P2.6 형식 그대로 |
| 막전위 갱신 빈도 | 그룹 끝마다 32뉴런(층 1은 40사이클마다) → 누산기 그림자 레지스터 32개와 직렬 갱신 | 뉴런마다 N_in/32 사이클(최소 2사이클)에 1뉴런 → 직렬 갱신 그대로 |
| 0 스파이크 건너뛰기 | 가능: 층 2~4에서 스파이크가 0인 입력 j의 word를 읽지 않으면 된다 | 어렵다: word 안의 32입력 중 일부만 0이어도 레인이 쓰인다 |

**0 스파이크 건너뛰기의 효과(계산)**: P2.7 골든 80개(40모델 × 정상·이상, 31 타임스텝)에서 스파이크 비율은 층 1 출력 22.3 %, 층 2 42.5 %, 층 3 45.7 %다. 출력 고정 방식에서 0 입력을 건너뛰면 요청당 사이클은 평균 1,385, p99 1,661, 최대 1,728로 밀집 4,068의 약 1/3이다. 이는 80개 벡터로 계산한 값이며, 이때도 **DDR3에서 가져올 가중치 바이트는 줄지 않는다**(어떤 입력이 0일지 미리 모르므로). 연산이 빨라질수록 전송 대기가 더 지배적이 된다.

**권고**: 출력 고정(OS)을 기준으로 두고, DDR3 가중치 형식을 레인 교차 배치(형식 버전 2)로 바꾸는 안을 P3.9에서 P4.1 설계와 함께 확정한다. 저장소 포트·폭·타일 수는 두 방식이 같으므로 이 문서의 BRAM 계산은 선택과 무관하다.

층 4(2뉴런 × 64입력 = 128 B)는 출력 고정 방식에서 word 하나에 뉴런이 2개뿐이다. 그대로 두면 64 word(2 KiB) 중 30레인이 논다. 대신 word 하나에 (입력 16개 × 뉴런 2개)를 담아 4 word로 저장하고, 레인 결과를 뉴런별 16입력 덧셈 트리로 합친다. 저장량은 128 B, 4사이클이다.

## 4. 가중치 저장소

### 4.1 캐시 엔트리

```text
층별 word = 그룹 수 × 입력 수
  L1 = 12 × 40  =   480      (384뉴런 / 32)
  L2 =  8 × 384 = 3,072
  L3 =  2 × 256 =   512
  L4 =  4               (§3 묶음)
  합계         = 4,068 word × 32 B = 130,176 B
엔트리 깊이   = 4,096 word (2^12, 28 word 여유)
```

RAMB36을 어떤 (깊이 × 폭)으로 쓰느냐에 따라 타일 수가 달라진다.

| 구성 | 엔트리 구성 | 타일 | 비고 |
|---|---|---:|---|
| 4K × 9 (패리티 포함) | 256 bit = 9 bit 열 28개 + 4 bit 열 1개(RAMB18 4K × 4) | **28.5** | **Vivado 추론 결과(§8)**. 출력 선택 없음 |
| 512 × 72 (패리티 포함) | 72 bit 열 4개(288 bit) × 깊이 8단 | 32 | 깊이 방향 8:1 선택 필요 |
| 512 × 64 / 1K × 32 (바이트 정렬) | 레인 바이트가 한 프리미티브 안에 | 32 | |

256 bit word를 9 bit 열로 나누면 레인 바이트가 두 프리미티브에 걸치지만 이는 배선일 뿐 논리 비용이 없다. 그래서 넓은 word에서는 패리티 비트(타일당 4 Kibit)를 데이터로 쓸 수 있고, 엔트리가 32 → 28.5 타일로 준다.

**포트**: Simple Dual Port. 읽기 포트는 연산, 쓰기 포트는 DMA 채우기에 고정한다. 연산이 엔트리 X를 읽는 동안 DMA가 엔트리 Y를 채우는 것은 서로 다른 타일이라 충돌이 없다. 같은 엔트리를 채우면서 읽는 슬라이스 스트리밍도 두 포트가 달라 가능하며, 이때는 슬라이스 단위 유효 비트로 순서를 지킨다.

**엔트리 선택**: 엔트리 E개의 256 bit 출력 중 하나를 고르는 E:1 다중화기(2단 파이프라인)가 연산기 앞에 들어간다. 엔트리가 칩 전체 BRAM 열에 흩어지므로 이 경로의 100 MHz 타이밍을 §8에서 확인했다.

### 4.2 슬라이스 버퍼

캐시에 없는 모델은 DDR3에서 슬라이스 단위로 가져와 바로 연산한다. 슬라이스를 **뉴런 그룹 하나(32뉴런 × 그 층의 입력 전체)**로 정하면, Channel Window 안의 트랙 k개가 같은 슬라이스를 차례로 쓰고 다음 그룹으로 넘어갈 수 있다(슬라이스를 k번 재사용).

| 층 | 그룹 크기 | 비고 |
|---|---:|---|
| L1 | 40 word = 1,280 B | |
| L2 | 384 word = 12,288 B | 가장 큼 |
| L3 | 256 word = 8,192 B | |
| L4 | 4 word = 128 B | |

가장 큰 그룹(12 KiB)을 담는 512 word(16 KiB) 버퍼 두 개로 이중 버퍼를 만든다: **7.5 타일**(1K × 36 열 7개 + RAMB18 1개, 구현 확인). 슬라이스 크기 자체는 P3.8 스윕에서 정하며, 그룹 여러 개를 한 슬라이스로 묶으면 버퍼가 커진다.

P3.1 실측으로 본 슬라이스 전송 비용(모델 전환, 한 번에 하나씩 요청, 512 B~130,176 B 11개 크기의 1차 회귀):

```text
MIG 주소 매핑 ROW_BANK_COLUMN (권고):  t(S) = 0.244 µs + S / 3.015 GB/s   (최대 잔차 0.023 µs)
MIG 주소 매핑 BANK_ROW_COLUMN (P1.6): t(S) = 0.215 µs + S / 2.900 GB/s   (최대 잔차 0.039 µs)
L2 그룹 12,288 B → 약 4.32 µs (ROW_BANK_COLUMN),  연산(그룹 384사이클) = 3.84 µs/트랙
```

트랙 1개만 처리하면 L2 그룹 전송(4.32 µs)이 연산(3.84 µs)보다 길고, 트랙 2개 이상을 묶으면 연산이 전송을 덮는다. 이 비교는 버퍼·전송 경합이 없을 때의 계산이며 P3.5 시뮬레이터에서 다시 본다.

## 5. 막전위 뱅크

```text
뱅크      깊이                     폭     타일
L1   512 × 384 = 196,608      16 bit   96     (구현: 32K × 1 열 16개 × 깊이 6단)
L2   512 × 256 = 131,072      16 bit   64
L3   512 ×  64 =  32,768      16 bit   16
L4   512 ×   2 =   1,024      16 bit    0.5   (RAMB18 1K × 16)
합계                                   176.5   데이터 722,944 B = 706 KiB, 물리 794.25 KiB
```

- **포트**: Simple Dual Port. 읽기 포트로 읽고, 2~3사이클 뒤 쓰기 포트로 같은 주소에 쓴다(읽기-수정-쓰기 파이프라인). 뉴런 1개/사이클이면 층 1 그룹(32뉴런)을 32사이클에 갱신하므로 다음 그룹 누산(40사이클) 안에 끝난다.
- **폭**: PLIF 갱신기를 P개 두면 폭은 16P bit다. 용량이 타일 수를 정하므로 폭을 32·64 bit로 늘려도 타일 수는 같다.
- **주소**: `track × N_l + n`. N_l = 384 = 256 + 128이라 시프트 두 개의 합이고, 나머지 층은 2의 거듭제곱이다.
- **패리티**: 16 bit 폭은 9의 배수가 아니라 타일당 4 Kibit을 못 쓴다. 9뉴런을 144 bit word 하나에 담으면(512 × 72 열 2개) 층 1이 86 타일로 줄어드는 계산이 나오지만, 32뉴런 그룹과 경계가 맞지 않아 갱신 경로가 복잡해진다. 기본안에서는 쓰지 않는다.
- 트랙별 판정 누적값(출력층 막전위의 시간 합, 2 × 21 bit)은 트랙 메타에 둔다.

막전위를 DDR3로 내보내는 대안(제안서 §3.2)의 비용은 요청당 읽기 1,412 B + 쓰기 1,412 B다. 512트랙 × 31.25회/s면 `16,000 × 2,824 B = 45.18 MB/s`로 P3.1 순차 대역폭(3.015 GB/s)의 1.5 %, 완전 그룹핑 가중치 전송량(162.72 MB/s)의 28 %다. 1,412 B 전송 하나는 위 회귀식으로 약 0.71 µs다. 이 대안이 캐시 확대(§7: 11 엔트리)를 정당화하는지는 P3.6에서 비교한다.

## 7. BRAM 타일 예산 (P3.2 실측 반영)

P3.2 측정 설계의 구현 리포트(`report_utilization -hierarchical`)에서 IP별 BRAM은 다음과 같다.

| 블록 | RAMB36 | RAMB18 | 타일 | 최종 시스템에 남는가 |
|---|---:|---:|---:|---|
| XDMA (Gen2 ×2, H2C 1·C2H 1, AXI-Lite 마스터) | 18 | 5 | **20.5** | 남음 |
| MIG (DDR3 32 bit, AXI 256 bit) | 0 | 0 | **0** | 남음 |
| SmartConnect 3×3 (64↔256 bit, 125↔100 MHz) | 0 | 0 | 0 | 형태는 바뀔 수 있음 |
| 시험용 AXI BRAM 64 KiB | 16 | 0 | 16 | 측정 전용 |
| JTAG-AXI | 2 | 1 | 2.5 | 측정 전용 |
| 트래픽 생성기 지연 기록 2,048 × 64 bit | 4 | 0 | 4 | 측정 전용 |

### 7.1 제안서 709.375 KiB의 갱신

제안서는 `1,642.5 − 706 − 100 − 127.125 = 709.375 KiB`로 계산했다(1,642.5 KiB = 365 타일 × 4.5 KiB, 패리티 포함 물리 용량). 같은 단위로, 같은 배분을 타일 단위로 다시 계산한다.

```text
전체                 365   타일 (물리 1,642.5 KiB)
− XDMA(실측)          20.5         (제안서 "기타 100 KiB" 대체, 물리 92.25 KiB)
− MIG(실측)            0
− 막전위             176.5         (데이터 706 KiB, 16/18 bit 사용이라 물리 794.25 KiB)
− 프리페치 1벌        28.5         (127.125 KiB → 4,096 word 엔트리, 물리 128.25 KiB)
= 가중치 가용분      139.5 타일 = 627.75 KiB          ← 709.375 KiB의 갱신값
− β·vth 40모델        14
− 요청 큐              7.5
− 트랙 메타            1
= 가중치 가용분      117   타일 = 526.5 KiB           ← 부가 메모리를 BRAM에 둘 때
```

차이(709.375 → 627.75 KiB, −81.6 KiB)의 대부분은 막전위가 16 bit라 패리티 비트를 못 쓰는 것(+88.25 KiB)이고, XDMA 실측(92.25 KiB)이 기타 예산(100 KiB)보다 작아 일부 상쇄된다.

### 7.2 저장 정책별 엔트리 수

엔트리 하나는 28.5 타일(D·E는 β·vth 0.5를 더해 29)이다. B는 5번째 엔트리까지 4.5 타일이 모자라고, C는 5벌이 들어가지만 잔여가 3 타일이라 다른 버퍼를 넣을 여유가 없다. **D가 5벌과 슬라이스 스트리밍을 함께 갖는 구성**이다.

## 8. 배치·배선 확인 (fit 실험)

`build_p3.tcl -fit N_ENT,SLICE_BUF,BV_ALL40,Q_BRAM`은 측정 설계(MIG + XDMA + SmartConnect + 레지스터 + 트래픽 생성기)에 [mem_fit.v](../../hardware/board_test/p3_meas/mem_fit.v)를 붙여 배치·배선까지 한다. 측정용 BRAM 64 KiB와 JTAG-AXI는 빼고 SmartConnect는 2×2로 줄였다. `mem_fit`은 기능 회로가 아니라, 위 구성의 메모리를 실제 크기로 만들고 두 포트를 모두 움직이는 골격이다: 트래픽 생성기가 읽은 DDR3 데이터를 엔트리·버퍼에 쓰고, 32레인이 엔트리를 읽어 누산하고, 막전위 뱅크 4개가 β·vth를 읽어 읽기-수정-쓰기를 한다.

| 구성 | BRAM 타일 (계산 / 구현) | LUT | 분산 RAM LUT | ui_clk WNS | 판정 |
|---|---|---:|---:|---:|---|
| B: `-fit 4,1,1,1` (엔트리 4, 슬라이스 버퍼, β·vth 40모델, 큐 BRAM) | 344 / **344 (94.2 %)** | 30,850 | 4,639 | +0.093 ns | 배치·배선·타이밍 통과 |
| D: `-fit 5,1,0,0` (엔트리 5, 슬라이스 버퍼, β·vth 엔트리별, 큐 분산 RAM) | 352 / **352 (96.4 %)** | 37,941 | 10,111 | +0.073 ns | 배치·배선·타이밍 통과 |

B의 메모리별 구현(Vivado 추론): 엔트리 = RAMB36(4K × 9) 28 + RAMB18(4K × 4) 1 = 28.5, 슬라이스 버퍼 7.5, 큐 7.5, β·vth 16(32K × 1 × 16), 메타 1, 막전위 96 + 64 + 16 + 0.5. 계산 344 = XDMA 20.5 + 엔트리 114 + 버퍼 7.5 + β·vth 16 + 큐 7.5 + 메타 1 + 막전위 176.5 + 측정용 지연 기록 1. ui_clk 최악 경로는 BRAM 배선이 아니라 골격의 PLIF 갱신식(곱셈→덧셈→포화→비교→뺄셈을 한 사이클, 13단)이다. 실제 설계는 이 식을 파이프라인으로 나누므로, BRAM을 94 % 쓴 배치 자체가 100 MHz의 걸림돌은 아니었다.

D의 계산 352 = XDMA 20.5 + 엔트리 142.5 + 버퍼 7.5 + β·vth 6 × 0.5(엔트리 5 + 버퍼 1) + 메타 1 + 막전위 176.5 + 측정용 1이고 구현도 352다(골격의 트랙 메타는 BRAM으로 두었다). 요청 큐 512 × 512 bit를 분산 RAM으로 옮기는 데 LUT 약 5,500개(골격 `u_fit`의 LUTRAM 5,472)가 들었다. 이 구성에서 측정용 지연 기록 1 타일을 빼면 BRAM 잔여는 14 타일이다. 두 구성 모두 Critical Warning 0, 구현에서 Vivado가 BRAM 선택을 바꾸지 않았다.
