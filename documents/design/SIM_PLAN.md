## 1. 시뮬레이션 환경 (P3.5)

Python 이벤트 기반 시뮬레이터 하나(`software/sim_develop/`). 모든 조합이 같은 시드에서 같은 요청열을 쓴다.

### 1.1 요청 도착 — 무작위 모델, 통신 지연 포함

| 항목 | 값 |
|---|---|
| 트랙 수 N | **512** (주 조건). 부하 점검용 **640** 한 점(연산 가동률 89.5 %). r1의 768은 요청당 연산만으로 `768 × 44.748 µs = 34.4 ms > 32 ms`라 모든 조합이 실패하므로 바꿨다. 밀집 연산의 상한은 715트랙 |
| 모델 수 M | 40 |
| 트랙↔모델 | 트랙마다 모델을 **균등 무작위**로 배정(시드마다 다름). 비교용 **편중** 조건: 모델 k의 트랙 비율 ∝ 1/(k+1)(Zipf, 상위 5모델 53 %, 1위 23 %). 편중 정도는 가정 |
| 입력 생성 시각 | 트랙별 위상 `U(0, 32 ms)`, 이후 32 ms마다: `t_gen = φ + k × 32 ms` |
| 도착 시각 | `t_arr = t_gen + d_host + d_in`. `d_in`은 P3.3 실측 H2C 64 B, 62.5 µs 간격(= 16 kHz, N=512의 요청률) 표본 20,000개(`p3_h2c_64_p62.5.txt`, p50 28.0 µs)에서 무작위 추출. `d_host`(전처리)는 미측정이라 0으로 두고 별도 표기 |
| 결과 회수 | `t_done = 연산 완료 + d_out`. `d_out`은 P3.3 실측 C2H 64 B 표본(`p3_c2h_64.txt`, p50 25.1 µs)에서 추출 |
| 마감 | `t_gen + 32 ms`. 응답 시간 `= t_done − t_gen` |
| 실행 길이 | 80주기(2.56 s): 앞 16주기 워밍업 제외, **측정 64주기(2.048 s, N=512에서 요청 32,768개)**. 정수 주기로 잡아 손계산과 바로 비교한다. 시드 5개 |

PCIe 지연 표본은 요청마다 독립으로 뽑는다. 호스트 DMA 큐의 경합(16 kHz에서 H2C 엔진 가동률 약 45 %)은 넣지 않았다.

### 1.2 비용 모델 (실측값 고정)

| 대상 | 식·값 | 출처 |
|---|---|---|
| DDR3 전송 | `0.244 µs + S / 3.015 GB/s`. DMA 엔진 1개(직렬). 앞 전송이 끝나기 전에 다음 요청을 내 두면 고정 비용이 숨는다: `도착 완료 = max(요청 시각 + 0.244 µs, 앞 전송 완료) + S / BW` | P3.1 회귀(ROW_BANK_COLUMN), pipelined 실측(512 B도 2.67 GB/s) |
| 전송량 | 모델 전체 **131,588 B**(가중치 130,176 + β·vth 1,412). L1·β·vth 상주 모델은 L2~L4 **114,816 B** | MODEL_MEMORY_LAYOUT |
| 연산 | 출력 고정 32레인, 1 word(256 bit)/사이클 × (1 + 제어 오버헤드 10 %) @ 100 MHz. 요청 1개 = 4,068 word → **44.748 µs**. 뉴런 그룹(32뉴런 × 입력 전체) 23개: L1 12개 × 40 word, L2 8개 × 384, L3 2개 × 256, L4 1개 × 4 | P3.4. 오버헤드 10 %는 가정 |
| 모델 전환 | 추가 비용 없음 | P3.1에서 관측 안 됨 |
| 온칩 예산 | 가중치·β·vth·적재 버퍼에 **168 타일** = 365 − XDMA 20.5 − 막전위 176.5. 엔트리 1벌 29(가중치 28.5 + β·vth 0.5) | P3.2 실측, ONCHIP_MEMORY |
| 동시성 | DMA 1개와 연산 배열 1개가 동시에 동작 | |

### 1.3 진행 방식 (부품과 무관한 공통 규칙)

1. **결정 시각 T**에 스케줄러가 다음 모델을 고른다. 준비된 요청이 없으면 다음 도착까지 기다린다(일부러 기다리지는 않는다).
2. 저장 정책이 그 모델에 필요한 그룹별 적재 바이트를 정하고 캐시 상태를 갱신한다.
3. 연산 방식이 DMA·연산 시각을 계산한다. **첫 그룹 연산이 시작되는 시각 s에 묶음 구성원을 확정**한다. T 뒤 s까지 도착한 같은 모델 요청도 합류한다.
4. 다음 결정 시각은 s다. 즉 **한 묶음 앞을 미리 정해**, 묶음 i가 연산하는 동안 묶음 i+1의 가중치를 가져온다. 미래 요청은 알지 못한다.
5. 요청별 완료 시각: "한 번에"는 트랙을 하나씩 모델 전체로 연산하므로 j번째 트랙이 `s + j × 44.748 µs`에 끝난다. "한 줄씩"은 그룹마다 트랙을 돌므로 마지막 그룹(L4) 시작 + j × L4 연산에 끝난다.

### 1.4 지표

모든 실행에서 같은 네 가지를 낸다: **마감 위반율**, **가중치 DRAM 전송률(MB/s)**, **응답 시간 p99**, **최악 응답 시간**. 보조로 평균 묶음 길이, 캐시 적중률, DMA·연산 가동률, BRAM 타일을 낸다. 시드 5개의 응답을 합쳐 p99·최악을 구하고, 전송률·가동률은 시드 평균이다.

### 1.6 코드 구조 — 24조합을 만드는 방법

조합마다 코드를 따로 만들지 않는다. 공통 시뮬레이터 1개와 같은 모양의 부품 9개를 만들고 반복문으로 조립한다.

| 파일 | 내용 |
|---|---|
| `sim_core.py` | 고정 조건·비용 모델, 요청열 생성(`make_workload`), 준비된 요청 집합(`Ready`), 진행 규칙(`simulate`), 지표 |
| `policies.py` | 부품 9개. 저장 정책 `plan(m)`·`peek(m)`·`tiles()` / 스케줄러 `pick()`·`members()` / 연산 방식 `run()`·`extra_tiles()` |
| `run_sim.py` | `--selftest`(§1.5), `itertools.product(저장 3, 스케줄러 4, 연산 2) × 시드 5` 병렬 실행 → `sim_result/sim_n{N}.jsonl`, `sim_result/summary_n{N}.md` |
| `target_exp.py` | P3.8 마무리(MODEL_SIZE_PLAN §5): XL · 256레인 · 막전위 DDR3에서 시나리오별 최대 트랙, 목표 여유, 목표 트랙의 설계 32개 지표. 사이클 회계는 `simulate(detail=True)`, B·C를 예산에 맞춘 `PartialAll`·`PinnedHybrid`, 슬라이스 칸 보정은 `configure(rev=4)` |

120회 실행은 약 10초 걸린다. 후보를 늘리려면 부품 클래스 하나를 만들어 목록에 넣는다.

## 2. 결정 1 — 저장 정책 (P3.6)

**질문**: 같은 168 타일로 무엇을 온칩에 둘 것인가.

| 후보 | 내용 | 미스 시 동작 | BRAM 타일 |
|---|---|---|---:|
| A. 전체 캐시 | 모델 엔트리 5벌(가중치 + β·vth), LRU 교체 | 모델 전체(131,588 B)를 교체될 엔트리에 적재 | 145 |
| B. 부분 상주 | 40모델의 L1 가중치(15,360 B씩)와 β·vth 상주 | 매 묶음 L2~L4(114,816 B)를 가져오고 보관하지 않음 | 156.5 + 적재 버퍼 |
| C. 혼합 | 엔트리 3벌(LRU) + 트랙이 많은 **21모델**의 L1·β·vth 상주 | 엔트리 미스면 L1 상주 모델은 L2~L4만, 아니면 전체를 엔트리에 적재 | 167 |

C의 상주 모델 수는 r1의 20개에서 "엔트리 3벌을 뺀 예산(81 타일)에 들어가는 최대값" 21개로 바꿨다(`87 + 72.5 + 7.5 = 167`).

## 3. 결정 2 — 스케줄러 (P3.7)

**질문**: 다음에 어느 모델의 요청을, 몇 개 묶어 처리할 것인가.

| 후보 | 모델 선택 | 묶음 |
|---|---|---|
| FCFS | 도착이 가장 이른 요청의 모델 | 그 요청과 도착 순서로 바로 이어지는 같은 모델 요청 |
| EDF | 마감이 가장 이른 요청의 모델 | 그 요청과 마감 순서로 바로 이어지는 같은 모델 요청 |
| 모델별 그룹핑 | 가장 오래 기다린 요청의 모델 | 그 모델의 준비된 요청 전부 |
| 점수 기반 | 마감 여유 < `T_urgent`인 요청이 있으면 그 요청의 모델. 아니면 `n ÷ (남은 전송 시간 + n × 44.748 µs)` 최대 모델, `n = min(준비된 요청 수, K)` | 그 모델의 요청을 마감 순서로 최대 K개 |

점수 기반의 파라미터는 `T_urgent = 4 ms`, `K = 16`으로 고정한다. 남은 전송 시간은 저장 정책의 현재 상태(`peek`)로 계산한다.

## 4. 결정 3 — 연산 방식 (P3.8)

**질문**: 가중치가 DDR3에서 들어올 때 언제 연산을 시작할 것인가.

| 후보 | 내용 | 적재 위치·추가 타일 |
|---|---|---|
| 한 번에 | 필요한 가중치가 모두 들어온 뒤 묶음 연산 시작 | A·C: 교체될 엔트리(0). B: L2~L4 적재 버퍼 1벌(28.5) → **합계 185, 예산 초과** |
| 한 줄씩 | 뉴런 그룹이 도착하는 대로 묶음 안 트랙들이 차례로 연산 | A·C: 교체될 엔트리에 바로 적재하고 그룹별 도착만 확인(0). B: 슬라이스 이중 버퍼(7.5), 2칸을 묶음 경계와 상관없이 번갈아 씀 → 합계 164 |

r1은 "한 줄씩"을 항상 슬라이스 이중 버퍼로 보았다. 엔트리가 있는 A·C는 교체될 엔트리에 바로 적재하면 되므로 버퍼가 필요 없고, 다음 묶음의 가중치를 2그룹 이상 앞당겨 가져올 수 있다.

## 5. 실험과 판정

- 24조합 × 시드 5개를 N=512에서 실행하고, 부하 점검으로 N=640에서 한 번 더 실행한다.
- **제외**: BRAM 168 타일 초과, 측정 구간 마감 위반 1건 이상.
- **최종 조합**: 남은 조합 중 ① 가중치 전송률 최소(차이 5 % 이내는 같다고 봄) ② 최악 응답 최소 ③ 버퍼가 작은 쪽.
- **결정별 근거**: 최종 조합에서 한 결정만 바꾼 비교(저장 3개, 스케줄러 4개, 연산 2개)를 표로 남긴다.

## 6. 첫 실행 결과 (2026-10-09, 시뮬레이션)

전체 표: [summary_n512.md](../../software/sim_result/summary_n512.md), [summary_n640.md](../../software/sim_result/summary_n640.md)

| 항목 | N=512 | N=640 |
|---|---|---|
| 예산 안 20조합의 마감 위반 | 모두 0 | 모두 0 |
| 예산 안 20조합의 p99 / 최악 응답 | 0.36~0.56 ms / 0.44~0.97 ms | 0.71~1.58 ms / 0.82~3.10 ms |
| 예산 안 20조합의 전송률 | 1,771~1,862 MB/s (차이 5.2 %) | 2,093~2,292 MB/s (차이 9.5 %) |
| 평균 묶음 길이 | 1.01~1.04 | 1.02~1.10 |
| 가동률 DMA · 연산 | 0.59~0.62 · 0.72 | 0.69~0.76 · 0.89 |
| B × 한 번에 (185 타일, 예산 초과) | FCFS·EDF 과부하로 위반 100 %. 그룹핑·점수는 위반 0, 묶음 2.2, 851 MB/s | FCFS·EDF 위반 100 %. 그룹핑·점수는 위반 0, 묶음 7.3, 315 MB/s, 최악 14.9·29.0 ms |

해석:

- **N=512·640에서는 DDR3가 병목이 아니다.** 모델 전체 전송(43.89 µs)이 요청당 연산(44.748 µs)보다 짧아, 묶지 않고 매 요청마다 가중치를 가져와도 다음 묶음의 적재가 현재 연산 뒤에 숨는다. 병목은 연산(가동률 0.72, 0.89)이다.
- 일부러 기다리지 않는 스케줄러는 큐가 짧아(응답 p99 < 2 ms) **같은 모델 요청이 거의 쌓이지 않는다.** 그래서 네 스케줄러의 묶음 길이·전송률이 거의 같고, Channel Window의 재사용 효과가 나타나지 않는다.
- 묶음이 길어진 경우는 B × 한 번에뿐이다. 적재 버퍼가 1벌이라 전송과 연산이 직렬화되고, 그 결과 큐가 쌓였다. 큐가 쌓이면 그룹핑·점수가 전송량을 최대 1/7(N=640, B × 한 줄씩 대비)까지 줄이지만, 이는 예산을 넘는 구성에서 생긴 결과다.
- 따라서 §5 판정 규칙으로는 조합이 거의 구별되지 않는다(전송률 차이 5 % 남짓, 응답 차이 1 ms 미만). **판정은 보류**하고 비교 조건을 정한 뒤 다시 실행한다(후보: 마감 여유 안에서 일부러 기다리는 대기 허용 시간 `W`를 스케줄러 파라미터로 추가, 또는 0 스파이크 건너뛰기로 요청당 연산을 줄여 DDR3가 병목이 되는 조건 추가).

### 6.1 DDR3 대역폭 민감도 (가상 조건, N=512)

`run_sim.py --bw <GB/s>`로 DDR3 대역폭만 낮춰 같은 24조합을 실행했다. 실측은 3.015 GB/s이고, 2.0 GB/s는 제안서 가정, 1.5 GB/s는 DDR2급이다. 묶지 않을 때 필요한 대역폭은 `16,000 요청/s × 131,588 B = 2.1 GB/s`다. 아래는 예산 안 20조합만 센 값이다. 전체 표: [bw2](../../software/sim_result/summary_n512_bw2.md), [bw1.5](../../software/sim_result/summary_n512_bw1.5.md).

| 대역폭 | 위반 0 조합 | 실패 조합 | 통과 조합의 최악 응답 | 통과 조합의 평균 묶음 |
|---|---|---|---|---|
| 3.015 GB/s (실측) | 20/20 | 없음 | 0.44~0.97 ms | 1.01~1.04 |
| 2.0 GB/s | 18/20 | A × FCFS·EDF × 한 번에 (위반 4.3 %) | 0.76~3.34 ms | 1.02~1.15 |
| 1.5 GB/s | 10/20 | FCFS·EDF 전부 (위반 100 %, 과부하) | 1.82~10.0 ms | 1.22~1.49 |

- 대역폭이 묶지 않을 때의 요구량(2.1 GB/s)보다 낮아지면 **스케줄러가 합격·불합격을 가른다.** FCFS·EDF는 도착·마감 순서로 바로 이어지는 같은 모델만 묶으므로 묶음이 1.03에 머물러 과부하가 된다. 그룹핑·점수는 큐가 쌓이는 만큼 묶음이 길어져(1.2~1.5) DMA가 대역폭 한계에서 버틴다.
- 같은 조건에서도 저장 정책·연산 방식의 차이는 작다(통과 조합끼리 전송률 차이 약 11 %, 최악 응답 차이 수 ms).
- 이 결과는 가상 조건이다. 실측 대역폭에서는 §6 결론(512트랙은 묶지 않아도 마감을 지킴)이 유지된다.

### 6.2 대역폭 단계 실행 — 조합별 최저 통과 대역폭 (가상 조건, N=512)

`run_sim.py --sweep --dist {uniform,zipf}`: 3.015 GB/s부터 0.1 GB/s까지 11단계, 24조합 × 시드 5. "최저 통과"는 그 대역폭과 그 위 모든 단계에서 위반 0인 가장 낮은 대역폭이다. 전체 표: [균등](../../software/sim_result/sweep_n512_uniform.md), [편중](../../software/sim_result/sweep_n512_zipf.md).

| 조합 묶음 (예산 안) | 균등 | 편중 |
|---|---|---|
| FCFS·EDF (저장·연산 무관) | 2.0 (A × 한 번에는 3.015) | 2.0 |
| 그룹핑 (A·B·C, 한 줄씩·한 번에) | 0.2 | 0.25 |
| 점수 (A·B·C, 한 줄씩·한 번에) | 0.2 (A × 한 번에 0.25) | 0.25 (A × 한 번에 0.35, C × 한 줄씩 0.2) |
| 참고: B × 한 번에 (185 타일, 예산 초과) | 0.75 | 0.75 |

해석:

- **스케줄러가 최저 대역폭을 약 10배 가른다.** 모으는 스케줄러(그룹핑·점수)는 같은 모델 요청이 쌓이는 만큼 묶음이 길어져(0.25 GB/s에서 그룹핑 묶음 8~12) 실측의 1/12~1/15까지 버틴다. 한계는 주기마다 40모델을 한 번씩 가져오는 양(`40 × 131,588 B / 32 ms = 0.164 GB/s`, B는 0.144 GB/s)에 가깝다.
- **저장 정책은 최저 대역폭을 거의 바꾸지 않는다**(0.2~0.35 GB/s 안). 이유 두 가지:
  - 그룹핑은 "가장 오래 기다린 요청의 모델", 즉 가장 오래 쓰지 않은 모델을 고르므로 LRU 캐시에서 이미 빠진 모델을 고른다. A·C의 캐시 적중률이 0이다.
  - 점수 기반은 캐시에 있는 모델을 먼저 골라 적중률 10~60 %로 전송을 줄이지만, 캐시에 없는 모델의 요청을 마감 여유 4 ms(`T_urgent`)까지 미룬다. 대역폭이 낮으면 응답 p99가 28~30 ms로 마감에 붙어, 버티는 한계는 그룹핑과 비슷하다.
- 온칩 용량이 전체 가중치의 약 1/8(0.65 MB / 5.3 MB)이라, 무엇을 온칩에 두든 아낄 수 있는 전송이 작다. 편중 조건에서는 인기 모델이 계속 요청되지만, 그룹핑은 그 모델도 다른 모델을 다 돈 뒤에 다시 고르므로 캐시 이점을 살리지 못한다.
- **연산 방식은 최저 대역폭을 거의 바꾸지 않는다.** 다만 B는 한 번에와 함께 쓰면 L2~L4 버퍼 때문에 예산을 넘고 0.75 GB/s에서 무너지므로, B는 한 줄씩과만 쓸 수 있다.

### 6.3 확장 환경 — 64레인 · 1,024트랙 (가상 설계, 시뮬레이션)

DDR3를 실측 대역폭에서 병목으로 만들기 위한 가상 환경이다. 확정 목표(512트랙)를 바꾸는 안이므로 결과는 비교용이다. `run_sim.py --lanes 64 --tracks 1024 [--sweep]`, 그림 `plot_sim.py`.

| 항목 | 기준 (32레인 · 512트랙) | 확장 (64레인 · 1,024트랙) |
|---|---|---|
| word · 뉴런 그룹 | 256 bit · 32뉴런, 23그룹 | 512 bit · 64뉴런, 12그룹 |
| 요청당 연산 | 4,068사이클 → 44.748 µs | 2,034사이클 → 22.374 µs |
| 연산 가동률 | 0.72 | 0.72 |
| 묶지 않을 때 DDR3 요구량 | 2.1 GB/s (실측의 70 %) | 4.2 GB/s + 막전위 0.09 GB/s (**실측의 143 %**) |
| 막전위 | BRAM 176.5 타일 | 1,024트랙은 353 타일이라 BRAM(344.5)에 들어가지 않음 → **DDR3**, 요청마다 읽기·쓰기 2,824 B. 한 줄씩은 묶음 막전위 버퍼(64트랙, 22.5 타일)가 필요해 묶음을 64로 제한 |
| 가중치 예산 | 168 타일 | 322 타일 (365 − XDMA 20.5 − 막전위 버퍼 22.5) |
| A / B / C | 5벌 / L1 40모델 / 3벌 + L1 21모델 | 11벌 / L1 40모델 / 6벌 + L1 38모델 |

엔트리 1벌은 두 환경 모두 29 타일이다(2,048 × 512 bit = 28.5 + β·vth 0.5). 막전위 읽기 지연은 숨긴다고 가정했고, 이동량만 DMA 시간에 넣었다(묶음의 가중치 전송 뒤).

결과(전체 표: [summary_n1024_l64.md](../../software/sim_result/summary_n1024_l64.md), [sweep 균등](../../software/sim_result/sweep_n1024_l64_uniform.md), [sweep 편중](../../software/sim_result/sweep_n1024_l64_zipf.md), 그림 [1](../../software/sim_result/figures/fig1_scheduler_miss.png) [2](../../software/sim_result/figures/fig2_min_bw.png) [3](../../software/sim_result/figures/fig3_storage_p99.png) [4](../../software/sim_result/figures/fig4_bytes_per_request.png)):

- **실측 대역폭에서 FCFS·EDF가 무너진다.** 균등 분포에서 모든 저장 정책·연산 방식에서 위반 100 %다. 그룹핑·점수는 위반 0, p99 0.8~1.4 ms(B × 한 번에만 4.9~8.0 ms).
- **최저 통과 대역폭**: 그룹핑·점수 0.25~0.5 GB/s, B × 한 번에 0.75~1.0 GB/s. 기준 환경(0.2~0.35)보다 저장·연산 조합 간 폭이 2배로 벌어졌다.
- **요청당 가중치 전송(실측 대역폭, 그림 4)**: 균등 분포에서 A·C 69~88 KB, B × 한 줄씩 77~79 KB. 편중 분포에서는 A 49~57 KB, C 59~68 KB, B × 한 줄씩 72~76 KB로 **같은 한 줄씩끼리 비교하면 전체 캐시가 부분 상주보다 20~30 % 적다.** B × 한 번에는 26 KB로 가장 적지만, 이는 전송·연산이 직렬화되어 큐가 쌓이고 묶음이 4.3으로 길어진 결과이며 응답이 길고 최저 통과 대역폭이 가장 높다.
- 저장 정책별 p99 응답 차이는 여전히 작다(그림 3).

## 7. 사양 동결 (P3.9)

세 결정 결과와 P3.4 권고(MIG ROW_BANK_COLUMN, 출력 고정 레인 배치, DDR3 형식 v2)를 묶어 RTL 사양을 정한다. 모듈 인터페이스, 레지스터맵(정책 선택·계측 카운터), 요청 패킷(`track_id` 9 bit, `model_id` 6 bit, `t_gen`, 입력 40 B)만 최소로 정한다.

## 8. 하지 않는 것 (필요하면 나중에 추가)

막전위 DDR3 이동, 0 스파이크 건너뛰기 연산, PCIe 묶음 전송 크기 분석, 호스트 DMA 경합, 지터 분포 스윕, 버퍼 수·상주 비율 스윕.
