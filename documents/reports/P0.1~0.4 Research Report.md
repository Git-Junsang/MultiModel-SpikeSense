# P0.1~P0.4 연구 보고서 — 개발 환경과 보드 연결 기반 구축

작성일: 2026-09-23 | 개정: r1 (2026-09-24, 최종 구성 중심으로 정리) | 작성자: 서준상

대상 프로젝트: 다중 모델·다중 트랙 실시간 SNN 추론 가속기  
관련 문서: [TASKS.md](../design/TASKS.md) Phase 0, [ENVIRONMENT.md](../design/ENVIRONMENT.md), [PROPOSAL.md](../design/PROPOSAL.md)

## 1. 개요

P0.1~P0.4에서는 모델 학습과 FPGA 개발에 필요한 서버·도구·보드 연결을 점검하고, 보드 제약 파일과 프로젝트 생성 스크립트를 마련했다. 점검은 2026-09-22에 수행했으며, 9월 23일에 확정한 작업 환경과 후속 보드 시험 결과를 함께 반영했다.

| 항목 | 작업 | 결과 |
|---|---|---|
| P0.1 | 개발·학습 서버 점검 | RTX 3090 Ti와 PyTorch의 GPU 연산 확인 |
| P0.2 | FPGA 툴체인 점검 | 대상 파트 합성, xsim 시뮬레이션, Verilator lint 통과 |
| P0.3 | 보드 연결 환경 구축 | JTAG에서 `xc7a200t_0` 인식 |
| P0.4 | 보드 제약과 프로젝트 스크립트 작성 | 배치배선 후 87개 포트의 핀 배치 일치 확인 |

네 항목을 모두 완료했다. 이 단계의 검증 범위는 **개발 환경의 동작과 보드 제약의 적합성**이며, 모델 40개·512트랙·32 ms 마감이라는 목표의 달성 여부는 이후 설계 검증과 성능 평가에서 확인한다.

## 2. 대상 보드

| 항목 | 사양 |
|---|---|
| 보드 | ALINX AX7A200B, 코어보드 AC7A200 |
| FPGA | XC7A200T-2FBG484I, Vivado 파트 `xc7a200tfbg484-2` |
| DDR3 | MT41J256M16HA-125 ×2, 32 bit 버스, 1 GiB |
| PCIe | Gen2 ×2, 커넥터는 ×4 크기 |
| 시스템 클럭 | 200 MHz 차동, R4/T4 |
| PCIe 참조 클럭 | Host 슬롯에서 공급하는 100 MHz, F10/E10 |

사양과 핀 배치는 [보드 매뉴얼](../manual/AX7A200_User_Manual.pdf)을 기준으로 정리했다. PCIe 링크의 Gen2 ×2 동작은 후속 P0.7 보드 시험에서 확인했다. 보드의 별도 125 MHz GTP 참조 클럭(F6/E6)은 PCIe 참조 클럭과 구분한다.

## 3. P0.1 — 개발·학습 서버

모델 학습과 FPGA 빌드는 개발 서버에서 수행하고, 보드 제어와 PCIe 시험은 FPGA Host PC에서 수행한다.

| 역할 | 호스트 | 용도 |
|---|---|---|
| 개발·학습 서버 | `Dev-Ubuntu` | 저장소 작업, 모델 학습, 합성·구현·시뮬레이션 |
| FPGA Host PC | `sdsl-llm` | 보드 장착, 로컬 JTAG 제어, PCIe 시험 |

개발 서버의 주요 환경은 다음과 같다. 값은 점검 당시 기준이며, 전체 패키지 버전과 저장 공간은 [ENVIRONMENT.md](../design/ENVIRONMENT.md) §2에 정리했다.

| 항목 | 확인 결과 |
|---|---|
| OS | Ubuntu 24.04.4 LTS |
| CPU / RAM | Intel Core i5-14600K, 12 vCPU / 16 GiB |
| GPU | NVIDIA GeForce RTX 3090 Ti, 24,564 MiB |
| 드라이버 / CUDA | 610.57.04 / CUDA UMD 13.3, `nvcc` 미설치 |
| Python / PyTorch | Python 3.12.3 / PyTorch 2.13.0+cu130 |
| GPU 동작 | CUDA 사용 가능, 4096×4096 FP32 행렬곱 20회 정상 수행 |

학습 GPU는 개발 서버의 **RTX 3090 Ti**로 정했다. 학습과 개발 작업을 같은 서버에서 수행하고, 공용 FPGA Host는 보드 시험에 사용한다. PyTorch의 GPU 연산은 `nvcc` 없이도 확인했으며, 커스텀 CUDA 커널을 컴파일할 경우 Toolkit이 필요하다. 학습 전에는 `nvidia-smi`로 GPU 여유 메모리를 확인한다.

## 4. P0.2 — FPGA 툴체인

| 도구 | 버전·설정 | 검증 결과 |
|---|---|---|
| Vivado | 2026.1, BASIC 라이선스 | `xc7a200tfbg484-2` 합성 성공 |
| xsim | `xvlog` → `xelab` → `xsim` | 카운터 testbench에서 `PASS q=10` |
| Verilator | 5.020, `--lint-only -Wall` | 경고 0건 |

8비트 카운터와 testbench로 합성·시뮬레이션·lint를 확인했다. 이후 RTL 검증에도 xsim과 Verilator를 사용한다.

빌드 시 적용할 환경 설정은 두 가지다.

- **Vivado 실행**: 개발 서버에서는 libudev를 `LD_PRELOAD`하는 `/usr/local/bin/vivado` 래퍼를 사용한다. 원본 실행 파일은 컨테이너의 장치 검색 과정에서 오류가 발생하므로 `settings64.sh`를 직접 적용하지 않는다.
- **빌드 경로**: MIG가 공백이 있는 경로의 설정 파일을 읽지 못하므로, IP를 포함한 설계는 `~/mmss_build/<이름>`처럼 공백 없는 ASCII 경로에서 빌드한다.

## 5. P0.3 — 보드 연결과 작업 절차

FPGA Host에 Vivado 2026.1과 Artix-7 지원 파일, 케이블 드라이버, BASIC 라이선스를 설치했다. 보드는 Host의 PCIe 슬롯에 장착하고 슬롯 전원으로 구동한다.

| 항목 | 확인 결과 |
|---|---|
| Host OS | Ubuntu 24.04.5 LTS |
| JTAG 어댑터 | Digilent로 인식되는 FT232H USB JTAG 다운로더 |
| FPGA 인식 | `xc7a200t_0`, IDCODE `0x13636093` |
| 보드 제어 | Host의 Vivado Hardware Manager에서 로컬 JTAG 사용 |

작업 절차는 다음과 같이 확정했다.

1. 개발 서버에서 합성·구현을 수행하고 비트스트림을 생성한다.
2. `.bit`와 필요한 `.ltx`·`.mcs` 파일을 `scp`로 Host의 `~/fpga_work/`에 전송한다.
3. Host의 Hardware Manager에서 FPGA 다운로드, 플래시 기록, 보드 시험을 수행한다.

초기 인식에 사용한 임시 원격 JTAG 구성은 정식 설치 후 정리했다. 설치와 문제 해결 기록은 [ENVIRONMENT.md](../design/ENVIRONMENT.md)에 남겼다.

## 6. P0.4 — 보드 제약과 프로젝트 생성

### 6.1 산출물

설계에 필요한 제약만 선택할 수 있도록 XDC를 기능별로 나눴다.

| 파일 | 용도 |
|---|---|
| [ax7a200b_base.xdc](../../hardware/constraints/ax7a200b_base.xdc) | 시스템 클럭, 구성 전압, QSPI ×4 설정 |
| [ax7a200b_io.xdc](../../hardware/constraints/ax7a200b_io.xdc) | LED, 리셋, 버튼 |
| [ax7a200b_uart.xdc](../../hardware/constraints/ax7a200b_uart.xdc) | USB-UART 핀 |
| [ax7a200b_ddr3.xdc](../../hardware/constraints/ax7a200b_ddr3.xdc) | DDR3 32 bit 핀 배치, MIG 설정 대조용 |
| [ax7a200b_pcie.xdc](../../hardware/constraints/ax7a200b_pcie.xdc) | PCIe 참조 클럭, 레인과 GTP 채널 대응, PERST# |
| [create_project.tcl](../../hardware/vivado/create_project.tcl) | 프로젝트 생성, 합성·구현·비트스트림 생성 |

DDR3의 DQ·DQS에는 각각 `SSTL15`·`DIFF_SSTL15`와 내부 종단 설정 `IN_TERM UNTUNED_SPLIT_50`을 적용했다. PCIe의 lane0은 `GTPE2_CHANNEL_X0Y7`, lane1은 `X0Y6`에 대응한다. 후속 보드 시험에서는 DDR3의 MIG 핀 71개와 PCIe IP의 GTP 배치가 이 기준과 일치함을 확인했다.

프로젝트 스크립트는 `hardware/src/`와 `hardware/testbench/`의 파일을 재귀적으로 수집한다. `-src`로 RTL 경로를 추가하고, `-xdc`로 제약 파일을 선택하며, `-proj_dir`로 생성 위치를 지정한다. 실행 단계는 `-run synth|impl|bit`로 선택한다. 구현까지 수행하면 자원·타이밍·DRC 보고서를 `<프로젝트>/reports/`에 저장한다.

생성된 프로젝트는 빌드 산출물로 관리하고, 설계 변경은 저장소의 소스와 스크립트에 반영한다.

### 6.2 검증 결과

시험용 탑 모듈에 `base,io,ddr3,pcie` 제약을 적용해 합성부터 비트스트림 생성까지 수행했다.

| 확인 항목 | 결과 |
|---|---|
| 빌드 | 합성·배치·배선·비트스트림 생성 완료 |
| Critical Warning / Error | 각 0건 |
| DRC | 시험용 설계의 미연결 입력 버퍼 경고(BUFC-1) 9건 |
| 핀 배치 | 배선 완료 후 포트 87개의 `PACKAGE_PIN`을 XDC와 대조, 불일치 0건 |
| 타이밍 | WNS +0.767 ns, 시험용 설계 기준 |

이 결과는 **핀 번호·I/O 표준·뱅크 전압이 디바이스 규칙에 맞는지**를 확인한 것이다. 시험용 비트스트림은 DDR3 핀을 임의로 구동하므로 보드에 다운로드하지 않았다. 실제 DDR3·PCIe 동작은 P0.6~P0.7에서 별도로 확인했다.

### 6.3 핀 확인 상태

| 항목 | 상태 |
|---|---|
| PCIe PERST# | P0.4에서는 미확인. 후속 P0.7 보드 시험에서 **L16**으로 확정해 XDC에 반영 |
| 팬 제어(FAN_PWM) | 핀 번호 미확인. 현재 보드에 팬이 없어 보류 |
| USB-UART 방향 | FPGA 기준 송수신 방향 미확인. 최초 사용 시 루프백 시험 필요 |
| 물리 LED·버튼 배선 | 미확인. P0.5에서도 내부 구동값만 JTAG로 확인 |

## 7. 후속 검증

이 단계에서 개발 환경과 보드 연결을 확보했다. DDR3 실효 대역폭·지연, MIG·XDMA 등의 BRAM 점유량, PCIe 지연·지터는 Phase 2에서 측정한다. **DDR3 실효 2.0 GB/s는 아직 가정값**이며, 최종 자원 예산도 측정 결과를 반영해 갱신해야 한다.

후속 완료 결과는 [P0.5~P0.7 보드 시험 보고서](<P0.5~0.7 Research Report.md>)와 [P0.8 저장소 구성·NumPy 순전파 보고서](<P0.8 Research Report.md>)에 정리했다.
