# P3.12 보고서: 평균 response time 단축

작성일: 2026-10-14

2026-10-14부터 목표를 off-chip 접근 최소화에서 평균 response time 단축으로 바꿨다. 이 보고서는 scheduler, cache 교체, prefetch, 연산 방식, Host 입출력 경로를 하나씩 바꾸며 평균 response time이 어디서 줄어드는지 잰 결과다. 값은 모두 simulation이다. Response time은 입력 생성부터 결과가 Host에 도착할 때까지다.

## 1. 요약

### 1.1 환경

| 구분 | 조건 |
|---|---|
| simulator | `sim_core` rev 4에 추론 요청별 연산 시간을 더했다(§3.1) |
| 구성 | L·64 lane, 1,024트랙, membrane potential DDR3, BRAM 예약 25.5 tile |
| 연산 시간 | golden vector 80구간의 layer별 spike 수. control overhead는 dense와 같은 203.4 cycle로 둔다(가정) |
| 입출력 | PCIe 64 B 실측 표본. Ethernet 지연은 아직 재지 않았다 |
| 평가 | 시나리오 6 × seed 20, 기준 조건과 악조건 4개 |

### 1.2 실험과 결과

| # | 실험 | 결과 |
|---|---|---|
| 1 | 단계별 개선 (§3) | 평균 6.16 → 1.51 ms(−75%). 연산이 3.36 ms, 입출력이 1.24 ms, cache 교체와 scheduler가 0.05 ms를 줄였다 |
| 2 | scheduler의 한계 (§2) | weight 적재가 전혀 없어도 1.46 ms다. Scheduler와 prefetch로 줄일 수 있는 폭은 0.05 ms다 |
| 3 | WSPT 대 Dysta Method, 14개 조합 (§4) | entry cache가 있는 A·E·F·G에서는 WSPT가 0.006–0.019 ms 빠르다. B·C·D에서는 느렸다. 적재 대기를 잘못 계산한 탓이고, 고치면 평균이 Dysta Method와 같아진다 |
| 4 | R.복제 × 넓게 읽기 (§5) | 평균 1.19 ms. 복제 없는 최선 조합(1.51 ms)보다 21% 짧다. 악조건 4개에서 miss 0 |
| 5 | 같은 구성에서 WSPT-R 대 Dysta Method (§5.3) | WSPT-R의 평균이 5.5 µs(0.5%) 짧고, 실행별 최대 response time은 0.40 ms 길다 |

### 1.3 결론

1. 평균 response time은 동시 도착 때의 연산 시간과 Host 입출력 대기가 정한다. Compute array가 하나이고 추론 요청마다 일의 양이 비슷해서(변동계수 8%) 처리 순서를 바꿔도 평균은 거의 그대로다.
2. 평균을 크게 줄인 것은 연산 방식(spike 0 건너뛰기, cycle마다 spike 여러 개 누산)과 즉시 입출력이다.
3. 세 축을 함께 바꾼 R.복제 × 넓게 읽기 × batch 단위 scheduler가 가장 빠르다. 이득은 저장과 읽기에서 나온다. Scheduler 쪽 조건은 모델의 대기 추론 요청을 한 batch로 처리하는 것 하나다.
4. WSPT를 제안 scheduler로 내세울 근거는 약하다. 평균은 0.5% 짧지만 최대 response time이 0.4 ms 길다. 신규성 후보는 저장과 읽기의 결합(R.복제·넓게 읽기)으로 두고, scheduler는 가장 단순한 batch 단위 규칙을 쓰는 안을 권한다(제안).

### 1.4 한계와 남은 결정

- R.복제·넓게 읽기는 entry BRAM을 true dual-port로 쓰고, DMA가 여러 entry에 같은 데이터를 동시에 쓸 수 있다는 전제다. RTL로 확인해야 한다.
- 복제 구성에서는 control overhead 203.4 cycle(가정)이 추론 요청당 연산의 41%다. 실제 RTL 값에 따라 결과가 크게 달라진다.
- 입출력 지연은 PCIe 표본이다. Host 링크를 Ethernet으로 바꾸면 다시 재야 한다.
- 최대 트랙 수, XL, 한 줄씩과 복제의 결합은 확인하지 않았다.
- 채택하려면 PROPOSAL과 ARCH_SPEC의 dataflow(§5.2), Host 입출력, cache 교체, scheduler를 바꿔야 한다.

## 2. Scheduler만 바꿀 때의 한계

Compute array가 하나이고 다음 모델의 weight를 앞 batch 연산 중에 받는다고 하자. 그러면 compute array를 쉬게 하지 않는 scheduler는 처리 순서와 상관없이 완료 시각들의 집합이 같고, 평균도 같다. 순서로 바뀌는 것은 두 가지뿐이다. 하나는 weight를 기다리며 compute array가 쉬는 시간이고, 다른 하나는 추론 요청마다 다른 연산 시간의 배치다.

- 쉬는 시간: §3 단계 6 구성에서 weight 적재를 0으로 두어도 평균은 1.51 → 1.46 ms로 0.05 ms 줄 뿐이다.
- 연산 시간의 배치: 추론 요청 하나의 연산 시간은 변동계수 8%다. 일의 크기를 미리 다 알고 짧은 것부터 처리해도, 1,024개가 동시에 도착할 때의 평균 완료 시각은 3.2% 줄어든다(계산, spike 1개/cycle 기준).

평균은 동시 도착 시나리오(synchronized·skewed-synchronized)가 좌우한다. 1,024개 추론 요청이 한꺼번에 들어오면 평균 response time은 대략 몰림 전체 연산 시간의 절반이다. 그래서 추론 요청당 연산을 줄이는 쪽이 효과가 크다.

## 3. 단계별 개선

### 3.1 바꾼 것

| 단계 | 축 | 바꾼 것 | hardware |
|---|---|---|---|
| 1 | 연산 | spike 0 건너뛰기를 simulator에 넣었다. ARCH_SPEC.md §5.2에 이미 있던 동작이다 | 변경 없음 |
| 2 | 연산 | L2·L3에서 cycle마다 spike 입력 2개를 누산한다. BRAM 두 번째 port와 DSP pre-adder를 쓴다 | 두 번째 읽기 주소, spike 번호 2개/cycle |
| 3 | 입출력 | 연산이 끝나면 결과를 바로 Host로 보낸다. Host가 1 ms마다 읽던 방식을 대신한다 | 결과 전송 logic |
| 4 | 입출력 | Host가 입력을 만들자마자 보낸다. 1 ms batch 전송을 없앤다 | Host runtime |
| 5 | 저장 | G.offset-order 교체. 트랙 offset으로 다음 사용을 예측해 가장 늦게 쓸 모델을 내보낸다 | 모델별 다음 사용 시각 |
| 6 | scheduler | WSPT. (적재 대기 + n × 모델 평균 연산) ÷ n이 가장 작은 모델을 먼저 처리한다 | 모델별 평균 연산 register |

추론 요청당 연산(golden vector 평균, control overhead 203.4 cycle 포함):

| 읽기 | word | cycle | µs |
|---|---:|---:|---:|
| dense | 2,034 | 2,237.4 | 22.37 |
| spike 0 건너뛰기 | 699.9 | 903.3 | 9.03 |
| + spike 2개/cycle | 472.2 | 675.6 | 6.76 |
| 넓게 읽기, spike 10개/cycle (§5) | 290.0 | 493.4 | 4.93 |

L1은 mel 입력을 곱하므로 어느 경우에도 dense 240 word다.

## 4. WSPT와 Dysta Method

### 4.1 14개 조합

P3.12 조건의 전체 조합 실험(`p312L64all_fixed_n1024`, seed 20)에서 저장 7 × 읽기 2 조합마다 두 scheduler를 비교했다.

| 저장 | 평균 차 (WSPT − Dysta Method) | WSPT 최대 response time |
|---|---|---|
| A·E·F·G (entry cache) | −0.006 ~ −0.019 ms | 7.1–7.5 ms, Dysta Method와 비슷 |
| B·C·D (부분 상주·고정 혼합·stream) | +0.002 ~ +0.131 ms | B 21.9·31.4 ms, D 26.7·16.8 ms까지 길어짐 |

### 4.2 원인과 수정

WSPT는 다음 모델의 weight를 지금 연산과 겹쳐 받을 수 있다고 보고 적재 대기를 계산했다. Entry cache가 있는 A·E·F·G는 빈 entry에 받으므로 이 가정이 맞다. B·C·D는 적재 buffer가 하나라 앞 batch 연산이 끝나야 받을 수 있다. WSPT는 이 대기를 0으로 보고 작은 batch를 먼저 골랐다.

수정판 WSPT(수정)은 DMA가 비는 시각과 적재 buffer(한 줄씩은 slot)가 비는 시각으로 적재 대기를 계산한다. 평균 ms / 최대 ms:

| 조합 | Dysta Method | WSPT | WSPT(수정) |
|---|---:|---:|---:|
| G·한 번에 | 1.525 / 7.22 | 1.512 / 7.13 | 1.510 / 7.12 |
| B·한 줄씩 | 1.653 / 7.24 | 1.784 / 31.40 | 1.652 / 9.09 |
| D·한 번에 | 1.981 / 8.82 | 2.059 / 26.72 | 1.992 / 26.72 |

수정하면 평균은 Dysta Method와 같아진다. D·한 번에의 최대 response time 26.7 ms는 남았고, 원인은 아직 찾지 않았다.

## 5. R.복제 × 넓게 읽기

### 5.1 구조

| 축 | 이름 | 동작 |
|---|---|---|
| 저장 | R.복제 | 대기 추론 요청이 8개 이상인 모델을 entry 5개에 DMA 한 번으로 동시에 쓴다(broadcast). Entry 10개를 5개씩 번갈아 써서, 한쪽으로 연산하는 동안 다른 쪽에 다음 모델을 받는다. 그 밖에는 G.offset-order와 같다 |
| 읽기 | 넓게 읽기 | 복사본 5개의 두 port에서 word 10개를 읽어 L2·L3에서 cycle마다 spike 입력 10개를 누산한다. L1은 그대로 1개/cycle이다 |
| scheduler | batch 단위 | 모델의 대기 추론 요청을 한 batch로 처리한다. WSPT-R은 복제할 모델을 복제 연산 시간으로 본다 |

hardware 영향(추정, RTL 미확인):

| 항목 | 변화 |
|---|---|
| BRAM, DSP | 없음. Entry 10개와 DSP 64개 그대로 |
| DDR3 weight 읽기 | 거의 같음. 42.8 → 43.0–43.5 KiB/추론 |
| LUT | lane마다 10입력 덧셈기, spike 번호를 cycle마다 10개 내는 생성기. 수천 개로 추정 |
| 전제 | entry BRAM true dual-port, DMA가 여러 entry에 같은 데이터를 동시에 씀 |

### 5.2 결과

시나리오 6 × seed 20, 모두 miss 0.

| 설계 | 평균 ms | 최대 ms | synchronized 평균 ms | skewed-synchronized 평균 ms |
|---|---:|---:|---:|---:|
| R.복제 · WSPT-R | 1.187 | 5.92 | 2.66 | 2.81 |
| R.복제 · Dysta Method | 1.194 | 5.91 | 2.67 | 2.83 |
| R.복제 · Clockwork Method | 1.196 | 5.91 | 2.67 | 2.84 |
| R.복제 · Grouping | 1.199 | 5.94 | 2.67 | 2.82 |
| R.복제 · Dysta Method(추론 요청 단위) | 1.377 | 6.79 | 3.40 | 2.99 |
| 비교: G.offset-order · WSPT(수정) | 1.510 | 7.12 | 3.50 | 3.54 |
| 비교: G.offset-order · Dysta Method | 1.525 | 7.22 | 3.55 | 3.56 |

Batch 단위 scheduler 넷은 1.19–1.20 ms로 같다. 추론 요청을 하나씩 처리하는 Dysta Method(추론 요청 단위)는 복제 적재 한 번을 추론 요청 하나에만 써서 1.38 ms에 머문다.

복사본 수 R과 복제 기준 THR(WSPT-R, seed 5):

| R | THR | 평균 ms | 최대 ms |
|---:|---:|---:|---:|
| 3 | 8 | 1.238 | 6.02 |
| 4 | 8 | 1.205 | 5.91 |
| 5 | 4 | 1.190 | 5.86 |
| 5 | 16 | 1.190 | 6.12 |

R = 5는 entry 10개를 반으로 나눈 값이다. THR은 4–16 사이에서 평균이 같다.

### 5.3 WSPT-R 대 Dysta Method

같은 시나리오와 seed끼리 짝지어 비교했다(실행 120개).

| 지표 | WSPT-R − Dysta Method |
|---|---|
| 평균 | −5.5 µs. WSPT-R이 120번 중 76번 빠르다(t = −6.2) |
| synchronized·skewed-synchronized 평균 | −11.0 µs, −22.9 µs. 둘 다 20번 중 20번 WSPT-R이 빠르다 |
| uniform·skewed·intermittent·fluctuating 평균 | 차이 없음 |
| p99 | +66 µs |
| 실행별 최대 | +0.40 ms. Dysta Method가 120번 중 106번 작다 |

WSPT는 추론 요청당 시간이 짧은 모델부터 처리한다. 무거운 모델이 몰림의 끝으로 밀려서 최대 response time이 길어진다. 복제 없는 G.offset-order에서도 같은 경향이다(평균 −11.9 µs, 최대 +0.39 ms).

### 5.4 악조건

miss / 최대 ms (평균 ms). guard는 꼬리 지연을 모른다. dense는 모든 입력이 spike인 경우로, 연산이 가장 길다.

| 설계 | 기준 | 꼬리 +700 µs | control overhead 20% | DDR3 2.0 GB/s | dense |
|---|---:|---:|---:|---:|---:|
| R.복제 · Dysta Method | 0 / 5.9 (1.19) | 0 / 7.3 (2.62) | 0 / 7.9 (1.62) | 0 / 6.5 (1.27) | 0 / 23.1 (4.87) |
| R.복제 · WSPT-R | 0 / 5.9 (1.19) | 0 / 8.5 (2.61) | 0 / 7.9 (1.61) | 0 / 13.7 (1.27) | 0 / 23.1 (4.86) |

두 scheduler 모두 miss 0이다. DDR3 2.0 GB/s에서 WSPT-R의 최대 response time은 13.7 ms로 Dysta Method(6.5 ms)의 두 배다.
