## 2. 목적

RTL golden reference는 PyTorch 없이 동작해야 한다. 그래서 검증 단계를 다음처럼 나눴다.

```text
PyTorch FP32 → NumPy FP32 → NumPy INT8 → RTL
```

단계를 나누면 구현 오류와 quantization 오차를 구분할 수 있다.

## 5. 새 모델 FP32 비교

`snn_fp32.py`는 다음 순서를 그대로 구현한다.

1. linear current
2. `beta × membrane`
3. current 적분
4. `membrane >= threshold` 발화
5. soft reset

비교 조건은 40개 모델의 전체 test segment다.

| 지표 | 결과 |
|---|---:|
| Segment | 129,792 |
| 판정 불일치 | 1 |
| 파일 AUC 차이 | 소수 4자리에서 0 |
| spike 비교량 | 약 28.4억 |
| spike 불일치 | 200 |

spike 차이는 모두 threshold ±3.1×10⁻⁶ 안에서 시작했다. NumPy와 PyTorch BLAS의 FP32 덧셈 순서가 달라 생긴 반올림 차이다. 한 segment 판정 차이도 두 출력 logit 차이가 약 `1.9×10⁻⁶`인 tie에 가까운 경우였다.

## 6. 판정

- FP32: 판정과 AUC가 같으면 통과
- INT8·RTL: 모든 state와 output이 bit 단위로 같아야 통과

FP32 bit 일치를 강제하면 정상적인 BLAS 반올림 차이까지 오류로 본다. 정수 연산에는 이런 문제가 없다.
