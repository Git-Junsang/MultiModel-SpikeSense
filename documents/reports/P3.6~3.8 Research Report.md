# P3.6~P3.8 보고서: 모델 크기와 scheduler

작성일: 2026-10-11

이 보고서는 P3.6~P3.8의 결론만 모은다. Accuracy는 실제 학습·평가 결과다. 트랙, deadline, energy는 실측 비용을 넣은 simulation 결과다.

## 1. 요약

### 1.1 환경

| 구분 | 조건 |
|---|---|
| Accuracy | DCASE 2020 Task 2, 40대, 지도학습, batch 512, 60 epoch, seed 42 |
| Model | XS~XL, weight INT8 |
| Overlap | 다른 장비 정상음을 waveform에 혼합 |
| Architecture | XL, 256 lane @100 MHz, membrane potential DDR3 |
| Memory·I/O | DDR3 3.015 GB/s, PCIe sample, Host 1 ms batch |
| deadline | 입력 생성→Host 결과 32 ms |
| Scenario | uniform, skewed, synchronized, intermittent, skewed-synchronized, fluctuating × seed 20 |

### 1.2 실험과 결과

| 실험 | 결과 |
|---|---|
| 작은 model | L보다 평균 AUC 0.007–0.029 낮음 |
| XL | L보다 +0.005, CI가 0 포함 |
| Valve | M 0.871 → L 0.905 → XL 0.940 |
| Random overlap | L 0.956 → 0.755, augmentation 뒤 0.821 |
| XL 최대 트랙 | 전체 시나리오 1,232 |
| 1,024트랙 24조합 | miss 0은 8개, FCFS·EDF는 miss 100% |
| SlackBatch | miss 0, Grouping 대비 off-chip −61%, energy −58% |

### 1.3 결론

P3.9 제안안:

- XL INT8 + overlap augmentation
- 256 lane, membrane potential DDR3
- synthesis 목표 1,024트랙
- 전체 model cache entry 2개
- SlackBatch

이 안은 simulation 결과다. 512→1,024트랙과 L→XL 변경은 `PROPOSAL.md`에 아직 반영하지 않았다.

## 2. 모델 크기

40대를 같은 조건으로 학습했다. 값은 file ROC-AUC다.

| 모델 | 구조 | weight/model | 평균 AUC | L 대비 95% CI |
|---|---|---:|---:|---|
| XS | 40-64-32-2 | 4,672 B | 0.9272 | −0.029, −0.041~−0.017 |
| P | 40-128-32-2 | 9,280 B | 0.9430 | −0.013, −0.020~−0.006 |
| S | 40-128-64-32-2 | 15,424 B | 0.9382 | −0.018, −0.028~−0.008 |
| M | 40-256-128-64-2 | 51,328 B | 0.9493 | −0.007, −0.013~−0.000 |
| **L** | 40-384-256-64-2 | 130,176 B | **0.9559** | 기준 |
| **XL** | 40-768-512-128-2 | 489,728 B | **0.9608** | +0.005, −0.004~+0.014 |

작은 모델은 모두 L보다 낮았다. XL의 전체 평균 이득은 작았다. 종류별 차이가 더 컸다.

| 장비 | M | L | XL |
|---|---:|---:|---:|
| valve 7대 | 0.871 | 0.905 | 0.940 |
| 나머지 33대 | L 대비 −0.001 | 기준 | L 대비 −0.002 |

Valve는 7/7 모두 XL에서 좋아졌다. 나머지는 M부터 거의 포화했다.

## 3. 소리 overlap

### 3.1 결과

| 학습 | 평가 | L | XL | XL−L |
|---|---|---:|---:|---:|
| clean | clean | 0.956 | 0.961 | +0.005 |
| clean | random overlap | 0.755 | 0.766 | +0.011 |
| augmented | random overlap | 0.821 | 0.826 | +0.005 |
| augmented | strong −6 dB | 0.755 | 0.765 | +0.010 |

Overlap augmentation은 clean accuracy를 유지하면서 random overlap AUC를 +0.065 회복했다. Valve에서 XL 이득은 strong −6 dB에서 +0.052였다.

강한 overlap에서도 평균 0.90은 달성하지 못했다. Easy +6 dB 조건에서만 0.906이었다.

### 3.2 판단

XL 선택 근거는 clean 평균 +0.005만이 아니다. Valve 7/7 향상과 overlap에서 이득이 커진 점을 함께 봤다.

한계:

- 실제 현장 overlap 수준을 모른다.
- 장비마다 학습 seed 하나만 썼다.
- XL training setting은 L과 같아 XL에 최적화하지 않았다.

## 4. 최대 트랙

### 4.1 L과 XL

모든 시나리오에서 miss 0인 최대 트랙이다.

| Lane | L, state BRAM | L, state DDR3 | XL, state BRAM | XL, state DDR3 |
|---:|---:|---:|---:|---:|
| 32 | 656 | 656 | 160 | 160 |
| 64 | 944 | 1,312 | 336 | 336 |
| 128 | 896 | 2,336 | 448 | 688 |
| 256 | 832 | 3,696 | 400 | **1,232** |

State BRAM 구성은 BRAM이 한계다. State DDR3 구성은 compute가 한계다. XL에서 FCFS는 약 176트랙을 넘지 못했다.

### 4.2 시나리오별 XL 결과

256 lane, state DDR3, Grouping 기준:

| uniform | skewed | synchronized | intermittent | skewed-synchronized | fluctuating |
|---:|---:|---:|---:|---:|---:|
| 1,328 | 1,312 | 1,232 | 5,328 | 1,232 | 1,632 |

동시 도착 synchronized·skewed-synchronized가 상한을 정했다. 1,024트랙은 1,232의 83%다.

## 5. 저장·scheduler·연산

1,024트랙에서 저장 4 × scheduler 3 × 연산 2 = 24조합을 비교했다.

| 결과 | 값 |
|---|---:|
| miss 0 | 8/24 |
| FCFS·EDF | 모두 miss 100% |
| 전체 cache | response time 최소 |
| 부분 상주·혼합 | 상주분이 XL의 약 4%, stream과 비슷 |

전체 cache는 추론 요청당 DDR3 traffic이 많지만 response time이 짧았다. Stream은 response time이 늘지만 weight byte와 추정 energy가 적었다.

## 6. Scheduler 비교

A 전체 cache·한 번에, 1,024트랙 결과다.

| 이름 | miss | 평균 | 최대, 악조건 worst case | off-chip KB/req | Energy µJ/req |
|---|---:|---:|---:|---:|---:|
| FCFS | 100 % | 5.2 s | 17.1 s | 442 | 73.6 |
| EDF | 100 % | 5.2 s | 17.1 s | 442 | 73.7 |
| Grouping | 0 | 8.5 ms | 29.2 ms | 78.8 | 13.7 |
| Dysta | 0 | 8.0 ms | 34.2 ms | 81.0 | 14.1 |
| Timeout | 0.014 % | 10.7 ms | 34.2 ms | 68.9 | 12.1 |
| SlackBatch-Lite | 0 | 11.3 ms | 29.2 ms | 40.2 | 7.3 |
| **SlackBatch** | **0** | **14.0 ms** | **29.8 ms** | **31.0** | **5.8** |

P3.9에서 SlackBatch guard를 고쳤다. 새 정의의 XL 결과는 off-chip 32.3 KB/req, energy 6.0 µJ/req다. 자세한 차이는 [P3.9 보고서](<P3.9 Research Report.md>) §4에 있다.

악조건 5개:

1. 기준
2. Host batch 2 ms
3. PCIe tail +700 µs
4. control overhead +20 %
5. DDR3 2.0 GB/s

Grouping, SlackBatch-Lite, SlackBatch는 모두 miss 0이었다. Dysta Method는 느린 DDR3와 control overhead에서 miss가 났다. Timeout은 평가 seed와 악조건에서 miss가 났다.

SlackBatch는 Grouping 순서를 유지한다. 남은 전송·연산 시간과 deadline 여유로 가장 늦은 안전 시작 시각을 계산한다. 한산할 때는 기다려 batch를 키우고, 몰릴 때는 바로 실행한다.

## 7. 검증과 한계

확인함:

- 40대 모델 크기별 accuracy
- overlap augmentation 효과
- Simulation self-test
- 6시나리오 × seed 20
- 악조건 5개

확인하지 않음:

- 256 lane RTL resource와 timing
- SlackBatch RTL cost
- 실제 보드 miss rate와 response time
- 실제 energy
- Timeout 원 논문의 정확한 범위
