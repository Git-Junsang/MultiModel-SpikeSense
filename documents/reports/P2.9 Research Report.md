# P2.9 보고서: 실시간 특징 정규화

작성일: 2026-10-25, 보드 결과 2026-10-26

Host의 실시간 특징 정규화를 seg에서 "트랙마다 기준을 이어 가며 τ = 5 s로 잊는 방식"으로 바꿨다. seg는 판정 주기마다 기준을 지웠다. 첫 보드 시험에서 파일 사이 무음과 소리가 끊기는 경계 frame에 약한 점이 드러나, 하한·무음 frame·조용한 frame 처리를 더했다. 재학습은 하지 않았다. 최종 규칙으로 P5.3 입력을 보드에서 다시 돌린 AUC는 0.9531이다. P5.3 seg는 0.9383, 학습 특징 software 평가는 0.9554다. Offset Assignment, cache, RTL, 추론 요청 형식은 바꾸지 않았다.

## 2. 실험과 결과

### 2.1 최종 규칙

Frame k의 mel dB를 d라 한다.

```text
d    = max(dB, F)                          F: 트랙의 하한(기본 −80 dB). m_k, n_k = frame k의 d 최대·최소
m_k ≤ F + 6        → 무음 frame: 기준을 그대로 둔다
m_k < hi − 15      → 조용한 frame: 최소는 그대로, 최대만 아래 식으로 갱신
그 밖              → hi = max(m_k, a·hi + (1 − a)·m_k),  lo = min(n_k, a·lo + (1 − a)·n_k),  a = e^(−32 ms / τ), τ = 5 s
l = max(lo, hi − 80),  x = clip((d − l) / (hi − l), 0, 1),  x_q = clip(rint(127x), 0, 127)
```

- Frame의 최대·최소가 기준을 넘으면 바로 받고, 아니면 시간 상수 τ로 그 값 쪽으로 돌아간다. 소리 크기를 따라가는 envelope follower와 같은 꼴이다. τ 하나가 "잊는 시간"이라 설명하기 쉽고, τ = ∞이면 누적 최대·최소가 된다.
- 기준은 처음 소리가 난 frame에서 시작하고 판정 주기가 바뀌어도 지우지 않는다. Membrane potential은 지금처럼 판정 주기마다 `RESET_STATE`로 새로 시작한다.
- 지난 frame만 쓰므로 frame 64 ms, 32 ms 간격, deadline, 계산 시작 시각이 바뀌지 않는다.
- DCASE 소리는 −65 dB 아래로 내려가지 않는다(test 파일 600개, −80 dB 아래 칸 0개). 그래서 F = −80 dB는 학습 특징을 바꾸지 않는다. 정상 소리의 frame 최대가 기준 최대보다 내려간 폭은 p99.9 15.5 dB, 최대 24.5 dB다.

### 2.2 τ 고르기

두 조건에서 쟀다. "파일마다 새로 시작"은 파일 첫 frame에서 기준을 새로 시작한다. 첫 판정 주기가 seg와 같은 보수적 조건이다. "stream"은 모델마다 test 파일을 무작위 순서(seed 0)로 이어 트랙 하나처럼 듣고, 기준을 파일 사이에서도 이어 간다. 모델마다 몇 시간 길이이고 10 s마다 소리 크기가 갑자기 바뀐다.

`L_normal_noaug`. 칸은 평균 AUC, 0.9 이상 모델 수, 장비 종류별 평균, 최저 모델이다.

| seg(바꾸기 전 Host) | 0.9401 | 33 | 0.878 | 0.913 | 0.937 | ToyCar_id05 0.790 |
| unit(장비별 고정값) | 0.9177 | 29 | 0.950 | 0.807 | 0.888 | pump_id00 0.541 |
| 파일마다 새로 시작, τ = 2 s | 0.9508 | 36 | 0.924 | 0.918 | 0.943 | ToyCar_id05 0.795 |

`L_mixed_aug`의 평균 AUC는 file 0.9513, seg 0.9392다. 파일마다 새로 시작 / stream으로 τ = 2 s 0.9438 / 0.9442, 5 s 0.9474 / 0.9485, 10 s 0.9502 / 0.9495, ∞ 0.9527 / 0.8912다.

- τ = ∞는 stream에서 0.8639로 떨어진다. 한 번 들은 가장 큰 소리가 기준에 계속 남아, 기준이 "가장 큰 소리 − 80 dB"로 굳기 때문이다.
- τ = 10 s는 파일마다 새로 시작하면 가장 높지만 stream에서 valve가 0.875다. 파일이 바뀐 뒤에도 앞 파일의 소리 크기를 오래 기억한다.
- τ = 5 s는 두 조건 중 나쁜 쪽 평균이 가장 높다(2 s 0.9508, 5 s 0.9539, 10 s 0.9480). 사용자 결정으로 τ = 5 s를 골랐다.

### 2.3 무음 처리

τ = 5 s 규칙만 넣은 Host로 보드를 돌리자 AUC가 0.8734로 seg(0.9383)보다 낮았다. pump는 0.816, valve는 0.745였다. FPGA 출력과 Host 특징은 Python과 같았다. 원인은 두 가지였다.

1. 파일 뒤 무음(샘플 0)의 mel dB는 −100이다. 최소를 바로 받으므로 기준의 최소가 무음에서 떨어지고, 다음 파일에서 τ에 걸쳐 천천히 돌아온다. 그동안 정규화 폭이 넓어져 폭이 좁은 pump·valve·slider(파일 폭 40–44 dB) 특징이 무너진다.
2. 소리가 끊기는 경계 frame은 소리 몇 샘플과 0이 섞여 무음보다는 크지만 매우 작다. 이런 frame도 최소를 끌어내린다. librosa 평가는 파일 끝을 반만 채우므로 이런 frame이 없다.

software에서 stream 조건의 파일 사이에 같은 길이의 무음 frame을 넣어 1을 확인했다. 2는 보드 입력으로 Python 경로를 계산해 확인했다. pump_id00은 보드 규칙에서 0.574, 파일마다 기준을 새로 시작하면 0.855였다.

후보를 software 세 조건(파일마다 새로 시작 / stream / stream + 파일 사이 무음)으로 쟀다. `L_normal_noaug` 평균 AUC다.

| 규칙 | 파일마다 새로 시작 | stream | stream + 무음 |
|---|---:|---:|---:|
| τ = 5 s만 | 0.9560 | 0.9539 | 0.8683 |
| A: 하한 −80 dB + 무음 frame은 기준 멈춤 | 0.9560 | 0.9539 | 0.9539 |
| B: A + 최소도 천천히 따라감 | 0.9435 | 0.9196 | 0.9196 |
| A + 조용한 frame(기준 최대 − 15 dB)은 최소 멈춤(최종) | 0.9560 | 0.9539 | 0.9539 |

`L_mixed_aug`는 τ = 5 s만 0.9474 / 0.9485 / 0.8888, A 0.9474 / 0.9485 / 0.9485, B 0.9411 / 0.9278 / 0.9278, 최종 0.9473 / 0.9487 / 0.9487이다. B는 파일이 바뀔 때 최소가 늦게 따라가 오히려 나빠졌다.

경계 frame(원인 2)은 software 평가에 없다. 그래서 조용한 frame 기준은 보드 입력의 Python 경로로 골랐다. FPGA 출력이 같은 입력의 snn_int8과 bit 단위로 같으므로 이 값이 그 규칙으로 보드를 돌린 AUC다.

| 조용한 frame 기준 | 보드 입력 평균 AUC(40개) | ≥ 0.9 |
|---|---:|---:|
| 없음(A, 보드 실측) | 0.9305 | 31 |
| 30 dB | 0.9461 | 32 |
| 20 dB | 0.9514 | 35 |
| 15 dB | 0.9531 | 35 |

15 dB는 DCASE 정상 frame의 0.1%도 조용한 frame으로 본다. 하지만 위 software 세 조건의 값은 소수 넷째 자리까지 같았다. 그래서 15 dB를 골랐다.

## 3. 결론

1. 트랙마다 기준을 이어 가며 τ = 5 s로 잊고 무음·조용한 frame에서 기준을 멈추면, 재학습 없이 보드 AUC가 seg 0.9383에서 0.9531로 오른다. 학습 특징의 software 값 0.9554에 가깝다. 손실의 대부분이던 ToyCar가 0.873에서 0.951로 회복된다.
2. 잊지 않는 규칙(τ = ∞)은 쉬지 않고 도는 트랙에서 무너지므로 쓰지 않는다.
3. 최소를 바로 받는 규칙은 무음과 소리가 끊기는 frame에 약하다. 하한·무음 frame·조용한 frame 처리로 막았다. 실제 mic에서는 하한을 mic의 바닥 잡음 위로 정한다.
4. 규칙은 02 §5와 06 §2에 적었고 Host program에 들어 있다. Offset Assignment, cache, RTL, 추론 요청 형식은 그대로다.

## 4. 한계

- τ와 15 dB를 평가에 쓴 test 파일과 보드 입력으로 골랐다. 후보가 적고(τ 4개, 기준 3개) 차이도 작지만 선택 편향이 있다.
- 보드 배치는 소리를 샘플 0으로 자르는 인공 조건이다. 실제 mic에서는 하한을 정하는 절차와 긴 stream에서의 동작을 재지 않았다(mic 없음).
- software 평가는 librosa `center=True` frame과 16 bit 저장이다. 보드는 Host frame 경계와 12 bit 저장이다.
- 결과 손실(38–66개)은 FPGA가 보낸 뒤 Host 수신 쪽에서 생긴다. 원인은 sub1 Host NIC(Intel I219)의 절전이다([P5.3 결과 손실 보고서](<P5.3 Result Loss Research Report.md>)). 정확도 비교에는 영향이 없다(빠진 판정 주기는 판정하지 않음).
