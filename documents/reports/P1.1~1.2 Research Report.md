## 1. 요약

Phase 1의 앞 두 항목을 2026-09-22~23에 수행했다. 목표는 **40개 모델을 무엇으로 학습할지 정하고, 그 결정이 가속기 설계 수치에 미치는 영향을 확정하는 것**이었다.

| Task | 내용 | 결과 |
|---|---|---|
| P1.1 | 데이터 확보 방안 결정, 출력 라벨 정의 | 완료. **DCASE 2020 Task 2** 전체 내려받기·검증, 출력은 **2클래스(정상/이상)**로 확정 |
| P1.2 | 40개 모델 구성과 트랙↔모델 매핑 초안 | 완료. 기계 41대 중 **40대 선정**(fan id_00 제외), 학습용 이상 정의는 **지도학습**으로 확정, 매핑 3안 제시 |

이 단계의 결정은 세 가지다.

1. **출력을 8클래스(정상 + 결함 7종)에서 2클래스(정상/이상)로 바꿨다.** 결함 종류 라벨이 있는 공개 음향 데이터는 시험대 1~8대 규모뿐이어서 40개 개인화 모델과 양립하지 않는다(§3). 모델당 가중치는 130,560 B → **130,176 B**, 뉴런은 712 → **706**이 됐고, 대역폭·캐시 결론은 바뀌지 않는다(§4).
2. **데이터는 DCASE 2020 Task 2로 확정했다.** 기계 ID가 **41개**로 목표 모델 수 40개와 거의 같고, ID 하나당 정상 녹음이 72분~2.8시간이다.
3. **학습용 이상을 정의하는 방식이 실험으로 뒤집혔다.** 처음에는 "같은 기종 다른 ID의 정상 소리를 가짜 이상으로 쓰는" DCASE 관례를 따르려 했으나, 이 방식은 가짜 이상만 구분하고 **실제 이상에서는 AUC 0.38~0.48로 무학습 기준선(0.56)보다 나빴다.** 그래서 실제 이상 파일 절반을 학습에 쓰는 지도학습으로 바꿨다(§5.2).

데이터셋 규모·ID 구성은 **내려받은 파일을 직접 센 값**이고, 학습 방식 비교 수치는 **실제 학습을 돌려 얻은 값**이다. 다른 데이터셋의 수치는 공개 문서를 읽은 값이며 직접 확인하지 않았다.

## 2. 이 단계의 목적과 요구 조건

### 2.1 왜 데이터를 먼저 정하는가

이 연구의 평가 대상은 스케줄러와 온칩 저장 정책이지 모델 정확도가 아니다. 그래도 데이터는 두 경로로 하드웨어 설계에 들어온다.

- **모델 수 M = 40의 근거**: "개인화 모델 40개"가 데이터로 뒷받침되지 않으면 40개라는 조건 자체가 임의의 가정이 된다.
- **모델 구조**: 출력 클래스 수가 가중치 크기·뉴런 수를 바꾸고, 그것이 막전위 용량·BRAM 예산·전송 시간 계산 전체로 퍼진다.

### 2.2 요구 조건

| 조건 | 이유 |
|---|---|
| 서로 다른 기계 개체 40대 이상 | 모델 40개를 "개인화"로 설명하려면 기계마다 데이터가 달라야 한다 |
| 기계 1대당 학습 데이터가 충분할 것 | 모델 40개를 각각 학습해야 한다 |
| 음향(마이크) 데이터 | Host 전처리(USB 마이크 → mel 40차원)와 데모 구성이 음향 기준이다 |
| 입력 차원·주기 정합 | 선행 프로젝트의 mel 40차원, hop 512 @ 16 kHz = 32 ms 주기를 그대로 쓴다 |
| 연구 목적 사용 가능 라이선스 | 논문·공개 저장소에 결과를 싣는다 |

### 3.2 결함 종류와 기계 대수는 양립하지 않는다

조사 결과는 한 줄로 요약된다. **결함 종류를 구분해 놓은 데이터는 거의 전부 시험대 1대(UOEMD는 모터 8대)에서 나온다.** 기계를 40대 모으려면 결함 라벨을 포기해야 하고, 결함 라벨을 얻으려면 기계 대수를 포기해야 한다.

여러 데이터셋을 합치는 방법도 검토했다. 모델마다 다른 데이터셋을 쓰는 것은 가능하지만(모델 40개는 서로 독립이므로), **출력의 의미는 모든 모델에서 같아야 Host가 결과를 일관되게 해석**할 수 있다. 공통 분모를 찾으면 4클래스(정상 / 불균형 / 정렬 불량 / 베어링 결함)가 최대이고, 쓸 수 있는 데이터는 KAIST·UOEMD·MaFaulDa뿐이다. 셋을 다 합쳐도 다음과 같다.

| 4클래스 통합 시 | 정상 | 불균형 | 정렬 불량 | 베어링 | 합계 |
|---|---|---|---|---|---|
| KAIST (부하 3종) | 120초 × 3 | 60초 × 5 × 3 | 60초 × 3 × 3 | 60초 × 6 × 3 | 48분 |
| UOEMD | 10초 × 16 | 10초 × 16 | 10초 × 16 | 10초 × 16 | 10.7분 |
| MaFaulDa | 5초 × 49 | 5초 × 333 | 5초 × 498 | 5초 × 1,071 | 2.7시간 |
| **합계** | **약 12.8분** | 약 33분 | 약 45분 | 약 1.6시간 | **약 3.7시간** |

모델 40개로 나누면 **모델당 약 5.5분, 정상은 약 19초**다. 시험대가 3곳뿐이라 40개로 나누는 기준도 기계 개체가 아니라 속도·부하 조건이 된다. DCASE는 ID 하나당 정상만 72분~2.8시간이므로 차이가 두 자릿수다. 4클래스 안은 기본 조건에서 제외했다.

## 4. 출력 2클래스 변경이 설계에 미치는 영향

`40→384→256→64→8`을 `40→384→256→64→2`로 바꾸면서 관련 수치를 다시 계산했다.

| 항목 | 8출력 (이전) | 2출력 (확정) |
|---|---|---|
| 가중치 | 130,560 B = 127.5 KiB | **130,176 B = 127.125 KiB** |
| 뉴런 | 712 | **706** |
| 막전위(512트랙) | 712 KiB | **706 KiB** |
| 모델 저장 가용분 | 703 KiB | **709.375 KiB** |
| 전체 캐시 가능 모델 | 5벌 | **5벌** (709.375 / 127.125 = 5.58) |
| 재사용 없는 전송률 | 2.089 GB/s (104.4%) | **2.083 GB/s (104.1%)** |
| 완전 그룹핑 전송률 | 163.2 MB/s (8.2%) | **162.72 MB/s (8.1%)** |
| 모델 전체 전송 | 65.28 µs | **65.088 µs** |
| 요청당 순수 연산 | 40.8 µs | **40.68 µs** |
| 트랙 경계(대역폭/연산/막전위) | 490 / 784 / 926 | **491 / 786 / 934** |

출력층 가중치는 `64 × 8 = 512 B`에서 `64 × 2 = 128 B`로 줄어 전체의 0.3%만 바뀐다. **40개 모델이 온칩에 다 들어가지 않는다는 조건(5,085 KiB > 709 KiB)은 그대로**이므로 문제 설정과 저장 정책 비교는 영향을 받지 않는다.

반영한 곳은 다음과 같다.

- [PROPOSAL.md](../design/PROPOSAL.md) rev.4, [AGENTS.md](../../AGENTS.md), [TASKS.md](../design/TASKS.md) r4, [RELATED_WORK.md](../design/RELATED_WORK.md), 요약본 3건
- 2026-09-17 중간보고 PPTX의 슬라이드 3·4·6·9·16 표와 발표자 노트
- `software/model_develop/snn_model.py`의 `LAYER_SIZES`. 자체 검증에서 가중치 130,176개·뉴런 706개·순전파 출력 형태를 확인했다

중간보고 슬라이드의 보드 표기 `AX7203B · PCIe Gen2 ×4`도 실물과 달라 `AX7A200B · XC7A200T · PCIe Gen2 ×2`로 함께 고쳤다.

**주의**: P1.4 직전의 배치·에포크 결정 실험은 구조 변경 이전에 돌려서 8출력 모델(130,560개)을 썼고, 나중에 40대 구성에서 제외된 `fan_id00`에서 수행했다. 출력 8개 중 2개만 사용했으므로 배치·에포크 결론은 그대로 쓸 수 있다. 실험 폴더는 제외 장비 정리와 함께 지웠고, 결론에 쓴 수치는 `analysis_data/REPORT.md` §배치·에포크를 정한 근거로 옮겼다.

## 5. P1.2 — 모델 40개 구성

### 5.1 41대 중 40대 선정 — fan id_00 제외

기계 ID는 41개, 목표 모델 수는 40개이므로 1대를 뺀다.

처음에는 **성능과 무관하게 `slider_id06`을 임의로 제외**했다. 학습용 정상이 434개로 가장 적은 축이고 이상 샘플이 89개로 가장 적어 평가 신뢰도가 낮다는 이유였다.

그런데 40대를 학습해 보니 **`fan_id00`이 AUC 0.738로 가장 낮았고**, 같은 조건으로 `slider_id06`을 학습하자 **0.9982**가 나왔다. 그래서 2026-09-23에 둘을 맞바꿨다. `fan_id00`의 wav·학습 기록은 이후 저장소에서 삭제했다.

최종 구성은 fan 01~06(6), pump 00~06(7), slider 00~06(7), valve 00~06(7), ToyCar 01~07(7), ToyConveyor 01~06(6) = **40대**다. 장비 이름은 `<기종>_id<두 자리>` 형식을 쓴다.

**이 교체는 평가 결과를 보고 고른 것이다.** 따라서 40대 평균 성능은 "40트랙에 올릴 장비를 고른 뒤의 값"이며 방법 자체의 기대 성능이 아니다. 이 점을 드러내기 위해 41대 전부의 평균(AUC 0.9510)도 함께 기록한다. 제외한 `fan_id00`의 wav·학습 기록은 저장소에서 삭제했다. 비교에 쓴 수치(AUC 0.738)만 문서에 남는다.

### 5.2 학습용 이상 정의 — 가짜 이상은 실패했고 지도학습으로 바꿨다

DCASE 2020 Task 2는 원래 **이상 데이터 없이 학습하는 과제**다. 이상 샘플은 테스트 세트에만 있다. 그래서 처음 계획은 챌린지 상위 팀들이 쓴 방식, 즉 **같은 기종 다른 ID의 정상 소리를 가짜 이상으로 학습**하는 것이었다.

`fan_id00`에서 세 방식을 비교했다(파일 단위 AUC, test는 그 장비의 실제 정상·이상).

| 방식 | 학습용 이상의 정의 | val AUC(가짜 이상 기준) | **test AUC(실제 이상)** |
|---|---|---|---|
| other_id | 같은 기종 다른 ID(fan 01~06)의 정상 소리 | 0.997~0.998 | **0.384~0.423** |
| mix | 대상 ID 정상에 다른 ID 소리를 부분 합성(−6~+3 dB) | 0.914~0.920 | **0.396~0.481** |
| real (지도학습) | 실제 이상 파일 절반(183개) | 0.665 | **0.689 / 0.755** |
| 기준선 | 파일 평균 mel의 Mahalanobis 거리, 학습 없음 | — | 0.564 |

결론은 명확했다.

- **가짜 이상은 가짜 이상만 구분한다.** other_id는 val에서 0.998을 찍고 실제 이상에서는 0.4 근처다. AUC가 0.5보다 **낮다**는 것은 실제 이상을 오히려 정상 쪽으로 판정한다는 뜻이다. "다른 ID처럼 들리면 이상"이라는 규칙이 이 장비의 실제 고장 방향과 어긋난다.
- **구조의 문제는 아니다.** 같은 모델·같은 입력에 실제 이상을 넣으면 0.69~0.76이 나온다. 기준선 0.56과 DCASE 공식 AE 기준선(이 장비 약 0.54)을 크게 넘는다. 막힌 곳은 모델이 아니라 학습용 이상의 정의였다.

그래서 **실제 이상 파일의 절반을 학습에, 나머지 절반과 test 정상 전체를 평가에 쓰는 지도학습**으로 바꿨다. 이 선택의 성격을 분명히 해 둔다.

- **DCASE 2020의 과제 조건(비지도)에서 벗어난다.** 따라서 이 프로젝트의 AUC를 챌린지 순위표와 직접 비교할 수 없다. 논문에서는 조건을 명시해야 한다.
- 이 연구의 목적은 이상 탐지 성능 경쟁이 아니라 **40개 모델의 가중치를 실제로 확보해 스케줄러·저장 정책을 평가하는 것**이므로, 학습 조건이 챌린지와 달라도 가속기 평가에는 영향이 없다.
- 평가 지표는 DCASE 관례대로 **파일 단위 AUC와 pAUC(FPR ≤ 0.1)**를 쓴다.

이 방식으로 40대를 학습한 결과는 평균 AUC 0.9563이다. 상세는 P1.4의 범위이며 `analysis_data/REPORT.md`에 있다.

### 5.3 트랙↔모델 매핑 초안

512트랙을 40개 모델에 배정한다. 같은 모델을 쓰는 트랙이 많을수록 Channel Window로 묶을 수 있는 요청이 많아지므로, 매핑은 **스케줄러 평가의 입력 조건**이다. 하나로 고정하지 않고 세 조건을 둔다.

| 조건 | 배정 | 주기당 모델별 요청 수 | 의도 |
|---|---|---|---|
| **U (균등)** | 32모델 × 13트랙 + 8모델 × 12트랙 = 512 | 12~13 | 기본 조건. 완전 그룹핑 계산(162.72 MB/s)과 직접 비교된다 |
| **S (편중)** | 상위 8모델 × 32트랙 + 하위 32모델 × 8트랙 = 512 | 8 또는 32 | 인기 모델과 비인기 모델이 섞인 상황. 캐시 적중과 기아 현상을 함께 본다 |
| **D (희소)** | 40모델 × 1트랙 = 40트랙만 활성 | 1 | 재사용이 불가능한 최악 조건. 전송이 곧 병목이 된다 |

트랙 번호와 모델의 대응은 기종을 섞어 배치한다. 인접 트랙이 같은 기종·같은 모델에 몰리면 스케줄러가 우연히 유리해질 수 있기 때문이다.

세 조건 모두 **도착 위상은 트랙마다 다르게** 준다. 32 ms 주기 안에서 균등 분포한 위상에 통신 지터를 더한다. 구체적인 지터 분포와 트레이스 생성은 P2.5의 시뮬레이터에서 정한다.

이 매핑은 **초안**이다. 실측 대역폭(P2.1)과 비용 모델이 나오면 조건 수와 편중 정도를 조정한다.

**확인한 것**

- DCASE 2020 Task 2 전체를 내려받아 md5 19개가 모두 일치함을 확인했다 (wav 54,254개, 17 GB)
- 기계 ID가 41개이고, ID별 학습용 정상이 434~1,000개, 개발용 ID의 이상 샘플이 89~407개임을 직접 셌다
- 결함 종류 라벨이 있는 공개 음향 데이터로는 기계 40대를 구성할 수 없다는 것을 조사로 확인했다
- 가짜 이상(other_id·mix) 학습이 실제 이상 탐지에서 기준선보다 나쁘다는 것을 `fan_id00` 실험으로 확인했다
- 같은 모델·같은 입력에 실제 이상을 학습시키면 기준선을 크게 넘는다는 것을 확인했다(구조의 한계가 아님)
- 출력 2클래스 변경에 따른 설계 수치를 다시 계산하고 문서·슬라이드·모델 코드에 반영했다

| 항목 | 어디서 하는가 |
|---|---|
| 가짜 이상 방식이 다른 장비(신호가 분명한 장비)에서도 실패하는지 | 미확인. `fan_id00` 한 대에서만 비교했다 |

## 7. 남은 판단 사항

1. **모델 크기의 근거**: 8출력을 빼면서 "다중 결함 진단"이라는 응용 측 명분이 사라졌다. `40→384→256→64→2`(127 KiB)가 선행 모델 `40→128→32→2`(9 KiB)보다 정확도 이득이 있는지를 측정해 근거로 삼아야 한다. 이득이 없다면 모델 크기를 "대역폭 문제를 만들기 위한 설정"으로만 설명하게 되므로, 논문에서 이 점을 어떻게 서술할지 정해야 한다.
2. **지도학습 전환의 서술**: DCASE 비지도 조건에서 벗어났으므로, 논문·발표에서 "챌린지 점수와 비교 불가"를 명시하고 가속기 평가에는 영향이 없다는 점을 함께 적어야 한다.
3. **제외 장비 선정의 서술**: `fan_id00` 제외는 학습 결과를 보고 한 선택이다. 40대 평균(0.9563)과 41대 평균(0.9510)을 항상 함께 보고한다.
4. **데이터의 git 추적**: `software/data/`가 `.gitignore`에 없으면 wav 54,254개가 추적 대상이 된다. ignore 정책 변경은 별도 합의가 필요하다.
5. **부가 실험 범위**: 결함 종류 구분(KAIST 5클래스 등)을 실제로 수행할지, 한다면 모델 몇 개로 할지는 Phase 5의 실험 매트릭스를 정할 때 결정한다.

다음 단계는 **P1.5(INT8 양자화와 정확도 비교)**다.
