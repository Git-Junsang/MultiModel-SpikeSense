# P3.24 보고서: RTL 연산 cycle을 넣은 비교 재실험

작성일: 2026-10-17

> 2026-10-18 정정: 이 보고서의 jitter는 트랙마다 한 번 뽑아 모든 주기에 반복했고, offset-order cache가 그 위상을 알았다(미래 정보 누출). jitter 한계 3.2 ms와 §3.4의 논문 값은 쓰지 않는다. 동적 jitter로 다시 한 결과는 [P3.25 보고서](<P3.25 Research Report.md>)에 있다.

P4.1에서 control overhead가 67 cycle로 나왔다(가정은 203). 이 값을 simulation에 넣고 Dysta Method·DeepRT Method와의 비교를 다시 돌렸다. jitter를 0~6.4 ms로 바꿔 entry 4개로 버티는 jitter 한계도 찾았다. 값은 모두 simulation 결과이고 보드 실측이 아니다.

## 1. 요약

### 1.1 환경

| 구분 | 내용 |
|---|---|
| 구성 | L·64 lane @100 MHz, 1,024트랙, 모델 40개, entry 4개, 남는 BRAM에 12 bit membrane potential, spike 2개/cycle, 즉시 입출력 |
| 연산 cycle | control overhead 67 cycle(P4.1 RTL). 환경 값 `ovh = 1.03294`, (1.03294 − 1) × dense 2,034 word = 67 |
| DDR3 | P3.1 실측 회귀(read 0.244 µs + byte ÷ 3.015 GB/s) |
| 외부 지연 | 0. 입출력은 PCIe 64 B 실측 표본(편도 평균 약 0.03 ms) |
| 방법 | 제안(offset 배정 + offset-order cache + Grouping), Dysta Method·DeepRT Method(offset 배정 없음, LRU). 같은 BRAM·trace |
| 평가 | 시나리오 6개 × seed 10. 환경 파일 `p324_rtl_compare`, `p324_rtl_jitter`, `p324_rtl_dysta_eta` |

### 1.2 결과

| 질문 | 답 |
|---|---|
| engine cycle이 RTL과 같은가 | 실데이터 2,480 추론 모두 같다. 평균 535.9, 최소 389, 최대 621 cycle로 P4.1 xsim 측정과 같다 |
| jitter 0.8 ms 비교 | 제안 6.36 KiB/추론, 최대 응답 시간 0.69 ms. Dysta Method 57.0 KiB/추론, 5.84 ms. DDR3 −88.8 %, 최대 응답 시간 −88.3 % |
| entry 4개로 버티는 jitter | 3.2 ms. 3.2 ms에서 7.07 KiB/추론, 3.6 ms에서 13.6 KiB/추론으로 두 배가 된다 |
| jitter 0~3.2 ms의 가장 나쁜 값 | DDR3 7.07 KiB/추론(jitter 3.2 ms), 최대 응답 시간 1.44 ms(jitter 0), 최소 deadline 여유 30.56 ms. deadline miss 0 |
| 그 범위에서 Dysta Method 대비 | DDR3 −87.6 %, 최대 응답 시간 −75.4 % |
| Dysta Method 조절값 | η를 15개 후보로 바꿔도 57.0~59.2 KiB/추론, 최대 5.82~5.87 ms. 지금 값(1e-4)을 그대로 쓴다 |

### 1.3 결론

1. 연산 시간이 줄어 응답 시간만 바뀌었다. 제안의 평균 응답 시간은 0.179 → 0.114 ms, 최대는 1.08 → 0.69 ms다. DDR3 전송량은 6.36 KiB/추론 그대로다.
2. entry 4개는 jitter 3.2 ms(entry 4 × offset 간격 0.8 ms)까지 버틴다. 그보다 크면 DDR3 전송량이 jitter에 따라 빠르게 는다. 6.4 ms에서도 Dysta Method보다는 적다(40.6 KiB/추론).
3. jitter 0~3.2 ms 범위의 가장 나쁜 값으로 비교해도 Dysta Method보다 DDR3는 88 %, 최대 응답 시간은 75 % 작다.

## 2. 방법

### 2.1 RTL cycle 반영

engine은 추론마다 golden spike 수로 word를 센다(`240 + 4⌈n1/2⌉ + ⌈n2/2⌉ + 2`). 여기에 control overhead `(ovh − 1) × 2,034` cycle을 더한다. P4.1 RTL은 실데이터 모든 추론에서 control overhead가 67이었다. 그래서 `ovh = 1.03294`면 engine의 추론별 cycle이 RTL과 같다. golden_l64 80개(첫 timestep 포함 2,480 추론)로 둘을 대조해 모두 같음을 확인했다.

dense 연산 시간(`C_REQ`, scheduler guard가 쓰는 보수적 값)도 같은 배수라 2,237 → 2,101 cycle로 바뀐다.

### 2.2 값 정리

- 최대 응답 시간은 점마다 실행 60개 중 가장 큰 값이다.
- 최소 deadline 여유는 32 ms − 최대 응답 시간이다. 외부 지연이 0이라 이렇게 바로 구한다.
- "jitter J 이하" 값은 시험한 jitter 0~J 가운데 가장 나쁜 값이다. DDR3는 가장 큰 값, 응답 시간은 가장 긴 값을 쓴다.
- Dysta Method·DeepRT Method는 offset 배정이 없어 jitter와 무관하다. 한 번만 돌렸다.

## 3. 결과

### 3.1 비교 (jitter 0.8 ms)

| 방법 | DDR3 KiB/추론 | DDR3 MB/s | 평균 응답 시간 ms | 최대 응답 시간 ms | deadline miss |
|---|---:|---:|---:|---:|---:|
| Dysta Method | 57.01 (56.84) | 1,520 | 1.320 (1.608) | 5.84 (7.19) | 0 |
| DeepRT Method | 11.26 (11.26) | 300 | 7.748 (7.842) | 16.67 (17.37) | 0 |
| **제안** | **6.36 (6.36)** | **169** | **0.114 (0.179)** | **0.69 (1.08)** | 0 |

괄호는 control overhead 203 cycle일 때 값(`p321_compare`, entry 4)이다.

- Dysta Method 대비 제안: DDR3 −88.8 %, 평균 응답 시간 −91.4 %, 최대 응답 시간 −88.3 %.
- DeepRT Method 대비 제안: DDR3 −43.5 %, 평균 응답 시간 1/68.
- DDR3 전송량은 연산 시간이 바뀌어도 거의 그대로다. cache hit과 batch 구성이 도착 순서로 정해지기 때문이다.
- 제안의 최대 응답 시간 0.69 ms는 편중 시나리오(skewed·skewed-synchronized)에서 나온다. 다른 시나리오는 0.23 ms 이하다. Dysta Method의 5.84 ms는 동시 도착(synchronized·skewed-synchronized)에서 나온다.

### 3.2 jitter 한계

| jitter ms | DDR3 KiB/추론 | DDR3 MB/s | 평균 응답 시간 ms | 최대 응답 시간 ms | hit rate |
|---:|---:|---:|---:|---:|---:|
| 0 | 6.36 | 169 | 0.265 | 1.44 | 0.10 |
| 0.4 | 6.36 | 169 | 0.152 | 1.06 | 0.92 |
| 0.8 | 6.36 | 169 | 0.114 | 0.69 | 0.93 |
| 1.2 | 6.37 | 170 | 0.087 | 0.68 | 0.93 |
| 1.6 | 6.51 | 173 | 0.077 | 0.50 | 0.93 |
| 2.0 | 6.55 | 175 | 0.072 | 0.41 | 0.93 |
| 2.4 | 6.69 | 178 | 0.069 | 0.40 | 0.93 |
| 2.8 | 6.76 | 180 | 0.066 | 0.27 | 0.93 |
| **3.2** | **7.07** | **189** | 0.066 | 0.23 | 0.93 |
| 3.6 | 13.61 | 363 | 0.072 | 0.30 | 0.87 |
| 4.0 | 18.18 | 485 | 0.076 | 0.29 | 0.83 |
| 4.8 | 27.55 | 734 | 0.085 | 0.35 | 0.74 |
| 5.6 | 34.83 | 929 | 0.092 | 0.36 | 0.67 |
| 6.4 | 40.61 | 1,083 | 0.100 | 0.45 | 0.61 |

- 모든 점에서 deadline miss는 0이다.
- jitter 3.2 ms까지 DDR3 전송량은 6.36 → 7.07 KiB/추론으로 11 % 는다. 3.6 ms에서 13.61로 두 배가 된다. 추론 요청이 퍼진 폭이 offset 간격 0.8 ms의 4배를 넘어 동시에 섞여 오는 모델이 entry 4개보다 많아지기 때문이다. P3.21의 "필요한 entry = jitter ÷ 0.8 ms 올림"과 같다.
- 최대 응답 시간은 jitter가 작을수록 길다. jitter 0이면 같은 모델 추론 요청이 모두 같은 순간에 도착한다. 편중 시나리오에서 가장 큰 모델(약 240트랙)의 batch가 길어져 1.44 ms가 된다.

### 3.3 Dysta Method 조절값

연산 시간이 바뀌어 P3.11에서 고른 η(1e-4)가 여전히 Dysta Method에 유리한지 확인했다. 후보는 P3.11과 같은 15개(0~10)다.

| η | DDR3 KiB/추론 | 평균 응답 시간 ms | 최대 응답 시간 ms |
|---|---:|---:|---:|
| 0 | 57.0 | 1.319 | 5.82 |
| **1e-4 (지금)** | **57.0** | **1.320** | **5.84** |
| 1e-3~0.05 | 57.1 | 1.316~1.317 | 5.87 |
| 0.1~10 | 57.4~59.2 | 1.332~1.365 | 5.87 |

η에 따른 차이는 DDR3 4 %, 최대 응답 시간 0.05 ms 이하다. η = 0이 최대 응답 시간 0.02 ms 짧지만 비교 결과는 바뀌지 않는다.

### 3.4 논문 A-2 문단 값

| 자리 | 값 | 근거 |
|---|---|---|
| `[J_BOUND]` | 3.2 ms | §3.2, entry 4 × offset 간격 0.8 ms |
| `[NEW_KIB]` | 7.07 | jitter 0~3.2 ms에서 가장 큰 값(3.2 ms) |
| `[NEW_MAX_MS]` | 1.44 | jitter 0~3.2 ms에서 가장 긴 값(jitter 0, 편중 시나리오) |
| `[NEW_SLACK_MS]` | 30.56 | 32 − 1.44 |
| `[DDR_REDUCTION]` | 87.6 | 1 − 7.07 ÷ 57.01 |
| `[LATENCY_REDUCTION]` | 75.4 | 1 − 1.44 ÷ 5.84 |

jitter 0.8 ms 한 점으로 쓰면 6.36 KiB/추론, 0.69 ms, 31.31 ms, −88.8 %, −88.3 %다. 문단이 "jitter 3.2 ms 이하"라고 범위를 말하므로 범위의 가장 나쁜 값을 쓰는 쪽이 맞다.

## 4. 한계

- jitter는 재지 않았다(P3.16). 3.2 ms는 simulation에서 entry 4개가 버티는 한계이고, 실제 jitter가 이 안에 드는지는 모른다. 그래서 "측정한 jitter 범위"라는 표현은 P3.16 측정 뒤에만 쓸 수 있다.
- jitter는 균등분포 폭 하나로 넣었다. 실제 분포의 꼬리가 길면 같은 폭에서도 DDR3가 더 늘 수 있다.
- 입출력은 PCIe 64 B 표본이다. Ethernet 지연은 재지 않았다. 외부 지연 0은 오디오 buffer·Host 전처리를 뺀다는 뜻이고, 링크 지연(왕복 약 0.06 ms)은 응답 시간에 들어 있다.
- 악조건 겹침(모든 입력 spike + control overhead 20 % + DDR3 2.0 GB/s)은 다시 돌리지 않았다. engine의 "모든 입력 spike"는 spike 0 건너뛰기를 끈 dense 연산(2,101 cycle)이다. RTL에서 spike가 모두 1인 입력은 1,205 cycle이라, 01_OVERVIEW.md §5.4의 worst case 25 ms와 P3.21·P3.22의 악조건 값은 보수적이다.
- RTL cycle은 compute_array 단독 값이다. membrane potential 경로(P4.2), cache 교체(P4.3), DMA(P4.4)가 붙으면 정지 cycle이 생길 수 있다.
