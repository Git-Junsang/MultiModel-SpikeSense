# P3.10 보고서: 모델 export와 golden vector

작성일: 2026-10-12. 수정: 2026-10-13, 구현 모델이 L·64 lane으로 바뀌어 다시 만들었다.

## 1. 요약

### 1.1 환경

| 구분 | 조건 |
|---|---|
| Checkpoint | L 40대, `software/weights/L_normal_noaug/<unit>/last.pth` (증강 없음) |
| 구조 | `40→384→256→64→2`, 706뉴런 |
| 양자화 | P2.5 규칙 그대로, [snn_int8.py](../../software/model/snn_int8.py) |
| 형식 | 64 lane slot, ARCH_SPEC.md §6.3 |

### 1.2 결과

| 항목 | 결과 |
|---|---|
| Export | 40모델, slot 256 KiB, DDR3 image 10,485,760 B |
| Golden | 실데이터 80개 + saturation 2개 |
| 검증 | `l64` PASS, `1lane`·`xl` 재검증 PASS |
| 교차 확인 | `golden_l64` 82개가 1 lane `golden`과 배열까지 같음 |
| 정수 경로 AUC | P2.5 결과 그대로, FP32 0.9563 → INT8 0.9554 |

### 1.3 결론

`hardware/data/models_l64/`와 `golden_l64/`를 P4 RTL의 기준 data로 쓴다.

Checkpoint를 L_aug로 바꿀 때는 `--weights`만 바꿔 export와 golden을 다시 만든다. 형식과 RTL은 바뀌지 않는다.

## 2. Export

[model_format_64lane.py](../../software/model/model_format_64lane.py)의 `LaneFormat`이 lane-interleaved 형식을 만든다. 모델 구조와 lane 수를 인자로 받는다. `L64`가 구현 기준이고 `XL`은 비교용이다. 1 lane code와 출력은 바꾸지 않았다.

| 파일 | 크기 |
|---|---:|
| `weights.bin` | 130,176 B |
| `params.bin` | 1,412 B |
| `model.slot.bin` | 256 KiB |
| `entry.hex` | 2,034줄 × 512 bit |
| `params.hex` | 706줄 × 16 bit |
| `models.ddr.bin` | 10,485,760 B |

파일 뜻은 MODEL_MEMORY_LAYOUT.md §5에 있다.

## 3. Golden vector

1 lane과 같은 방식으로 만들었다. 장비마다 test의 첫 정상·이상 segment를 쓰고, 길이는 31 timestep이다. Generator는 checkpoint가 아니라 `model.slot.bin`을 읽는다.

같은 checkpoint라서 layer별 배열은 1 lane golden과 같아야 한다. 82개 NPZ를 비교해 모든 배열과 dtype이 같음을 확인했다. Slot 형식이 바뀌어도 계산 결과는 그대로라는 뜻이다.

| Saturation vector | L1 | L2 | L3 | L4 |
|---|---:|---:|---:|---:|
| 양수 | 9,600 | 7,936 | 1,920 | 54 |
| 음수 | 9,600 | 0 | 0 | 0 |

Saturation test는 weight 127 또는 −128, 입력 127, β·vth 255인 인공 모델이다. 대표 HEX는 `hardware/data/golden_l64/rtl_hex/fan_id01_normal/`이다.

## 4. 검증

[verify_export.py](../../software/model/verify_export.py) `--format l64`가 확인한 항목:

- BIN, HEX, slot, DDR3 image의 크기와 SHA-256
- checkpoint를 다시 양자화한 값과 slot·file 복원값의 일치
- golden 82개 재계산과 bit 일치
- ARCH_SPEC 주소식으로 `fan_id01`의 slot, `entry.hex`, `params.hex`를 직접 확인

마지막 항목은 변환 함수를 쓰지 않는다. 변환과 역변환이 같은 방향으로 틀리는 경우를 잡는다.

```text
PASS l64: 모델 40개, 실데이터 벡터 80개, stress 2개, 포화=[[9600, 7936, 1920, 54], [9600, 0, 0, 0]]
PASS xl: 모델 40개, 실데이터 벡터 80개, stress 2개, 포화=[[19200, 15872, 3968, 58], [19200, 0, 0, 0]]
PASS v1: 모델 40개, 실데이터 벡터 80개, stress 2개, 포화=[[9600, 7936, 1920, 54], [9600, 0, 0, 0]]
```

## 5. XL_aug 결과 (비교용)

2026-10-12에는 XL_aug를 구현 모델로 보고 export했다. 산출물은 `hardware/data/models_xl/`, `golden_xl/`에 남겼다.

| 항목 | 결과 |
|---|---|
| 양자화 범위 | 40대 통과, vth 10~184, β 124~242 |
| 정수 경로 AUC | FP32 0.9559 → INT8 0.9547, −0.0011 |
| L INT8 대비 | −0.0006, 16대 높음, 22대 낮음 |
| membrane potential 포화 | test 129,792 segment에서 0회 |
| L3 membrane potential 최대 | INT16의 71.0 % (L은 52.2 %) |

XL_aug는 2대에서 L보다 크게 낮았다. FP32에서도 낮으므로 원인은 학습이다.

| 장비 | L INT8 | XL_aug FP32 | XL_aug INT8 |
|---|---:|---:|---:|
| ToyConveyor_id02 | 0.921 | 0.773 | 0.751 |
| ToyCar_id05 | 0.816 | 0.666 | 0.671 |

결과: `software/train_result/eval/quant_int8_xl_aug/`. 구현 모델을 L로 바꾼 이유는 ARCH_SPEC.md §2에 있다.
