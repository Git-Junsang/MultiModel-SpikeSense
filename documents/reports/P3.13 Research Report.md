# P3.13 보고서: Host Offset Assignment와 BRAM 배분

작성일: 2026-10-15

P3.12에서 평균 response time은 연산 방식과 입출력 경로로 줄였다. 하지만 scheduler만으로는 DDR3 traffic과 response time을 함께 줄이지 못했다. P3.13은 추론 요청이 오는 시각을 Host가 정하는 Offset Assignment를 넣는다. 그 결과 가속기를 어디까지 단순하게 만들 수 있는지, 남는 BRAM을 weight와 membrane potential에 어떻게 나눌지 본다. 값은 모두 simulation이다. 용어와 배경은 [SCHEDULING_PRIMER.md](<P3.13 Scheduling Primer.md>)에 있다.

### 1.3 결론

1. Offset Assignment와 작은 cache를 함께 쓰면 DDR3 traffic과 response time을 동시에 줄인다. 기존 scheduler는 둘 중 하나만 줄인다.
2. Offset Assignment를 하면 scheduler는 Grouping으로 충분하다. WSPT는 제외하고 SlackBatch는 비교군(scheduler 상한)으로만 쓴다. guard는 쓰지 않는다.
3. Offset Assignment로 weight 재사용이 확보되면, BRAM을 weight cache보다 membrane potential에 주는 쪽이 DDR3 traffic을 더 줄인다. Membrane potential은 12 bit로 저장한다.
4. 필요한 entry 수는 Host jitter가 정한다(대략 jitter ÷ 0.8 ms). Jitter는 환경값이라 재야 한다.
5. 제안 구성은 Host Offset Assignment + 즉시 입출력 + Grouping + offset-order weight cache(entry 2–4) + 남는 BRAM의 12 bit membrane potential + spike 0 건너뛰기다.

### 1.4 한계와 남은 결정

- Jitter를 재지 않았다. 측정 계획은 JITTER_PLAN.md에 있다. Host가 offset 단위로 모아 보내는 방식도 simulation하지 않았다.
- Membrane potential 일부 on-chip은 모든 트랙이 고르게 추론 요청을 낸다고 보고 추론 요청당 평균으로 넣었다. 트랙별로 따로 따지지 않았다.
- spike 2개/cycle, 즉시 입출력, control overhead 203 cycle은 RTL로 확인하지 않은 가정이다. 입출력 지연은 PCIe 표본이고 Ethernet은 재지 않았다.
- 편중 배정에서는 한 모델에 트랙이 240개 안팎 몰려 batch 하나가 1.6 ms다. Offset 간격 0.8 ms보다 길어 최대 response time이 1.55 ms가 된다. 트랙 수에 비례해 offset 간격을 주는 방식은 시험하지 않았다.
- Model-Grouped Offset Assignment와 같은 기법은 웹 검색과 OpenAlex에서 찾지 못했다. IEEE Xplore API는 승인 대기 중이다. 신규성은 검색을 마친 뒤 적는다.
- PROPOSAL, ARCH_SPEC, TASKS에 반영하지 않았다. 반영하려면 사용자 결정이 필요하다.

## 2. Host Offset Assignment

Mic는 쉬지 않고 수음하므로 32 ms frame의 경계를 어디에 둘지는 Host가 정한다. Offset Assignment는 모델 m의 트랙들이 m × 0.8 ms 근처(32 ms ÷ 모델 40개)에 frame 경계를 두게 하는 것이다. 그러면 같은 모델의 추론 요청이 함께 와서, scheduler가 기다리지 않아도 한 batch가 된다.

Host 비용은 트랙마다 첫 frame 경계 시각 하나를 정해 두는 것이다. 계산량은 늘지 않고 deadline(frame 경계 + 32 ms)도 그대로다. 가속기 쪽에서는 cache 교체 규칙만 바뀐다(§3.1). 그림 1([fig41](../../analysis/discards/figure/alignment/fig1_x-time_y-model.png))이 Offset Assignment 전과 후의 도착 시각이다.

## 3. 결과

비교군(Dysta Method 등)은 §3.2에만 나온다. 나머지는 제안 구성에서 한 가지씩 바꾼 결과다. 표의 값은 시나리오 6개를 합친 값이다.

### 3.1 Offset Assignment × cache (표 1)

Grouping 고정, jitter 0.8 ms.

| Offset Assignment | cache | BRAM tile | DDR3 KiB/추론 | MB/s | 평균 ms | 최대 ms |
|---|---|---:|---:|---:|---:|---:|
| 끔 | 없음 | 30 | 54.0 | 1,438 | 2.06 | 8.8 |
| 끔 | LRU 10 | 291 | 52.0 | 1,386 | 1.63 | 7.3 |
| 끔 | offset-order 10 | 291 | 38.2 | 1,018 | 1.53 | 7.2 |
| 켬 | 없음 | 30 | 50.2 | 1,336 | 0.25 | 1.3 |
| 켬 | LRU 2·4·10 | 59–291 | 8.9 | 238 | 0.18 | 1.6 |
| 켬 | offset-order 2 | 59 | 8.9 | 238 | 0.18 | 1.6 |
| 켬 | offset-order 4 | 117 | 8.6 | 229 | 0.18 | 1.6 |
| 켬 | offset-order 10 | 291 | 7.6 | 203 | 0.18 | 1.6 |

Offset Assignment만 하면 jitter 때문에 한 모델의 추론 요청이 따로따로 처리되고, cache가 없어 매번 다시 적재한다. Cache만 있으면 모델 40개가 섞여 와서 entry 10개로 못 버틴다. 둘을 함께 써야 준다.

offset-order 교체는 다음에 가장 늦게 쓸 모델을 내보낸다. Offset Assignment 상태에서는 그 모델이 방금 처리한 모델이다. 그래서 entry 중 1개만 돌고 나머지는 같은 모델을 계속 들고 있어, LRU보다 적재가 적다. FPGA는 Host가 시작할 때 써 준 모델별 offset 번호 표로 내보낼 entry를 고른다.

### 3.4 악조건 (표 3)

| 설계 | 기준 | 꼬리 +700 µs | control overhead +20% | DDR3 2.0 GB/s | 모든 입력 spike(dense) |
|---|---|---|---|---|---|
| 제안 | 0 / 1.6 | 0 / 3.0 | 0 / 1.9 | 0 / 1.2 | 0 / 9.2 |
| Offset Assignment만 끈 같은 hardware | 0 / 7.3 | 0 / 8.7 | 0 / 9.3 | 0 / 7.7 | 0 / 23.1 |

칸은 deadline miss 수 / 최대 response time(ms)이다. 1,024트랙의 deadline 보장은 worst case 계산(추론 요청 1,024개 동시 도착, dense 23 ms < 32 ms)에서 나온다. guard는 이 조건에서 개입하지 않아 쓰지 않는다. 동작과 측정은 GUARD.md에 따로 남겼다.

### 3.5 Jitter × entry (그림 3)

offset-order 교체, seed 10.

| entry \ jitter | 0~0.8 ms | 1.6 ms | 3.2 ms | 6.4 ms |
|---|---:|---:|---:|---:|
| 2 | 8.9 | 10.4 | 54.7 | 74.8 |
| 4 | 8.6 | 8.7 | 9.3 | 42.6 |
| 10 | 7.6 | 7.7 | 8.0 | 8.6 |

DDR3 KiB/추론이다. 늦은 추론 요청이 아직 올 수 있는 모델은 지난 jitter 시간 안에 offset이 지나간 모델들이다. 그래서 필요한 entry ≈ jitter ÷ 0.8 ms다. Entry가 모자라면 DDR3 traffic이 최대 8배로 뛰고, 넉넉하면 조금 는다.

| 패턴 | DDR3 KiB/추론 | MB/s | 최대 ms |
|---|---:|---:|---:|
| 무작위 offset | 80.6 | 2,641 | 1.1 |
| 동시 도착 | 7.5 | 246 | 7.3 |
| 고르게 나눈 offset | 81.6 | 2,672 | 0.8 |
| Model-Grouped Offset Assignment | 7.5 | 246 | 1.6 |
| Offset Assignment + 교대(30% 합류, 30% 이탈) | 9.6 | 219 | 0.6 |
| Offset Assignment + 지연 1% | 8.6 | 281 | 17.3 |
| Offset Assignment + 지연 5% | 12.8 | 420 | 17.4 |

제안 구성(entry 4), 균등·편중 배정 합산. 고르게 나눈 offset은 CAN offset 배정처럼 offset을 고르게 나누되 모델을 보지 않는다. 결과는 무작위와 같다. 효과는 offset을 주는 데서가 아니라 같은 모델을 모으는 데서 나온다. 지연 패턴의 최대 17 ms는 늦게 도착한 추론 요청 자체가 최대 16 ms 늦은 탓이다.

### 3.7 트랙 수 (그림 5)

동시 도착(synchronized)의 최대 response time ms.

| 트랙 | dense | spike 1개/cycle | spike 2개/cycle | dense worst case 계산 |
|---:|---:|---:|---:|---:|
| 1,024 | 23.0 | 9.4 | 7.0 | 23.2 |
| 1,408 | 31.6 | 12.8 | 9.6 | 31.8 |
| 1,536 | 과부하 | 14.0 | 10.5 | 34.7 |

Offset Assignment는 한계를 바꾸지 않는다. Offset Assignment를 켜도 dense 1,536트랙은 과부하다. 한계는 compute array이고 spike 0 건너뛰기가 여유를 만든다.

## 4. Membrane potential 저장 bit

Membrane potential은 16 bit로 계산하고, DDR3(또는 BRAM)에 쓸 때만 bit를 줄인다. 40대 DCASE test 세트에서 INT8 정수 모델과 비교했다.

| 저장 형식 | 평균 AUC | 기준 대비 | 0.01 넘게 떨어진 장비 | AUC 0.9 이상 | membrane potential 전송 KiB/추론 |
|---|---:|---|---:|---:|---:|
| 16 bit(기준) | 0.9554 | | | 35대 | 2.76 |
| 12 bit(±2,048로 포화) | 0.9554 | 40대 모두 판정이 같음 | 0 | 35대 | 2.07 |
| 10 bit | 0.9552 | −0.0002 | 2 | 35대 | 1.72 |
| 8 bit(그대로 포화) | 0.9454 | −0.0099 | 다수, 최악 −0.17 | 32대 | 1.38 |
| 8 bit(아래 2 bit 버림) | 0.9545 | −0.0008 | 4, 최악 −0.020 | 35대 | 1.38 |

12 bit는 위쪽 범위만 줄여 정밀도가 그대로다. 12 bit를 기준으로 쓴다.

## 5. BRAM 배분: weight entry × on-chip membrane potential

BRAM 365 tile에서 XDMA 20.5, 예약 25.5, 준비 buffer 4 tile을 빼고 남은 공간을 weight entry(1개 29 tile)와 membrane potential이 나눠 쓴다. 남는 BRAM에 membrane potential을 둘 수 있는 만큼 on-chip에 두고, 나머지 트랙은 DDR3에 둔다.

| entry | on-chip 트랙 16 / 12 / 8 bit | DDR3 KiB/추론(12 bit), jitter 0.8 / 1.6 / 3.2 ms |
|---:|---|---|
| 2 | 736 / 976 / 1,024 | **6.27** / 7.77 / 52.5 |
| 3 | 656 / 864 / 1,024 | 6.33 / **6.50** / 23.8 |
| 4 | 576 / 768 / 1,024 | 6.36 / 6.51 / 7.08 |
| 6 | 400 / 528 / 816 | 6.51 / 6.63 / **6.92** |
| 10 | 64 / 80 / 128 | 6.77 / 6.84 / 7.11 |

굵게 = 그 jitter에서 최소. Entry를 줄이면 weight 적재가 늘지만, Offset Assignment로 weight 재사용이 높아 그 증가가 작다. 그래서 membrane potential을 on-chip에 두는 쪽이 이긴다. Jitter 0.8 ms에서 entry 10 → 2로 바꾸면 weight는 +1.3, membrane potential은 −1.8 KiB/추론이다. 12 bit에 entry 4면 표 1의 같은 구성(16 bit, membrane potential 전부 DDR3) 8.6 KiB/추론보다 26% 적다.

자주 바뀌는 state를 on-chip에 두고 큰 weight를 off-chip에 두는 것은 단일 network SNN에서 이미 쓰인다(A18 Cheung 등 ICANN 2012, sPyNNaker 2018). Membrane potential과 weight가 on-chip 메모리를 두고 다툰다는 분석도 있다(A16 Sharma 등 ISLPED 2022). 이번 결과는 다중 모델에서도 같은 원칙이 맞으려면 offset 배정으로 weight 재사용을 확보하고, jitter에 맞는 최소 entry를 남겨야 한다는 것이다.
