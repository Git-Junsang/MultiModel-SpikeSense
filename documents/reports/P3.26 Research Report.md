# P3.26 보고서: Host 처리 지연을 모델 그룹 지연과 추론 요청별 지연으로 나눈 재실험

작성일: 2026-10-18

P3.25 검토(아스트라6)의 지적에 따라 simulator의 Host 처리 지연 모델, cache 예측식, drop 규칙을 고쳤다. 그 뒤 최종 비교, cache 정책 비교, entry 수 실험, deadline 분석을 다시 했다. 시간 기준과 jitter 정의([P3.25 보고서](<P3.25 Research Report.md>) §1.1 D1~D10)는 바꾸지 않았다. P3.25 결과는 "Host 처리 지연을 추론 요청마다 0~J로 둔 합성 실험"으로 남긴다.

수치는 따로 적지 않으면 simulation 결과다. Host 처리 지연은 개발 서버(sub1, Xeon W-2255, Python)에서 잰 Host 처리 지연 측정값을 재생했으므로 최종 Host(라즈베리파이 5급) 근거가 아니다.

## 1. 요약

**환경.** L·64-lane @100 MHz, 1,024트랙, 모델 40개, rtl67, DDR3 3,015 MB/s, 남는 BRAM에 12 bit membrane potential, Model-Grouped Offset Assignment offset, Grouping, 즉시 송신, 시나리오 6개 × seed 30이다. Host 처리 지연은 Xeon에서 잰 모델 그룹 지연에 추론 요청별 지연 j ~ Uniform(0, J)를 더했고 J는 0·0.8·3.2 ms다. 측정 조건은 CPU 고정·부하 없음(모델 그룹 지연 최대 8.75 ms)과 CPU 고정 없음·부하 없음(최대 31.1 ms)이다. 같은 트랙의 이전 추론 요청이 끝나기 전에 온 추론 요청은 버린다.

**실험·결과.** CPU 고정 조건에서 제안의 DDR3는 J ≤ 0.8 ms일 때 6.37–6.38 KiB/추론이다. P3.25와 같고 Dysta Method보다 88.7% 적다. J = 3.2 ms에서는 모델 그룹끼리 겹쳐 12.37 KiB/추론으로 늘고 감소폭은 78.9%다. 최대 response time은 Host 처리 지연 꼬리가 정해 방법 사이 차이가 4.8–9.6%로 줄었다. 준비 완료 뒤 최대(링크 + FPGA + 링크)는 제안 0.77–1.75 ms, Dysta Method 6.13–8.57 ms다. Cache 예측식은 모델 그룹 지연을 알아야 한다. J = 3.2 ms, entry 4에서 모델 그룹 지연을 아는 PNU-Count는 12.37 KiB/추론(Oracle MIN 11.04)이고 무시한 P3.25 식은 22.67이다. 필요한 entry 수는 J에 따라 다르다(CPU 고정 조건에서 J ≤ 0.8 ms면 2, 1.6 ms면 3, 3.2 ms면 6). 최종 비교, cache 정책 비교, entry 수 실험에서 drop은 0이었다. 조건부 response time은 CPU 고정 조건에서 19.9–26.6 ms로 32 ms 안이고, 고정 없이 쉬는 조건은 Host 처리 지연만 31.1 ms라 넘는다. adversarial search에서 CPU 고정 조건은 miss·drop이 없었고 response time 최대는 11.0–17.9 ms였다. 다만 즉시 송신은 한 모델·주기 안에서 weight를 여러 번(J = 3.2 ms에서 최대 24번) 읽었다. 모아 보내기도 packet 사이가 1 ms면 7–10번 읽었다.

**결론.**

1. Offset Assignment의 DDR3 이득은 Host 처리 지연이 모델 그룹째 흔들려도 유지된다. 한 모델 그룹이 함께 움직여 같은 batch에 들어가기 때문이다.
2. 모델 그룹 지연이 주기마다 바뀌면 cache 예측식에 넣어야 한다. Jitter만 보는 P3.25 식은 J = 3.2 ms에서 83% 더 적재한다.
3. Response time은 Host 처리 지연과 그 뒤로 나눠 보고한다. 방법 비교는 뒤쪽으로 하고, 최대 response time은 Host 꼬리가 정한다고 적는다.
4. Entry 4와 PNU-Count는 확정하지 않는다. 최종 Host의 추론 요청별 퍼짐이 0.8 ms 이하면 entry 2로 충분하고, PNU-Timeout과 PNU-Count의 차이도 0.3%다. 3.2 ms면 entry 6이 필요하다. 그때 entry 4에서는 PNU-Count가 PNU-Timeout보다 26% 적다(entry 6에서는 비교하지 않았다).
5. Hard deadline 보장은 주장하지 않는다. 조건부 response time은 측정 최대를 상한 자리에 넣은 계산이고, 그 계산의 단일 적재 가정이 즉시 송신과 packet 사이가 긴 모아 보내기에서 깨진다. adversarial search에서도 넘지 않았다는 것은 관측일 뿐이다.

**한계.** Host 처리 지연은 Xeon·Python 측정이다. 이 측정은 모델당 25.6트랙을 offset 순서로 계산한 Host에서 쟀다. 편중 시나리오(skewed·skewed-synchronized)의 큰 모델 그룹과 global alignment·unaligned 방식의 실제 Host 처리 지연은 이와 다를 수 있는데, 비교군에도 같은 (모델, 주기) 지연을 넣었다. 링크는 PCIe 64 B 표본이다.

## 2. 바꾼 것

### 2.1 Host 처리 지연의 두 부분

```text
t_ready(트랙 i, 주기 k) = t_host(i, k) + G(m, k) + j(i, k)
  G(m, k)  모델 m 묶음 지연. 모델·주기마다 하나이고 주기마다 바뀐다(Xeon 측정 재생)
  j(i, k)  추론 요청별 지연, 0 ≤ j < J. jitter J는 이 퍼짐이다(P3.25 D6 그대로)
```

- 모델 그룹 전체가 5 ms 늦으면 jitter는 0이지만 추론 요청은 O_m + 5 ms에 온다. P3.25는 G를 0으로 두고 j만 넣었다.
- 같은 트랙의 다음 추론 요청은 32 ms − (G 최대 − G 최소) − J까지 일찍 올 수 있다. P3.25의 32 ms − J는 G의 변화를 빠뜨렸다.
- Host는 트랙의 frame을 차례로 처리한다. 같은 트랙의 준비 시각이 앞 주기보다 이르면 앞 주기 시각으로 맞춘다.
- 환경 키는 `group_trace`(G 표)와 `jitter_dist`·`jitter_ms`(j)다. 옛 환경 파일은 `group_trace = ""`로 읽어 옛 결과가 그대로 나온다.

### 2.2 Cache 예측(PNU)

P3.25 식은 nominal offset 뒤 경과 시간 el만 본다. el이 τ(추론 요청별 지연 최대)를 넘으면 이번 주기가 끝났다고 보고 다음 사용을 다음 주기로 미룬다. 모델 그룹 전체가 늦으면 이 판단이 틀려 곧 올 모델을 내보낸다.

고친 식은 모델 그룹 지연 분포 G(측정 표의 앞 절반)를 알고, 이번 주기 첫 추론 요청이 오기 전과 뒤를 나눈다.

| 상태                                                   | 다음 사용                         |
| ------------------------------------------------------ | --------------------------------- |
| 이번 주기 첫 추론 요청 전, el < τ_G                        | 지금 + δ_G(el, 1)                |
| 첫 추론 요청이 a1에 온 뒤, 남은 추론 요청 r > 0, 지금 − a1 < τ | 지금 + δ(지금 − a1, r)           |
| 그 밖                                                  | 다음 주기 offset + E[G] + δ(0, n) |

- δ_G(el, 1)은 G > el일 때 G − el의 기대값이고, τ_G는 G 분포의 최대다. 첫 추론 요청 뒤에는 a1을 모델 그룹 시작으로 보고 P3.25 식을 쓴다.
- 예상 추론 요청 수 r·n은 P3.25와 같다(packet byte 12–15). PNU-Timeout은 r = 1이다.
- hardware에는 모델마다 이번 주기 첫 도착 시각 하나(40 × 32 bit)와 δ_G 표(1차원)가 더 든다. 추정이고 RTL은 없다. 이 보고서는 δ를 정확한 조건부 기대값으로 계산했다.
- `storage_attrs = {model_group_delay_aware = false}`는 P3.25 식이다(비교용).

### 2.3 Drop 규칙

06 §4.3의 ERR_CODE 5를 넣었다. 같은 트랙의 이전 추론 요청이 FPGA 연산을 끝내기 전에 새 추론 요청이 도착하면 새 추론 요청을 버린다. 결과가 없으므로 Host는 deadline miss로 센다. 표에는 늦게 끝난 추론 요청(miss − drop)과 drop을 나눠 쓴다.

Drop이 나면 앞 추론 요청은 이미 늦다. 다음 추론 요청은 다음 frame의 t_host 뒤에 도착하고, 그 t_host는 앞 frame보다 32 ms 늦다. 앞 추론 요청이 그때까지 끝나지 않았다면 response time이 32 ms를 넘은 것이다. 환경 키는 `drop_busy`이고, 옛 환경 파일은 false로 읽는다.

Drop 규칙의 첫 판에는 버그가 두 개 있었다. 첫째, 버린 추론 요청을 처리한 추론 요청으로 표시하지 않았다. 그래서 Grouping이 가장 오래된 추론 요청으로 버린 추론 요청을 계속 골라 추론 요청 없는 batch를 시간이 흐르지 않은 채 반복했다. 둘째, queue가 빈 채로 다음 도착까지 시간을 넘겼는데 그 도착을 버리면 빈 queue로 scheduler를 불렀다. Drop이 한 번도 없던 최종 비교, cache 정책 비교, entry 수 실험은 영향을 받지 않았다. adversarial search는 drop이 나는 지연 꼴에서 멈춰 sub1에서 메모리를 약 109 GB까지 썼다. 멈춘 뒤 두 곳을 고쳐 다시 돌렸고, 시험 3f·3g가 같은 경우를 막는다.

P3.25 결과도 그대로 나온다. p325_final_compare·p325_cache_policy의 점 5개 × 시나리오 uniform·skewed를 다시 돌리면 weight B, 최대·평균 response time, 적재 수가 runs CSV와 같다(차이 5 × 10⁻¹⁶ 이하).

- Drop은 모든 점에서 0이다. 늦게 끝난 추론 요청은 CPU 고정 없음 조건의 DeepRT Method 계열에서만 났다. 측정 구간 추론 요청 9,582,910개 중 2,077–3,611개(0.02–0.04%)이고, window 14.9 ms 대기에 Host 처리 지연 꼬리가 더해진 결과다.

- 준비 완료 뒤 최대는 제안이 Dysta Method보다 71.5–91.0%(CPU 고정), 85.2–93.9%(고정 없음) 짧다. Dysta Method는 Host 꼬리가 클수록 이 값이 커진다(6.13 → 11.78 ms). 늦은 모델 그룹이 다른 모델 추론 요청과 겹치기 때문으로 보인다(따로 확인하지 않았다).
- 제안의 준비 완료 뒤 최대는 J가 클수록 짧다(1.75 → 0.77 ms). 편중 시나리오의 큰 모델(약 240트랙)이 한꺼번에 오면 마지막 추론 요청이 batch 연산을 기다린다. 모델 그룹이 퍼져 오면 batch가 작아져 이 대기가 준다. 대신 적재가 는다.
- 측정과 같은 균등 배정(uniform)만 보면 제안은 5.27·5.28·12.91 KiB/추론, 준비 완료 뒤 최대 0.40·0.24·0.38 ms다. Dysta Method는 89.1–89.3 KiB/추론, 6.13–6.84 ms다.

## 5. 한계

- Host 처리 지연은 Xeon W-2255·Python·계산 thread 1개로 쟀다. 라즈베리파이 5에서는 계산이 더 느리고 꼬리 모양도 다를 수 있다.
- Host 처리 지연 측정은 모델당 25.6트랙을 offset 순서로 계산한 Host에서 쟀다. 편중 시나리오(skewed·skewed-synchronized)의 큰 모델(약 240트랙)은 Host 계산이 더 길다. Global alignment는 1,024트랙을 한꺼번에 계산하므로 Host 처리 지연이 훨씬 클 수 있고, unaligned는 트랙마다 따로 깨어난다. 모든 방법에 같은 (모델, 주기) 지연을 넣은 것은 FPGA 쪽만 비교하려는 단순화다.
- 측정한 추론 요청별 퍼짐은 측정 방식 때문에 0이다(P3.25 §4.11). j는 합성이다.
- 링크는 PCIe 64 B 표본이다. Ethernet packet 분할은 adversarial의 모아 보내기 변형에만 넣었다.
- PNU의 G 분포는 모델 40개를 합친 하나다. δ_G 표(LUT)의 오차는 재지 않았다.
- 교차점(p325_crossover), 확장성, mic–Host 지연 실험은 다시 돌리지 않았다.
