## 1. 요약

P1.4에서 학습한 40대 모델(`40→384→256→64→2`)을 INT8로 바꾸는 방식을 정하고, FP32 대비 정확도 저하를 쟀다.
후보 7개를 40대 전부에 돌려 본 결과 후보 사이의 평균 AUC 차이가 0.0006 이내였다. 그래서 **하드웨어가 가장 단순한 선행 방식(층별 대칭 INT8, β Q0.8, 누설 내림)을 채택**하고, 선행 RTL에 없던 **16 bit 막전위 포화 가산**만 추가했다.

| 항목 | 결과 |
|---|---|
| 채택 방식 | 선행 `export_weights.py` 방식 + 16 bit 포화 가산 (§3, §4) |
| 파일 단위 AUC 평균 | FP32 0.9563 → INT8 **0.9554** (−0.0009) |
| 장비별 AUC 변화 | −0.0116 (ToyCar_id07) ~ +0.0090 (valve_id00). 22대 하락, 14대 상승, 4대 동일 |
| AUC 0.9 이상 장비 | FP32 35대 → INT8 35대. INT8 최저 0.8160 (ToyCar_id05) |
| 세그먼트 판정 일치 | 전체 129,792개 중 96.5%. 장비 평균 96.9%, 최저 89.8% (ToyCar_id05) |
| 16 bit 넘침 | 0회 (4개 층 모두, test 세트 기준). 막전위 최대는 L3 17,093 = INT16의 52.2% |
| 정수 규칙 확인 | 같은 코드에 선행 INT8 가중치를 넣으면 선행 골든 벡터와 **비트 단위 일치** (2/2) |
| 모델당 추가 파라미터 | β 706 B + 임계값 706 B = **1,412 B**. 40대 56,480 B = 55.156 KiB (§6.2) |

코드: `software/model_develop/snn_int8.py`(양자화·정수 순전파), `software/analysis_develop/compare_quant.py`(40대 비교), `software/analysis_develop/quant_variants.py`(후보 비교). 결과: `software/analysis_develop/quant_int8/`.

## 2. 목적과 제약

### 2.1 목적

- 40대 모델마다 INT8 변환 후 정확도와 저하폭을 기록한다 (TASKS.md P1.5 완료 조건).
- P1.6(가중치 내보내기)과 P1.7(비트 정확 골든 참조), P3.1(연산기 RTL)이 공통으로 따를 **정수 규칙**을 하나로 정한다.
- P1.4에서 남긴 확인 항목인 "L3 막전위 여유 약 2배가 실제로 충분한가"를 포화 발생 횟수로 확인한다.

### 2.2 제약

| 제약 | 근거 |
|---|---|
| 가중치는 INT8, 모델당 130,176 B | 중간보고·PROPOSAL의 전송량·BRAM 예산 계산 기준 |
| 막전위는 16 bit | `512 × 706 × 2 B = 706 KiB`. 폭을 늘리면 BRAM 예산이 무너진다 (P1.4 결론) |
| 뉴런 규칙은 `plift_core.v`와 같다 | 누설 → 적분 → 발화 → soft reset. 선행 RTL 재사용 기준 (AGENTS.md) |
| 재학습 없이 변환만 한다 | 양자화 인식 학습(QAT)은 저하폭이 문제가 될 때 검토한다. 이번 결과로는 필요 없었다 |

### 2.3 평가 조건

- 데이터: P1.4와 같은 test 평가 세트(`train.prepare`의 supervised 분할, 학습과 같은 seed). 40대 세그먼트 129,792개, 파일 12,671개.
- FP32 기준: `snn_numpy.forward`. P0.8에서 PyTorch와 판정·AUC가 일치함을 확인한 구현이다. 이번 FP32 AUC 평균도 P1.4 `results.csv`와 같은 0.9563이다.
- INT8 점수: 출력 막전위 시간 평균에 출력층 스케일을 곱해 FP 단위로 되돌린 뒤 FP와 같은 식(softmax의 P(이상), 파일 단위 평균)으로 AUC를 계산한다. 판정(argmax)은 정수 그대로 비교하며, 스케일을 곱해도 판정이 바뀌지 않음을 코드에서 확인했다.
- 개발 서버 CPU(12스레드)에서 실행했다. 정수 행렬곱은 float64 BLAS로 계산했다. 피연산자가 정수이고 누산값이 2^53보다 훨씬 작아 정수 연산과 결과가 같다.

## 3. 방식 결정

### 3.1 후보

선행 방식을 기준(A)으로 두고, 하드웨어 비용이 조금 더 드는 대신 정밀도를 올릴 수 있는 세 가지를 조합했다.

| 기호 | 의미 | 하드웨어 비용 |
|---|---|---|
| A | 층별 대칭 스케일 `s = max|W| / 127` (선행 방식) | 기준 |
| R | 뉴런별(출력 행별) 스케일. 출력층만 층별 | 곱셈기는 늘지 않는다. 뉴런별 스케일은 그 뉴런의 막전위·임계값 단위로 흡수된다. 대신 임계값 정수가 커진다 |
| prior / sat | 16 bit 넘침 시 되감김(선행 RTL) / 포화 | 포화는 비교기와 선택기 정도 |
| rnd | 누설 `(β·mem) >> 8`을 내림 대신 반올림 | 뉴런당 가산기 1개 |
| b12 | β를 Q0.8 대신 Q0.12 | β 저장 1.5배, 곱셈 폭 증가 |

R에서 출력층만 층별로 둔 이유는 판정이 두 출력 뉴런 막전위의 argmax이기 때문이다. 두 뉴런의 단위가 다르면 비교가 성립하지 않는다.

모든 후보에서 16 bit 넘침은 0회였다. 그래서 A_prior와 A_sat의 결과가 같다.

### 3.3 판단

1. **뉴런별 스케일(R)은 기각한다.** AUC 이득은 +0.0003~0.0005뿐이다. 반면 가중치가 아주 작은 뉴런에서 임계값 정수가 최대 135,467까지 커진다. 임계값을 INT8에 담을 수 없고, 막전위 최대도 27,047(INT16의 82.5%)로 올라 여유가 거의 없어진다. 최저 판정 일치율도 오히려 낮다(86.9%).
2. **β Q0.12(b12)는 기각한다.** 학습된 β는 0.52~0.955 범위다. Q0.8의 간격 1/256은 β가 가장 큰 0.955에서도 `1 − β = 0.045`의 약 9%라 시간상수 오차가 작다. 측정상 이득이 없다(같은 누설 방식끼리 비교해 AUC +0.0002 이내).
3. **누설 반올림(rnd)은 넣지 않는다.** 판정 일치율은 0.2%p 오르지만 AUC는 그대로다(−0.0001~+0.0001). 내림을 유지하면 선행 `plift_core.v`의 누설 경로를 바꾸지 않아도 된다. 내림 누설은 음수 막전위가 0이 아니라 −1로 수렴하는 편향이 있으나, 측정상 정확도에 영향이 보이지 않았다.
4. **포화 가산은 넣는다.** test 세트에서는 넘침이 0회였다. 그러나 이론상 층 2 전류만으로 INT16을 넘을 수 있다(§4.2). 선행 RTL처럼 되감기면 큰 양수 막전위가 음수로 뒤집혀 발화가 멈추고, 이는 입력 분포가 바뀌는 실환경에서 조용한 오판정이 된다. 포화는 비용이 작고 값을 한계에 붙잡을 뿐 부호를 뒤집지 않는다.

결론: **A_sat**. 하드웨어 최적화를 우선해 선행 규칙을 그대로 두고 안전장치만 더했다.

## 4. 채택한 정수 규칙

### 4.1 변환식

| 대상 | 식 | 형식 | 40대 범위 |
|---|---|---|---|
| 입력 | `x_q = clip(round(mel × 127), 0, 127)` | 0~127 (부호 없는 7 bit, INT8에 담김) | — |
| 가중치 | `s_l = max|W_l| / 127`, `W_q = clip(round(W / s_l), −128, 127)` | INT8, 층별 대칭 | — |
| 누설 계수 | `β_q = clip(round(β × 256), 0, 255)` | Q0.8 uint8 | L1 134~243, L2 135~245, L3 144~243, L4 198~237 |
| 임계값 | `vth_q = round(thr / s_l)` | uint8 (1~255 밖이면 변환 오류) | L1 8~110, L2 10~116, L3 7~118, L4 38~57 |
| 출력 스케일 | `s_4` | FP (Host 보관) | — |

임계값은 모두 127 이하라 선행처럼 부호 없는 8 bit로 두고 16 bit로 0 확장해 비교하면 된다.

### 4.2 타임스텝마다 뉴런 갱신

```text
층 1 전류   cur = (Σ_j x_q[j] · W_q[i, j]) >> 7          # 누산 후 산술 시프트(내림)
층 2~4 전류 cur = Σ_j spike[j] · W_q[i, j]                # 스파이크 조건부 누산
누설·적분   mem = sat16( ((β_q · mem) >> 8) + cur )       # 누설 내림, [-32768, 32767] 포화
발화        spike = (mem >= vth_q)
soft reset  mem = mem − spike · vth_q
판정        출력층 막전위 31스텝 평균의 argmax (0 = 정상, 1 = 이상)
```

`>> 7`은 입력에 곱한 127배를 근사적으로 되돌려, 층 1 전류를 층 2~4와 같은 "가중치 정수" 단위로 맞춘다(선행 `L1_SHIFT = 7`).

### 4.3 비트 폭 (RTL에 넘길 사항)

| 신호 | 이론 최대 |값| | 측정 최대 |값| | 필요 폭 |
|---|---|---|---|
| 층 1 누산기 (시프트 전) | 40 × 127 × 128 = 650,240 | 72,916 | 부호 포함 21 bit |
| 층 1 전류 (시프트 후) | 650,240 >> 7 = 5,080 | — | 14 bit |
| 층 2 전류 | 384 × 128 = 49,152 | 1,246 | **17 bit** (INT16 초과) |
| 층 3 전류 | 256 × 128 = 32,768 | 1,504 | 16 bit (−32,768~+32,512) |
| 층 4 전류 | 64 × 128 = 8,192 | 530 | 14 bit |
| 누설 후 막전위 `(β_q · mem) >> 8` | 32,768 미만 (β_q ≤ 255) | — | 16 bit |
| 누설 + 전류 합 (포화 전) | 32,768 + 49,152 | L3 17,093 | 18 bit에서 더한 뒤 16 bit로 포화 |

선행 `plift_core.v`는 전류 입력과 합이 16 bit라 이 규칙을 그대로 담지 못한다. P3.1에서 전류 입력을 17 bit 이상으로 넓히고, 합을 18 bit로 계산한 뒤 포화시키도록 확장한다. 누설·발화·soft reset 경로는 그대로 쓴다. 누산기는 DSP48(48 bit 누산) 또는 스파이크 조건부 가산기 어느 쪽이든 21 bit 이상이면 된다.

### 4.4 정수 규칙 확인

`compare_quant.py`는 40대 비교에 앞서 같은 `snn_int8.forward`에 선행 SpikeSense-Edge의 INT8 가중치 HEX(`40→128→32→2`)를 넣고, 선행 골든 벡터(출력 막전위·스파이크)와 비교한다. 정상·이상 입력 2개 모두 비트 단위로 일치했다(`quant_int8/prior.txt`). 선행 골든 입력에는 넘침이 없어서 포화를 추가해도 결과가 같다. 이로써 이 코드의 누설·시프트·비교·리셋 순서가 선행 RTL 검증에 쓰인 규칙과 같음을 확인했다. 새 모델에 대한 RTL 비트 일치는 P1.7 골든 벡터와 P3.1 xsim에서 확인한다.

## 6. 다음 단계로 넘길 사항

### 6.1 P1.6 내보내기

- 가중치 파일은 모델당 INT8 130,176 B로 그대로다.
- 모델마다 β_q 706 B와 vth_q 706 B를 함께 내보낸다. 출력 스케일 `s_4`는 Host의 AUC 점수 계산에만 필요하므로 가속기 메모리에 두지 않는다.

### 6.2 BRAM·DDR3 예산 (결정 필요)

β·임계값은 모델당 1,412 B, 40대 합계 56,480 B = 55.156 KiB다. PROPOSAL은 127.125 KiB가 가중치만의 크기이며 추가 파라미터는 저장 예산에 따로 포함한다고 적고 있다. 이 55.156 KiB를 온칩에 상주시킬지(기타 100 KiB에 넣을지, 별도 항목으로 뺄지), 가중치처럼 DDR3에서 모델과 함께 전송할지(모델 전체 전송 130,176 → 131,588 B, +1.08%)는 P1.6 레이아웃을 정할 때 결정하고 PROPOSAL에 반영한다. PROPOSAL은 사용자 확인 후 수정한다.

### 6.3 P1.7·P3.1

- 골든 참조는 `snn_int8.forward`를 기준으로, 층별 전류·막전위·스파이크를 타임스텝마다 저장하도록 확장한다.
- `plift_core.v` 확장 항목은 §4.3에 적었다(전류 17 bit 이상, 18 bit 합, 16 bit 포화).
- 포화 경로는 test 데이터로는 한 번도 동작하지 않았다. P1.7에서 넘침을 일으키는 인위적 입력이나 가중치를 따로 만들어 포화 동작을 검증한다.

## 7. 한계

- 결과는 P1.4와 같은 test 세트에서 측정했다. 40대 구성은 이 세트의 결과를 보고 장비 1대를 교체한 것이므로(P1.4 결과 문서), 절대 AUC는 "고른 뒤의 성능"이다. FP32와 INT8의 **차이**는 같은 세트, 같은 모델에서 비교한 값이라 이 선택 편향의 영향을 받지 않는다.
- 후보 비교(§3)도 같은 test 세트로 했다. 후보 사이 차이가 0.0006 이내로 작아 과적합에 따른 선택은 아니지만, 별도 검증 세트로 고른 것은 아니다.
- 넘침 0회는 이 데이터에서의 측정이다. 최악 입력에 대한 보장은 포화 가산으로 대신한다.
- 입력 양자화(`round(mel × 127)`)는 Host 전처리가 mel을 같은 방식([0, 1] 정규화)으로 만든다는 전제다. 실시간 마이크 입력의 정규화 방식은 P3.8에서 정한다.
