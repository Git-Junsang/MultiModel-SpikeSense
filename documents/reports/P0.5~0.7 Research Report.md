## 1. 요약

Phase 0의 보드 시험 세 항목을 2026-09-23에 수행했다. 목표는 **문서로만 정리해 둔 보드 제약이 실물에서 동작하는지 확인하고, 가속기가 쓸 두 데이터 경로(DDR3, PCIe)를 실제로 열어 두는 것**이었다.

| Task | 내용 | 결과 |
|---|---|---|
| P0.5 | LED 점멸 설계로 비트스트림 생성·다운로드 | 완료. 보드를 직접 볼 수 없어 JTAG(VIO)로 연산 결과·클럭·LED 구동값을 확인 |
| P0.6 | MIG DDR3 예제 설계, 보드 메모리 시험 | 완료. 캘리브레이션 성공, 360초 동안 비교 오류 0 |
| P0.7 | PCIe Gen2 ×2 XDMA로 Host 링크·DMA 왕복 | 완료. `LnkSta: 5 GT/s ×2`, 64 KiB DMA 왕복 10/10 일치 |

세 항목 모두 완료했고, 이로써 **Phase 0의 완료 판정(보드·DDR3·PCIe·학습 서버·시뮬레이터가 모두 동작)** 가운데 보드 쪽 세 요소를 만족했다.

이 단계에서 얻은 가장 중요한 부산물은 **PCIe PERST# 핀을 L16으로 확정**한 것이다. 이 핀은 보드 매뉴얼에 번호가 없어 P0.4에서 미확인으로 남겨 두었던 항목이며, 연결하지 않으면 링크가 올라와도 DMA를 쓸 수 없다는 것이 이번에 드러났다(§5.3).

이 리포트의 모든 수치는 **실제로 실행해 얻은 값**이다. DDR3 실효 대역폭, PCIe 지연·지터, 최종 자원 예산은 이 단계의 확인 대상이 아니며 Phase 2에서 측정한다.

## 2. 이 단계의 목적과 제약

### 2.1 왜 이 세 가지를 먼저 하는가

가속기의 데이터 흐름은 `Host → PCIe → FPGA → DDR3 → BRAM → 연산 배열`이다. 아키텍처를 고정하기 전에 이 경로의 양 끝(PCIe, DDR3)이 실물에서 동작하는지 확인해야, 이후 설계 검증(P2)에서 측정한 값을 신뢰할 수 있다. P0.5는 그 앞 단계로, 보드에 비트스트림이 올라가고 설계가 실제로 도는지를 확인한다.

### 2.2 작업 환경의 제약

- **보드를 직접 볼 수 없다.** 보드는 원격지(FPGA Host `sdsl-llm`)에 있고 작업은 SSH로만 한다. LED·버튼 같은 눈으로 보는 확인은 불가능하므로, 모든 확인을 JTAG로 읽을 수 있는 형태로 바꿨다. 이를 위해 시험 설계마다 **VIO(Virtual Input/Output) IP**를 넣어 내부 상태를 읽었다.
- **Host는 공용 장비다.** 다른 사용자가 함께 쓰므로 재부팅과 설정 변경은 사전에 확인하고 진행했다.
- **빌드와 시험이 분리된다.** 합성·구현은 개발 서버에서 하고, 산출물(`.bit`·`.ltx`·`.mcs`)을 `scp`로 Host에 보내 Host의 Vivado Hardware Manager(로컬 JTAG)로 올린다.

### 2.3 Host 측 스크립트

반복 작업을 자동화하기 위해 `hardware/board_test/host/`에 다음을 만들었다.

| 스크립트 | 용도 |
|---|---|
| `program_fpga.tcl` | 비트스트림 다운로드, VIO 입력 probe 반복 읽기(`-reads`·`-period`) |
| `flash_qspi.tcl` | `-mode mcs` MCS 생성(개발 서버), `-mode flash` QSPI 기록·검증·플래시 부팅(Host) |
| `pcie_reset_vio.tcl` | VIO 출력으로 PCIe 코어를 리셋하고 상태 읽기 |
| `perst_latch.tcl` | PERST# 후보 핀 래치 초기화·읽기 |
| `xdma_roundtrip.sh` | `lspci` 링크 확인과 H2C→C2H 데이터 왕복 비교 |

## 3. P0.5 — LED 설계와 보드 동작 확인

### 3.1 설계

`hardware/board_test/p05_blink/blink_top.v`는 200 MHz 시스템 클럭으로 다음을 수행한다.

- 코어보드 LED 1 Hz 점멸, 캐리어 LED1~4를 약 0.33초마다 순환
- KEY1~4를 누르면 해당 LED를 계속 켜고, RESET을 누르면 카운터를 멈춘다
- **원격 확인용 연산**: `sum(i², i=1..1000)`을 한 클럭에 한 항씩 누산한다. 기댓값은 333,833,500 = `0x13E5E51C`
- 자유 실행 사이클 카운터(32 bit)

VIO probe로 연산 결과·완료 플래그·사이클 카운터·LED 구동값·버튼 입력을 내보낸다. 시뮬레이션에서는 `SIM` 매크로로 VIO를 제외한다.

### 3.2 검증

| 단계 | 결과 |
|---|---|
| xsim (`CLK_HZ`를 60으로 줄인 testbench) | `PASS`. 리셋 시 LED 꺼짐, 순환 순서, 키 입력 반영, 누산 결과 333,833,500 확인 |
| Verilator `--lint-only -Wall` | 경고 0 (비교식의 비트폭 경고 2건을 수정 후) |
| 빌드 | Critical Warning 0, WNS **+0.170 ns** |
| 보드 다운로드 | `DONE = 1` |

### 3.3 보드 결과 (JTAG 읽기)

5초 간격으로 두 번 읽었다.

| probe | 1회차 | 2회차 | 해석 |
|---|---|---|---|
| `acc` | `0x13E5E51C` | `0x13E5E51C` | 기댓값 333,833,500과 일치 |
| `calc_done` | 1 | 1 | 연산 완료 |
| `cyc` | `0x114709D7` | `0x4CF6005B` | 차이 1,001,322,116 |
| `led_n` 구동값 | `0xE` | `0x7` | LED 순환 동작 |
| `key_s1` / `rst_sync` | `0xF` / 1 | 동일 | 버튼 눌리지 않은 상태 |

사이클 차이를 읽기 간격으로 나누면 약 200 MHz다. 판독 시각은 Host의 초 단위 명령 실행 시점이라 오차가 있으므로 **"200 MHz 발진기가 정상 동작한다"는 수준의 확인**으로만 쓴다.

### 3.4 한계

LED와 버튼의 **물리 배선은 확인하지 못했다.** 확인한 것은 FPGA 내부에서 LED 출력 신호가 의도대로 바뀐다는 것까지다. 실물 점등 확인은 보드를 직접 볼 수 있을 때 남겨 둔다.

## 4. P0.6 — DDR3 (MIG) 보드 시험

### 4.1 MIG 설정

MIG는 GUI 대신 프로젝트 파일(XML)로 설정했다. `hardware/board_test/p06_mig/mig_ddr3.prj`는 저장소의 `ax7a200b_ddr3.xdc` 핀표에서 자동 생성했다.

| 항목 | 값 | 근거 |
|---|---|---|
| 메모리 | MT41J256M16XX-125 ×2 → 32 bit, 1 GiB | 매뉴얼 Part 2.4 |
| 동작 주파수 | 400 MHz (800 MT/s), `TimePeriod = 2500 ps` | 매뉴얼 기준 최대 |
| 입력 클럭 | 200 MHz 차동(R4/T4), 참조 클럭도 시스템 클럭 사용 | 보드 발진기 |
| PHY 비율 | 4:1 → **UI 클럭 100 MHz** | 목표 동작 주파수와 일치 |
| 사용자 인터페이스 | AXI4, 데이터 폭 256 bit, 주소 30 bit | P3.4의 DMA 인터페이스 계획과 맞춤 |
| 타이밍 | CL 6 / CWL 5, tRCD 13.75 ns, tRP 13.75 ns, tRFC 260 ns | 부품 XML |

**핀 교차 검증**: MIG가 생성한 XDC의 핀 71개(DQ 32, DQS 8, DM 4, 주소 15, 뱅크 3, 명령·제어 7, 클럭 2)를 저장소 XDC와 자동 비교해 **불일치 0건**을 확인했다. P0.4에서 매뉴얼을 옮겨 적은 표가 MIG의 기대와 일치한다는 뜻이다.

### 4.2 시험 설계 구성

MIG 예제 설계(`example_top`: MIG + AXI4 트래픽 생성기)를 그대로 쓰되, 원격에서 상태를 읽어야 하므로 다음을 덧붙였다.

- 예제 탑에 `ui_clk` 출력 포트만 추가(빌드 스크립트가 자동 패치)
- 감싸는 탑 `p06_top.v`: LED 표시, KEY1로 오류 래치 초기화, VIO로 상태 출력
- VIO probe: `init_calib_complete`, `tg_compare_error`(현재값), 오류 래치, 캘리브레이션 후 경과 초, 오류 발생 시각

경과 초는 UI 클럭으로 세므로, 이 값이 실제 경과 시간과 맞는지로 **UI 클럭 100 MHz를 간접 확인**할 수 있다.

### 4.3 결과

| 항목 | 값 |
|---|---|
| 빌드 | Critical Warning 0, WNS **+0.963 ns**, WHS **+0.052 ns** |
| DRC | Warning 4종(미사용 입력 버퍼 등), Error 0 |
| 캘리브레이션 | `init_calib_complete = 1` |
| 시험 시간 | 360초 (`run_sec = 0x168`) |
| 비교 오류 | `tg_compare_error = 0`, 오류 래치 0 |
| UI 클럭 | 20초 간격 읽기에서 `run_sec`이 20씩 증가 → 100 MHz 확인 |

자원 점유(Phase 2에서 갱신할 기준값):

| 자원 | 사용 | 전체 | 비율 |
|---|---|---|---|
| Slice LUT | 7,829 | 134,600 | 5.82 % |
| Slice Register | 7,953 | 269,200 | 2.95 % |
| Block RAM Tile | 0 | 365 | 0 % |
| MMCM / PLL | 1 / 1 | 10 / 10 | 각 10 % |

**MIG 자체가 BRAM을 쓰지 않는다는 점**은 가중치 저장용 BRAM 예산에 유리하다. 다만 이 수치는 트래픽 생성기를 포함한 예제 구성이며, 최종 설계의 점유는 P2.2에서 다시 측정한다.

### 4.4 한계

예제 트래픽 생성기의 기본 검사 범위는 **앞쪽 16 MiB**(`END_ADDRESS = 0x00FFFFFF`)다. 따라서 이번 결과는 "DDR3가 초기화되고 그 범위에서 읽기·쓰기가 일치한다"까지를 보인다. 1 GiB 전 범위 확인과 **실효 대역폭·지연 측정은 P2.1**에서 별도 트래픽 생성기로 수행한다. 가정값 2.0 GB/s는 아직 검증되지 않았다.

## 5. P0.7 — PCIe Gen2 ×2 (XDMA) 보드 시험

세 항목 중 가장 오래 걸렸고, 원인 규명 과정 자체가 결과다. 시간 순서대로 적는다.

### 5.1 설계

`hardware/board_test/p07_xdma/`의 블록 디자인 `p07_bd`는 **XDMA(Gen2 ×2, AXI-MM 64 bit, 125 MHz, H2C 1채널 + C2H 1채널) → AXI BRAM 컨트롤러 → BRAM 64 KiB** 구성이다. Host가 H2C로 BRAM에 쓰고 C2H로 읽어 비교하면 왕복이 검증된다.

탑 `p07_top.v`는 여기에 LED, 버튼, VIO를 붙인다. GT 채널 배치는 IP가 정하며, 빌드 후 확인한 결과 **lane0 = `GTPE2_CHANNEL_X0Y7`, lane1 = `X0Y6`**으로 P0.4에서 조사한 보드 대응과 일치했다.

### 5.2 1차 시도 — 링크는 올라오는데 장치가 보이지 않음

PERST# 핀을 모르는 상태였으므로, 구성 직후 약 21 ms 동안 리셋을 거는 **내부 파워온 리셋**으로 대신했다.

결과는 다음과 같았다.

- FPGA 쪽: `user_lnk_up = 1`, AXI 클럭 카운터로 125 MHz 확인 → **링크 학습은 성공**
- Host 쪽: `lspci`에 장치 없음

원인은 **슬롯과 부팅 순서** 두 가지였다.

1. **슬롯**: 보드가 SLOT3에 있었는데, SMBIOS 확인 결과 이 슬롯은 커넥터만 x16이고 **전기적으로는 x1**이었다. 게다가 이 슬롯의 루트 포트가 OS에 아예 나타나지 않았다. **SLOT5**(전기적 x4)로 옮기자 루트 포트 `00:1d.0`(PCH 포트 #9)이 나타났다. 이 과정에서 GPU도 SLOT1(x8)에서 SLOT2(x16)로 옮겨 x16으로 동작하게 했다.
2. **부팅 순서**: BIOS는 POST 시점에 장치가 없으면 해당 루트 포트를 감춘다. JTAG로 비트스트림을 올리는 방식은 Host 부팅 이후이므로 늦다. 그래서 **QSPI 플래시(N25Q128, SPI ×4)에 굽고 Host를 재부팅**해 전원 인가 시점에 FPGA가 구성되도록 했다.

### 5.3 2차 시도 — 장치는 보이지만 레지스터가 죽어 있음

슬롯을 옮기고 JTAG로 PCIe 코어를 리셋한 뒤 `echo 1 > /sys/bus/pci/rescan`을 하자 장치가 열거됐다.

```
0000:04:00.0 Serial controller [0700]: Xilinx Corporation Device [10ee:7022]
LnkSta: Speed 2.5GT/s, Width x2
```

그런데 XDMA 드라이버가 실패했다.

```
xdma:map_single_bar: BAR0 at 0x70000000 mapped at ..., length=65536(/65536)
xdma:map_bars: Failed to detect XDMA config BAR
xdma: probe of 0000:04:00.0 failed with error -22
```

직접 확인한 증상과 배제한 원인은 다음과 같다.

| 확인 | 결과 | 배제한 가설 |
|---|---|---|
| BAR0 전 범위(64 KiB) 읽기 | 전부 `0xffffffff`, 쓰기도 반영 안 됨 | — |
| PCIe 설정 공간 읽기 | 정상(`setpci`로 장치 ID `702210ee`, BAR 주소 `0x70000000`) | 링크 자체의 문제 아님 |
| 주소 충돌 | `/proc/iomem`에서 단독 할당 확인 | 주소 겹침 아님 |
| 브리지 창 | `Memory behind bridge: 70000000-700fffff`, Mem+ 활성 | 라우팅 문제 아님 |
| 오류 비트 | UR·완료 타임아웃 모두 0 | 트랜잭션은 완료되고 있음 |
| 읽기 지연 | 평균 7 µs | 요청이 FPGA까지 갔다 옴 |
| **Xilinx 예제 설계**(`xilinx_dma_pcie_ep`)로 교체 | 동일 증상 | 자체 블록 디자인의 설정 오류 아님 |

남은 가설은 **PERST# 미연결로 인한 초기화 순서 어긋남**이었다. Host가 리셋을 걸어도 FPGA 쪽 코어는 그대로 남아, 링크만 유지된 채 레지스터 블록이 응답하지 못하는 상태로 보였다.

### 5.4 PERST# 핀 탐색 — L16 확정

매뉴얼에는 PERST# 신호가 그림에만 있고 FPGA 핀 번호가 없다. 공개된 ALINX 예제(AX7103)의 J20은 AX7A200에서 HDMI 데이터 핀이라 쓸 수 없었다. 그래서 보드에서 직접 찾았다.

1. **후보 압축**: 매뉴얼 Part 2.9의 보드 간 커넥터 표에서 3.3 V 핀을 모두 뽑고, 캐리어보드 주변장치 표(LED·버튼·HDMI·SFP·확장 헤더 등)에 나오는 핀을 제외했다. 후보 **14개**가 남았다.
2. **관찰 회로**: 후보를 풀다운 입력으로 받아, 글리치를 거르기 위해 64클럭(0.32 µs) 연속 같은 값일 때만 반영하는 필터를 거쳐 **"High였던 적"과 "Low였던 적"을 각각 래치**했다. 래치는 보드 발진기(200 MHz)로 동작하므로 Host 상태와 무관하게 돈다. 래치 초기화와 읽기는 VIO로 한다.
3. **실험**: QSPI에 굽고, 래치를 지운 뒤 Host를 재부팅하고, 부팅 후 JTAG로 읽었다.

결과는 명확했다. 재부팅 전에는 각 핀이 High 아니면 Low로 고정(`ever_high = 0x1E20`, `ever_low = 0x21DF`, 서로 여집합)이었는데, 재부팅 후 `ever_low`가 `0x21FF`로 바뀌었다. 새로 켜진 비트는 하나, **bit 5 = L16**이다.

즉 L16만 부팅 과정에서 High → Low → High로 바뀌었고, 이는 PERST#의 거동과 정확히 일치한다. 나머지 13개는 변화가 없었다. 이 결과를 `ax7a200b_pcie.xdc`에 반영했다.

```tcl
set_property -dict { PACKAGE_PIN L16 IOSTANDARD LVCMOS33 PULLUP true } [get_ports pcie_perst_n]
set_false_path -from [get_ports pcie_perst_n]
```

### 5.5 3차 시도 — 정상 동작

PERST#를 XDMA `sys_rst_n`에 연결(내부 파워온 리셋·버튼·VIO 리셋과 OR)해 다시 빌드하고 QSPI에 구운 뒤 재부팅했다. 한 번에 동작했다.

| 항목 | 값 |
|---|---|
| 열거 | BIOS가 부팅 시점에 인식. `0000:04:00.0 [10ee:7022]`, BAR0 64 KiB @ `0x92E00000` |
| 링크 | `LnkSta: Speed 5GT/s, Width x2` — **Gen2 ×2, 목표와 일치** |
| 레지스터 | BAR0 오프셋 0x0·0x1000·0x2000·0x3000 = `0x1FC00006`·`0x1FC10006`·`0x1FC20006`·`0x1FC30006` (XDMA 식별자 정상) |
| 드라이버 | Xilinx `dma_ip_drivers` XDMA v2025.2.0(커밋 `b846609`)을 Host 커널 6.8.0-139에서 빌드·적재. `config bar 0, pos 0` 인식 |
| 장치 노드 | `/dev/xdma0_h2c_0`, `/dev/xdma0_c2h_0`, `/dev/xdma0_control` 생성 |
| **DMA 왕복** | 64 KiB 무작위 데이터를 H2C로 쓰고 C2H로 읽어 비교, **10회 모두 바이트 일치** |
| 빌드 | Critical Warning 0, WNS **+0.486 ns**, WHS **+0.036 ns** |

링크 속도가 1차 시도의 Gen1(2.5 GT/s)에서 Gen2(5 GT/s)로 올라간 것도 함께 확인했다. 리셋을 제대로 받으면서 정상적인 링크 학습 절차를 거쳤기 때문으로 본다.

자원 점유:

| 자원 | 사용 | 전체 | 비율 |
|---|---|---|---|
| Slice LUT | 12,259 | 134,600 | 9.11 % |
| Slice Register | 15,003 | 269,200 | 5.57 % |
| Block RAM Tile | 36.5 | 365 | 10.0 % |
| GTP 채널 | 2 | 4 | 50 % |

BRAM 36.5개 중 16개는 시험용 64 KiB 버퍼이므로, **XDMA 자체는 약 20개(≈ 90 KiB 상당)**를 쓴다. 이 값은 가중치용 BRAM 예산을 다시 계산할 때(P2.2) 반영해야 한다.

### 5.6 한계

- **DMA 처리량은 측정하지 않았다.** 확인한 것은 데이터 정합성이다. 대역폭과 지연·지터는 P2.3에서 측정한다.
- 왕복 대상은 FPGA 내부 BRAM 64 KiB다. DDR3를 경유하는 경로는 P3.7에서 통합한다.
- PERST# 확정 근거는 재부팅 시 신호 거동 관찰이다. 회로도로 교차 확인한 것은 아니지만, 연결 후 링크 속도와 DMA가 모두 정상화된 것이 방증이다.

## 6. 확인한 것과 확인하지 않은 것

**확인한 것**

- 보드에 비트스트림이 올라가고 설계가 의도대로 동작한다(연산 결과 일치, 200 MHz)
- DDR3가 캘리브레이션을 마치고 400 MHz·32 bit·AXI 256 bit 구성으로 동작하며, 6분간 데이터 오류가 없다
- 저장소의 DDR3 핀표 71개가 MIG의 기대와 일치한다
- PCIe가 Gen2 ×2로 링크되고 Host↔FPGA DMA 왕복 데이터가 일치한다
- PCIe PERST# 핀은 L16이다 (P0.4의 미확정 항목 해소)
- QSPI 플래시에 구워 Host 부팅 시 자동 구성되는 경로가 성립한다

**확인하지 않은 것**

| 항목 | 어디서 하는가 |
|---|---|
| DDR3 실효 대역폭·지연, 1 GiB 전 범위 | P2.1 |
| 최종 설계의 BRAM·LUT·FF 점유와 가중치 가용 BRAM | P2.2 |
| PCIe 지연·지터·DMA 처리량 | P2.3 |
| 물리 LED·버튼 배선, UART 신호 방향, 팬 제어 핀 | 보드를 직접 볼 수 있을 때 / 해당 기능을 쓸 때 |

## 7. 이후 작업에 남기는 사항

1. **부팅 순서 규칙**: PCIe를 쓰는 설계는 QSPI에 굽고 Host를 재부팅해야 BIOS가 인식한다. JTAG로만 올린 경우 `/sys/bus/pci/rescan`으로 붙일 수는 있으나 링크가 Gen1에 머무는 경우를 겪었다.
2. **슬롯 위치**: FPGA는 SLOT5(전기적 x4, 루트 포트 `00:1d.0`)에 둔다. SLOT3은 x1이며 루트 포트가 보이지 않았다.
3. **원격 확인 패턴**: 보드를 볼 수 없는 환경에서는 시험 설계에 VIO를 넣고 상태를 JTAG로 읽는 방식이 효과적이었다. 이번에 PERST# 핀 탐색도 이 방식(관찰 래치 + 재부팅)으로 해결했다. 이후 RTL 검증(P3·P4)에서도 계측 카운터를 JTAG로 읽는 경로를 유지한다.
4. **빌드 환경**: MIG는 경로에 공백이 있으면 설정 파일을 읽지 못한다. IP가 들어가는 설계는 `~/mmss_build/<이름>`에서 빌드한다. 상세는 [ENVIRONMENT.md](../design/ENVIRONMENT.md) §3.

다음 단계는 **P0.8(저장소 디렉터리 골격 확정과 선행 NumPy 순전파 재현)**이며, 이것으로 Phase 0이 끝난다. 이어서 Phase 2의 설계 검증은 이번에 열어 둔 DDR3·PCIe 경로 위에서 실측을 수행한다.
