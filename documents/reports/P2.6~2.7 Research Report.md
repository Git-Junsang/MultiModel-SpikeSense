## 2. P2.6 내보내기

`export_models.py`는 각 `last.pth`를 `snn_numpy.load_params`로 읽고 P2.5에서 확정한 `snn_int8.quantize`를 그대로 사용한다. 양자화 규칙을 내보내기 코드에 중복 구현하지 않았다.

가중치는 L1 15,360 B, L2 98,304 B, L3 16,384 B, L4 128 B로 합계 130,176 B다. 층 시작은 모두 128 B 경계에 있다. β와 임계값도 모델 슬롯에 넣어 DDR3 이미지 하나만으로 모델을 복원할 수 있게 했다. 그러나 섹션별 오프셋을 두어 온칩 상주나 선택 DMA를 막지 않는다.

슬롯 패딩을 제외한 가중치+파라미터는 131,588 B로 가중치만보다 1.08% 크다. 5개를 BRAM에 패딩 없이 두면 642.52 KiB이다. 이 수치는 기존 5모델 가중치 635.625 KiB보다 6.895 KiB 크므로 P3.2의 실측 IP 점유량과 함께 메모리 예산을 다시 계산해야 한다. `PROPOSAL.md`는 사전 확인 절차에 따라 이번 작업에서 수정하지 않았다.

## 3. P2.7 골든 참조

`snn_int8.forward` 자체를 정수 규칙의 단일 기준으로 유지하고, 실행 경로를 바꾸지 않는 `trace` 출력을 추가했다. 골든 생성기는 PyTorch 체크포인트를 직접 읽지 않고 P2.6의 `model.slot.bin`만 읽는다. 따라서 내보내기 순서·주소·부호 처리가 틀리면 골든 검증에서 드러난다.

NPZ 형식은 `[T,N]` 시간 우선이다. `cur_lN`(`int32`), `mem_pre_lN`(`int16`), `spk_lN`(`uint8`), `mem_lN`(`int16`)을 저장한다. `output_mem` 값은 `mem_l4`와 같다. `fan_id01/normal`과 포화 stress 2개는 `$readmemh`에 바로 쓸 수 있는 평면 HEX도 제공한다. 나머지 NPZ는 생성기의 `save_rtl_hex`로 같은 형식으로 변환할 수 있다.

## 4. 포화 경로

P2.5 test 전체와 이번 80개 실데이터 벡터에서는 16 bit 포화가 없었다. 그러므로 가중치를 모두 +127 또는 -128, β·임계값을 255, 입력을 127로 두는 인위 모델을 따로 만들었다.

- 양수 stress 포화 횟수 L1/L2/L3/L4: 9,600 / 7,936 / 1,920 / 54
- 음수 stress 포화 횟수 L1/L2/L3/L4: 9,600 / 0 / 0 / 0

이 벡터는 P4.1에서 정상 추론과 별도로 포화 비교기·선택기 경로를 검증하는 데 쓴다.
