# P3.1~P3.4 보고서: DDR3, PCIe, BRAM

작성일: 2026-10-09

## 1. 요약

| Task | 결과 | 종류 |
|---|---|---|
| P3.1 DDR3 | read 3.015 GB/s, write 2.812 GB/s | 보드 실측 |
| P3.2 IP resource | XDMA 20.5 tile, MIG 0 tile | 구현 report |
| P3.3 PCIe | 64 B H2C p50 27.2 µs | 보드 실측 |
| P3.4 BRAM | model entry 28.5 tile, membrane potential 176.5 tile | 계산 + fit |

DDR3는 2.0 GB/s 가정보다 빨랐다. 반면 BRAM의 실제 weight 공간은 709.375 KiB가 아니라 627.75 KiB였다.

## 2. 측정 설계

MIG, XDMA, register block, DDR traffic generator를 한 bitstream에 넣었다.

```text
Host ─ PCIe ─ XDMA ─ SmartConnect ─ DDR3
                 └─ register block
DDR traffic generator ────────────┘
```

DDR generator는 MIG에 직접 연결했다. 주소 mode, burst 길이, outstanding 수를 바꿀 수 있다.

검증:

| 항목 | 결과 |
|---|---|
| xsim | 11개 test + abort PASS |
| Verilator | warning 0 |
| protocol check | error 0 |
| timing | BRC WNS +0.288 ns, RBC +0.115 ns |
| board ID·calibration | 정상 |

## 3. DDR3 실측

### 3.1 무결성과 순차 대역폭

1 GiB 전체를 두 pattern으로 write·read했다. BRC와 RBC 모두 data error 0, protocol error 0이었다.

단위는 GB/s다.

| Burst | BRC read | BRC write | RBC read | RBC write |
|---|---:|---:|---:|---:|
| 32 B | 1.829 | 1.489 | 1.819 | 1.505 |
| 64 B | 2.906 | 1.903 | 3.015 | 1.962 |
| 512 B | 2.906 | 2.583 | 3.015 | 2.688 |
| 4 KiB | 2.906 | 2.688 | **3.015** | **2.812** |

RBC는 `ROW_BANK_COLUMN`, BRC는 `BANK_ROW_COLUMN`이다. RBC가 순차 read 3.7 %, write 4.6 % 빨랐다. 최종 MIG는 RBC를 권고한다.

### 3.2 Slice 전송

| 크기 | 평균 지연 | Blocking 대역폭 |
|---:|---:|---:|
| 512 B | 0.425 µs | 1.176 GB/s |
| 4 KiB | 1.605 µs | 2.537 GB/s |
| L1 15,360 B | 5.335 µs | 2.874 GB/s |
| L2 98,304 B | 32.846 µs | 2.992 GB/s |
| 모델 130,176 B | 43.425 µs | 2.997 GB/s |

비용 모델:

```text
t(S) = 0.244 µs + S / 3.015 GB/s
```

slice마다 약 0.24 µs가 든다. 작은 slice는 DDR3 read를 pipeline해야 한다. 40개 model slot을 무작위로 바꿔도 별도 switch 비용은 보이지 않았다.

단일 32 B read는 평균 275 ns, p99 370 ns, 최대 530 ns였다.

## 4. PCIe 실측

Host application에서 `CLOCK_MONOTONIC_RAW`로 쟀다. Driver, syscall, interrupt 시간이 포함된다.

| Test | p50 | p99 | 최대 |
|---|---:|---:|---:|
| MMIO read, user logic | 1.54 µs | 1.68 µs | 86.69 µs |
| MMIO write 12 + read 1 | 5.62 µs | 5.76 µs | 41.61 µs |
| H2C 64 B | 27.20 µs | 32.25 µs | 119.27 µs |
| C2H 64 B | 25.05 µs | 29.07 µs | 146.82 µs |
| H2C 4 KiB | 32.95 µs | 38.10 µs | 104.55 µs |
| H2C 64 KiB | 109.99 µs | 114.35 µs | 204.30 µs |
| H2C 24 KiB, 32 ms 간격 | 134.40 µs | 137.25 µs | 162.93 µs |

4 MiB throughput는 H2C 758 MB/s, C2H 566 MB/s였다. 5.4 MB model image를 5회 write·read했고 모두 같았다.

작은 DMA는 byte보다 software overhead가 크다. 추론 요청 16,000개/s를 하나씩 보내지 말고 묶어야 한다. 1 ms 간격의 64 B DMA는 p50 98 µs로 더 느렸다.

FPGA clock은 Host보다 +3.82 ppm 빨랐다. 32 ms에서는 0.12 µs 차이지만 한 시간에는 13.8 ms가 된다. Timestamp 변환은 주기적으로 다시 맞춰야 한다.

SmartConnect 3×3는 LUT 약 10k를 썼다. 최종 구조는 연결 수를 줄여야 한다.

## 6. BRAM 계산

| Memory | 구성 | Tile |
|---|---|---:|
| 모델 entry | 4,096 × 256 bit | 28.5 |
| slice double buffer | 512 × 256 bit ×2 | 7.5 |
| membrane potential | 512 × 706 ×16 bit | 176.5 |
| β·vth 40모델 | 28,240 ×16 bit | 14 |
| request queue | 512 ×64 B | 7.5 |
| 트랙 metadata | 512 ×64 bit | 1 |

기본 예산:

```text
365 - 20.5(XDMA) - 176.5(membrane potential) - 28.5(prefetch)
= 139.5 tile = 627.75 KiB
```

β·vth, queue, metadata도 BRAM에 두면 117 tile, 526.5 KiB가 남는다.

모델 entry가 28.5 tile인 이유는 Vivado가 parity bit까지 data로 쓰기 때문이다. 16 bit membrane potential은 parity bit를 쓰지 못한다.

## 7. Fit 확인

MIG·XDMA와 memory skeleton을 함께 배치했다.

| 구성 | BRAM 계산/구현 | LUT | WNS @100 MHz | 결과 |
|---|---:|---:|---:|---|
| entry 4, β·vth 전체 상주 | 344/344 | 30,850 | +0.093 ns | 통과 |
| entry 5, entry별 β·vth | 352/352 | 37,941 | +0.073 ns | 통과 |

5-entry 구성은 queue를 distributed RAM으로 옮긴다. LUTRAM 약 5,500개가 든다.

이 test는 memory 배치와 timing만 확인했다. 실제 accelerator control과 scheduler는 없다.

## 8. 결론과 한계

결정:

- MIG 주소 mapping은 RBC 권고
- P3.5 비용 모델은 `0.244 µs + S/3.015 GB/s`
- 5-entry 기준은 ONCHIP_MEMORY.md의 구성 D
- 작은 PCIe 추론 요청은 batch 전송

미확인:

- compute, DMA, state update 동시 경합
- 부하가 있는 Host의 tail 지연
- write의 실제 DDR3 commit 지연
- 256 lane 최종 timing과 scheduler resource
