## 2. 측정 설계

### 2.1 왜 측정 설계 하나로 묶었는가

P3.1(DDR3)과 P3.3(PCIe)을 따로 재면 최종 시스템처럼 MIG와 XDMA가 함께 있을 때의 자원·배치·클럭 조건을 볼 수 없다. 그래서 두 IP와 인터커넥트를 한 비트스트림에 넣고, 같은 설계에서 세 가지를 모두 측정했다.

```text
Host ──PCIe Gen2×2── XDMA ── SmartConnect 3×3 ──┬── BRAM 64 KiB (DMA 지연 시험용, 125 MHz)
                       │ AXI-Lite(BAR0 64 KiB)   ├── 레지스터 블록 p3_core (100 MHz)
JTAG-AXI(보조) ────────┘                        └── M_AXI_DDR ──┐
                                                                 정적 MUX ── MIG ── DDR3 1 GiB
                              트래픽 생성기 ddr_tgen (100 MHz) ──┘
```

- **트래픽 생성기를 MIG에 직접 붙였다.** SmartConnect를 거치면 인터커넥트 지연이 DDR3 측정에 섞인다. 호스트 DMA 경로는 정적 MUX(`DDR_SEL`)로 바꿔 쓴다.
- **레지스터는 PCIe BAR0로 접근한다.** PCIe가 안 붙으면 JTAG-AXI로 같은 레지스터를 읽을 수 있게 했다(이번에는 쓰지 않았다).
- MIG 설정은 P1.6과 같고(400 MHz, AXI 256 bit, UI 100 MHz), 사용자 주소 매핑만 빌드 옵션으로 바꿨다.

파일: `hardware/board_test/p3_meas/`(`p3_top.v`, `p3_core.v`, `ddr_tgen.v`, `p3_bd.tcl`, `build_p3.tcl`, `p3.xdc`, testbench `tb_p3_core.sv`·`run_tb.sh`, fit 골격 `mem_fit.v`), Host 도구 `hardware/board_test/host/`(`p3_load.sh`, `p3_regs.py`, `p3_ddr_bench.py`, `pcie_lat.c`, `p3_pcie_bench.sh`).

### 2.2 트래픽 생성기

한 실행은 "전송" n개다. 전송 하나는 연속 주소 `xfer_beats × 32 B`이며 가중치 슬라이스 하나를 가져오는 DMA 요청에 해당한다. 4 KiB 경계와 최대 버스트 길이에서 AXI 버스트로 자른다.

| 설정 | 값 |
|---|---|
| 주소 | SEQ(연속), SLOT_RAND(40개 모델 슬롯 중 무작위, 슬롯 간격 132 KiB), SLOT_RR(슬롯 순환), RAND_BEAT(1 GiB 안 무작위) |
| 발행 | blocking(앞 전송이 끝나야 다음 전송) / pipelined(전송 경계 없이 연속) |
| 동시 버스트 | 1~16 |
| 기록 | 전송별 (첫 데이터 지연, 완료 지연)을 2,048개까지 사이클 단위로 저장 |
| 검증 | 주소로 정해지는 패턴을 쓰고 읽으며 beat마다 비교 |

지연은 전송의 첫 버스트를 AR에 올린 사이클부터 마지막 R beat까지다(ui_clk 10 ns 단위). 쓰기는 마지막 B 응답까지인데, MIG AXI는 데이터를 받으면 DRAM 기록 전에 B를 돌려주므로(단일 beat 쓰기 지연 40 ns) **쓰기 지연은 DRAM 기록 완료 시각이 아니다.** 쓰기 대역폭만 의미가 있다.

### 2.3 검증

| 단계 | 결과 |
|---|---|
| xsim (`tb_p3_core.sv`) | **PASS**. MIG 대신 무작위 ready·지연을 가진 AXI 슬레이브 모델. 11개 실행 + abort. 4 KiB 경계를 넘는 버스트 없음, `len ≤ burst_max`, 동시 버스트 ≤ 설정값, 네 주소 모드의 쓰기→읽기 검증 오류 0, 메모리 한 워드를 바꾸면 오류 1개와 정확한 주소 보고, 기록 개수·`log_mask` 확인 |
| Verilator `--lint-only -Wall` | `p3_core`·`ddr_tgen` 경고 0 |
| 빌드 (BRC / RBC) | 구현 단계 Critical Warning 0, 모든 타이밍 제약 만족. 합성 단계에는 `p3.xdc`의 클럭 그룹이 PCIe 클럭(OOC IP 안에 있음)을 찾지 못한다는 경고 2건이 있었고, 구현에서는 비동기 그룹 2쌍이 적용됨을 클럭 상호작용 리포트로 확인했다(이후 `p3.xdc`를 구현 전용으로 지정). WNS **+0.288 / +0.115 ns**, WHS +0.036 / +0.031 ns. GT lane0 = X0Y7, lane1 = X0Y6 |
| 보드 | ID `0x4D4D5033`, 캘리브레이션 완료, TS 계수기 1초 차 100,021,860(약 100 MHz), 모든 측정 실행에서 프로토콜 오류 0 |

### 2.4 보드 적재 — 재부팅 없이

QSPI에는 P1.7 설계가 있다. Host를 재부팅하지 않고 측정 설계로 바꾸기 위해 `p3_load.sh`로 드라이버를 내리고 PCI 장치를 제거한 뒤 JTAG로 올리고 재스캔했다. 두 번 모두 재스캔 직후 **5 GT/s ×2**로 붙었고, BAR0(AXI-Lite 64 KiB)·BAR1(XDMA 설정 64 KiB)이 루트 포트 창 1 MiB 안에 할당됐다. P1.7에서 겪은 Gen1 고착은 PERST# 연결 뒤에는 나타나지 않았다.

## 3. P3.1 DDR3 실효 대역폭·지연 (보드 실측)

원자료: `software/analysis_develop/p3_meas/raw/ddr_{brc,rbc}.jsonl`, 자동 요약: [summary_ddr.md](../../software/analysis_develop/p3_meas/summary_ddr.md). 두 비트스트림은 MIG 사용자 주소 매핑만 다르다.

- **BRC** = BANK_ROW_COLUMN(P1.6 설정): 주소 상위가 뱅크. 순차 접근은 한 뱅크 안에서 4 KiB(한 행)마다 행이 바뀐다.
- **RBC** = ROW_BANK_COLUMN: 4 KiB마다 뱅크가 바뀐다. 다음 뱅크의 행을 미리 열 수 있다.

### 3.1 전 범위 무결성

1 GiB 전체를 두 가지 seed(패턴과 그 보수 성격의 값)로 쓰고 읽어 검증했다. **BRC·RBC 모두 오류 0, 프로토콜 오류 0.** P1.6의 "앞쪽 16 MiB만 검사" 한계를 해소했다.

### 3.2 순차 접근

| 버스트 | BRC 읽기 | BRC 쓰기 | RBC 읽기 | RBC 쓰기 |
|---|---:|---:|---:|---:|
| 1 beat (32 B) | 1.829 | 1.489 | 1.819 | 1.505 |
| 2 beat (64 B) | 2.906 | 1.903 | 3.015 | 1.962 |
| 16 beat (512 B) | 2.906 | 2.583 | 3.015 | 2.688 |
| 128 beat (4 KiB) | 2.906 | 2.688 | **3.015** | **2.812** |

단위 GB/s, 64 MiB 연속, 동시 버스트 16. 피크는 `800 MT/s × 4 B = 3.2 GB/s`다.

- 읽기는 버스트 2 beat 이상이면 포화한다. DDR3 BL8 한 번이 32 bit × 8 = 32 B = AXI 1 beat이고, MIG가 연속 요청을 묶어 처리하기 때문이다.
- 쓰기는 버스트가 길수록 좋아진다. 버스트 128에서 읽기의 93 %다.
- 동시 버스트 수: 버스트 16 beat는 4개 이상, 128 beat는 2개 이상이면 포화한다. 버스트 128 beat를 하나씩만 보내면 2.537 GB/s로 떨어진다.
- **RBC가 BRC보다 순차 읽기 3.7 %, 쓰기 4.6 % 높다.** BRC는 4 KiB마다 같은 뱅크에서 프리차지·활성화를 기다린다.

### 3.3 슬라이스 크기와 모델 전환

가중치 슬라이스를 하나씩 요청하는 DMA(blocking)와 연속 요청(pipelined)을 비교했다. "모델 전환"은 매 슬라이스를 40개 슬롯 중 무작위 모델의 시작 주소에서 읽는 경우다.

| 크기 B | 가정 시간 µs (2.0 GB/s) | RBC 전환·blocking GB/s | 지연 평균 / 최대 µs | 첫 데이터 µs | RBC 전환·pipelined GB/s | BRC 전환·blocking GB/s |
|---:|---:|---:|---|---:|---:|---:|
| 512 | 0.256 | 1.176 | 0.425 / 0.680 | 0.265 | 2.670 | 1.176 |
| 2,048 | 1.024 | 2.214 | 0.915 / 1.020 | 0.275 | 2.953 | 2.214 |
| 4,096 | 2.048 | 2.537 | 1.605 / 1.870 | 0.265 | 3.006 | 2.537 |
| 15,360 (L1) | 7.680 | 2.874 | 5.335 / 5.660 | 0.268 | 3.009 | 2.781 |
| 16,384 | 8.192 | 2.880 | 5.678 / 5.760 | 0.260 | 3.012 | 2.797 |
| 65,536 | 32.768 | 2.980 | 21.979 / 22.030 | 0.263 | 3.014 | 2.873 |
| 98,304 (L2) | 49.152 | 2.992 | 32.846 / 33.040 | 0.266 | 3.014 | 2.882 |
| 130,176 (모델) | 65.088 | **2.997** | **43.425 / 43.520** | 0.266 | 3.014 | 2.885 |

비용 모델용 1차 회귀(11개 크기, blocking, 모델 전환):

```text
RBC: t(S) = 0.244 µs + S / 3.015 GB/s   (최대 잔차 0.023 µs),  최대값 회귀 0.467 µs + S / 3.024 GB/s
BRC: t(S) = 0.215 µs + S / 2.900 GB/s   (최대 잔차 0.039 µs),  최대값 회귀 0.407 µs + S / 2.897 GB/s
```

해석:

- **슬라이스마다 약 0.24 µs의 고정 비용**(첫 데이터까지 약 0.26 µs)이 있다. 4 KiB 미만 슬라이스를 하나씩 요청하면 이 비용 때문에 대역폭이 크게 떨어진다(512 B에서 1.18 GB/s). 연속 요청(pipelined)이면 512 B도 2.67 GB/s(RBC)다. **슬라이스 DMA는 다음 슬라이스 요청을 앞당겨 겹쳐 내야 한다.**
- **모델 전환 비용은 따로 보이지 않는다.** 같은 크기에서 "모델 전환(무작위 슬롯)"과 "같은 모델 연속"의 대역폭 차이가 0.01 GB/s 이내다. 슬롯 하나(132 KiB)가 행 크기(4 KiB)보다 훨씬 커서 슬롯 경계의 행 전환이 슬라이스 고정 비용 안에 묻힌다. 비용 모델은 모델 ID와 무관하게 크기만으로 전송 시간을 계산하면 된다.
- 모델 하나 가중치(130,176 B) 전송은 실측 43.43 µs로, 제안서의 65.088 µs(2.0 GB/s 가정)보다 33 % 짧다. 따라서 "전체 모델 전송 / 요청당 연산 = 1.6"은 실측으로 `43.43 / 40.68 = 1.07`이 된다.
- 모델·층 단위(RBC, blocking): L1 15,360 B 5.34 µs, L2 98,304 B 32.87 µs, L3 16,384 B 5.68 µs, 슬롯 전체 135,168 B 45.06 µs, β·임계값까지 연속 구간 131,680 B 43.93 µs. 무작위 순서와 순환 순서의 차이 없음.

### 3.4 단일 접근 지연과 임의 주소

| 시험 (RBC) | 최소 | 평균 | p99 | 최대 |
|---|---:|---:|---:|---:|
| 32 B 읽기, 1 GiB 임의 주소, 하나씩 | 260 ns | 275 ns | 370 ns | 530 ns |
| 32 B 읽기, 연속 주소, 하나씩 | 250 ns | 275 ns | 410 ns | 490 ns |

임의 주소와 연속 주소의 단일 지연이 같다. MIG가 쉬는 동안 행을 닫아 두는 것으로 보인다(확인하지 않았다). 최대값(약 500 ns)은 리프레시와 겹친 경우로 본다. 임의 주소 소단위를 연속 요청하면 32 B 0.98 GB/s, 512 B 2.64 GB/s, 4 KiB 3.00 GB/s이고 주소 매핑에 따른 차이는 없다.

### 3.5 P3.5에 넘기는 값

| 항목 | 값 (RBC) |
|---|---|
| 순차 실효 대역폭 | 읽기 3.015 GB/s, 쓰기 2.812 GB/s |
| 슬라이스 1개 (blocking) | 평균 `0.244 µs + S / 3.015 GB/s`, 최악 `0.467 µs + S / 3.024 GB/s` |
| 연속 요청 시 | 4 KiB 이상 슬라이스는 3.0 GB/s 유지 |
| 모델 전환 추가 비용 | 측정 범위에서 없음 |
| 첫 데이터 지연 | 약 0.26 µs |

**MIG 주소 매핑은 ROW_BANK_COLUMN을 권고한다.** 최종 설계에서 바꿀지는 P3.9에서 정한다.

## 4. P3.3 PCIe Host↔FPGA 지연·지터 (보드 실측)

원자료: `software/analysis_develop/p3_meas/raw/pcie/`, 자동 요약: [summary_pcie.md](../../software/analysis_develop/p3_meas/summary_pcie.md).

### 4.1 측정 방법

`pcie_lat.c`가 호스트에서 연산 한 번(MMIO 접근 또는 XDMA 장치 파일의 `write`/`read`)의 시간을 `CLOCK_MONOTONIC_RAW`로 잰다. 따라서 값은 **호스트 응용이 체감하는 시간**이며, 드라이버·시스템 호출·인터럽트 처리가 포함된다. XDMA 드라이버는 인터럽트 모드다(폴링 모드는 실패, ENVIRONMENT §7.3). 측정 시 Host는 다른 부하가 거의 없었고(부하 평균 0.2 이하) CPU 고정·실시간 우선순위는 쓰지 않았다.

### 4.2 결과 (p3 측정 설계, µs)

| 시험 | 표본 | p50 | p99 | p99.9 | 최대 |
|---|---:|---:|---:|---:|---:|
| MMIO 읽기, XDMA 설정 BAR(사용자 로직 없음) | 100,000 | 1.30 | 1.39 | 3.14 | 80.63 |

처리량(DDR3 경로, `DDR_SEL=1`): H2C 4 MiB 평균 5.53 ms(**758 MB/s**), C2H 4 MiB 7.40 ms(566 MB/s). 40모델 DDR3 이미지 5,406,720 B를 H2C로 적재하고 C2H로 읽어 비교하는 시험을 5회 반복해 **5회 모두 일치**, 적재 7.01~7.18 ms(753~772 MB/s). 호스트 경로에서 narrow burst는 감지되지 않았다(MUX의 감지 플래그 0).

P1.7 설계(SmartConnect 없이 XDMA → BRAM)로 같은 시험을 먼저 했고, DMA 값은 1 µs 안팎으로 같았다(예: H2C 64 B p50 26.97 µs, C2H 64 B 24.64 µs). 인터커넥트는 DMA 지연에 거의 영향이 없다.

### 4.3 해석

1. **작은 DMA 한 번의 비용은 전송량이 아니라 소프트웨어 경로가 정한다.** 64 B와 4 KiB의 차이는 6 µs뿐이고, 64 B 하나에 27 µs가 든다. 요청 16,000개/s를 하나씩 DMA로 보내면 `16,000 × 27 µs = 0.43 s/s`, 즉 호스트 CPU 한 개의 43 %가 시스템 호출에 묶인다. **요청은 묶어 보내야 한다.** 512트랙 분량 24 KiB를 한 번에 보내는 데 134 µs다.
2. **띄엄띄엄 보내면 더 느리다.** 1 ms 간격이면 같은 64 B가 p50 98 µs다. 62.5 µs 간격(512트랙 평균 요청 간격)에서는 27~28 µs로 연속과 같다. 호출 사이에 CPU가 깊은 유휴 상태로 들어가 깨어나는 비용으로 보이며, CPU 유휴 상태를 바꿔 확인하지는 않았다.
3. **MMIO 경로는 µs 단위다.** 48 B 요청을 MMIO 쓰기 12번으로 보내면 5.6 µs로 DMA보다 5배 빠르다. 결과 회수도 MMIO 읽기 1.5 µs다. 요청 하나씩 보내는 저지연 경로로는 MMIO, 묶음 전송에는 DMA가 맞다. 실제 프로토콜은 P3.9에서 정한다.
4. **지터**: 관측 최대는 연속 측정에서 147 µs, 32 ms 주기 24 KiB 전송에서 163 µs다. P1.7 설계 측정에서는 62.5 µs 주기 H2C 64 B 최대 795 µs가 한 번 나왔다. 32 ms 마감 대비 0.5~2.5 %다. 다만 표본 수가 2만~10만 개이므로 이보다 드문 지연(스케줄러 선점 등)은 관측되지 않았을 수 있다. 하드 마감 검증에는 이 값을 상한으로 쓰지 않고 여유를 둔다.
5. **시계**: FPGA TS(보드 200 MHz 발진기 → MMCM 100 MHz)는 호스트 `CLOCK_MONOTONIC_RAW` 대비 **+3.82 ppm**(60초, 6만 표본, 회귀 잔차 p99 0.63 µs, 판독 왕복 p50 1.66 µs)이다. 32 ms 동안 0.12 µs라 한 요청 안에서는 무시할 수 있지만 1시간이면 13.8 ms가 벌어진다. 입력 생성 시각을 FPGA 시각으로 바꾸려면 주기적으로 대응 관계를 다시 맞춰야 한다.

## 5. P3.4 32레인 BRAM 구성 (계산 + 구현 확인)

상세는 [ONCHIP_MEMORY.md](../design/ONCHIP_MEMORY.md)에 정리했다. 요점은 다음과 같다.

| 메모리 | 포트·폭 | 타일 |
|---|---|---:|
| 가중치 캐시 엔트리 | SDP, 읽기 256 bit(연산) + 쓰기 256 bit(DMA), 4,096 word(4,068 사용) | 28.5 / 엔트리 |
| 슬라이스 이중 버퍼 | 같은 구성, 512 word × 2 | 7.5 |
| 막전위 | 층별 SDP 16 bit(뉴런 1개/사이클) 읽기-수정-쓰기 | 176.5 |
| β·vth | 40모델 상주 28,240 × 16 bit / 엔트리별 RAMB18 | 14 / 0.5 |
| 요청 큐, 트랙 메타 | 512 × 64 B, 512 × 64 bit | 7.5, 1 |

- 32레인에는 사이클당 256 bit 가중치 word가 필요하다. MIG AXI 폭도 256 bit라 DMA가 받은 word를 변환 없이 그대로 쓴다. 읽기와 쓰기가 서로 다른 포트라 연산과 채우기가 경합하지 않는다.
- 레인 배치는 출력 고정(레인 = 출력 뉴런 32개)을 권고한다. 밀집 4,068사이클이고 층 2~4에서 0 스파이크 입력을 건너뛸 수 있다(골든 80개 계산 평균 1,385사이클). 대신 DDR3 가중치 형식을 레인 교차 배치로 바꿔야 한다. 저장소 구성·타일 수는 레인 배치와 무관하다.
- 막전위는 그룹이 끝날 때만 갱신하므로 16 bit 포트로 충분하다(층 1: 40사이클에 32뉴런).
- 타일 용량은 폭에 따라 다르다. 256 bit 같은 넓은 word는 9 bit 열로 나눠 타일당 36 Kibit을 모두 쓰고(엔트리 28.5 타일), 16 bit 막전위는 18 bit 중 16 bit만 써서 32 Kibit이다(176.5 타일, 데이터 706 KiB에 물리 794.25 KiB).

### 6.2 가중치 가용 BRAM 재계산

제안서와 같은 단위(타일당 물리 4.5 KiB)와 같은 배분으로, 실측 IP 점유와 메모리별 타일 수(§5, ONCHIP_MEMORY §7)를 넣어 다시 계산했다.

```text

```

### 6.3 메모리 골격의 배치·배선 확인 (fit 실험)

계산만으로는 Vivado가 메모리를 어떤 프리미티브로 만들지, BRAM을 95 % 가까이 쓸 때 배치·배선과 100 MHz 타이밍이 되는지 알 수 없다. 그래서 측정 설계에 [mem_fit.v](../../hardware/board_test/p3_meas/mem_fit.v)를 붙여 배치·배선까지 했다(`build_p3.tcl -fit`). 측정용 BRAM 64 KiB와 JTAG-AXI는 빼고 SmartConnect는 2×2(호스트→DDR3, 호스트→레지스터)로 줄였다. `mem_fit`은 기능 회로가 아니라 ONCHIP_MEMORY의 메모리를 실제 크기로 만들고 두 포트를 모두 움직이는 골격이다. 트래픽 생성기가 읽은 DDR3 데이터를 엔트리·버퍼에 쓰고, 32레인이 엔트리를 읽어 누산하며, 막전위 뱅크 4개가 β·vth를 읽어 읽기-수정-쓰기를 한다.

| 구성 | BRAM 타일 (계산 / 구현) | LUT | 분산 RAM LUT | ui_clk WNS |
|---|---|---:|---:|---:|
| B: 엔트리 4, 슬라이스 이중 버퍼, β·vth 40모델, 큐 BRAM | 344 / **344 (94.2 %)** | 30,850 (22.9 %) | 4,639 | +0.093 ns |
| D: 엔트리 5, 슬라이스 이중 버퍼, β·vth 엔트리별, 큐 분산 RAM | 352 / **352 (96.4 %)** | 37,941 (28.2 %) | 10,111 | +0.073 ns |

두 구성 모두 배치·배선을 마쳤고 모든 타이밍 제약을 만족했으며 Critical Warning 0이다(계산 타일 수에는 측정용 지연 기록 1 타일 포함).

이 실험에서 계산 모델의 오류를 하나 찾았다. 처음 계산은 "8 bit 가중치는 패리티 비트를 쓸 수 없다"고 보고 엔트리 하나를 32 타일로 잡았다. 그런데 Vivado는 4,096 × 256 bit 엔트리를 RAMB36(4K × 9) 28개 + RAMB18(4K × 4) 1개 = **28.5 타일**로 만들었다. 256 bit word를 9 bit 열로 나누면 레인 바이트가 두 프리미티브에 걸칠 뿐 논리 비용이 없으므로 패리티 비트까지 데이터로 쓰는 것이다. 슬라이스 버퍼·요청 큐도 같은 이유로 8 → 7.5 타일이다. 16 bit 막전위는 계산대로 176.5 타일(32K × 1 또는 2K × 18, 16/18 bit 사용)이었다. β·vth 40모델(28,240 × 16 bit)은 Vivado가 32K × 1 × 16 = 16 타일로 추론했으며, 2K × 18 깊이 14단으로 지정하면 14 타일이다. 고친 모델로 다시 계산한 값이 §6.2와 ONCHIP_MEMORY §7이며, D 구성의 계산 352 타일은 구현과 일치했다.

ui_clk 최악 경로는 두 구성 모두 BRAM 배선이 아니라 골격의 PLIF 갱신식(곱셈→덧셈→포화→비교→뺄셈을 한 사이클, 13단)이었다. 실제 RTL은 이 식을 파이프라인으로 나눌 것이므로, BRAM을 96 % 쓰는 배치 자체가 100 MHz의 걸림돌은 아니었다. 다만 골격은 실제 제어 논리·스케줄러·요청 처리 논리를 포함하지 않으므로, 최종 설계의 LUT·타이밍은 P5.1에서 다시 확인한다.

## 7. 확인한 것과 확인하지 않은 것

**확인한 것**

- DDR3 1 GiB 전 범위 읽기·쓰기 무결성, 순차 3.015 GB/s(RBC), 슬라이스 크기별 전송 시간과 고정 비용, 모델 전환 비용이 따로 없음
- MIG 주소 매핑에 따른 차이(RBC가 3.7~4.6 % 높음)
- XDMA·MIG·SmartConnect의 자원 점유, BRAM 타일 기준 예산
- 계획한 온칩 메모리(엔트리 4벌·5벌 두 구성)를 MIG·XDMA와 함께 넣어도 배치·배선되고 100 MHz를 만족하며, 타일 수가 계산과 일치함(fit 실험, 기능 동작은 검증하지 않은 골격)
- PCIe MMIO·DMA 지연 분포, 묶음 전송 처리량, 호스트→DDR3 모델 이미지 적재와 되읽기 일치, 호스트·FPGA 시계 오차
- 측정 설계 재적재가 Host 재부팅 없이 Gen2 ×2로 동작함

**확인하지 않은 것**

| 항목 | 이유·다음 단계 |
|---|---|
| 연산·채우기·막전위 갱신이 동시에 DDR3·BRAM을 쓸 때의 경합 | 실제 RTL(P4)에서 측정. 이번 측정은 DDR3를 트래픽 생성기 하나가 독점 |

| XDMA 폴링 모드 | 드라이버에서 완료 감지 실패, 원인 미조사 |
| 부하가 있는 Host에서의 지터, 실시간 우선순위·CPU 고정 효과 | P4.8·P5에서 실제 전처리 프로세스와 함께 측정 |

| fit 골격의 기능 | `mem_fit`은 배치·타이밍 확인용 골격이라 시뮬레이션·보드 실행을 하지 않았다 |

## 8. 다음 단계와 결정이 필요한 것

1. **5벌 캐시 기준안의 구성(확정: 구성 D)**: 막전위 512트랙을 온칩에 두면 제안서 배분으로는 4벌이다. 5벌을 유지하려면 구성 D(슬라이스 이중 버퍼 + β·vth 엔트리별 + 큐·메타 분산 RAM, 잔여 15 타일)를 기준으로 삼는다. 막전위 일부를 DDR3로 옮기는 안(전부 옮기면 45.18 MB/s 추가, 엔트리 최대 11)은 P3.6에서 비교한다. 사용자 확인을 거쳐 PROPOSAL.md를 rev.5로 갱신했다(2026-10-09): §2.1 BRAM·DDR3·PCIe 실측, §3.2 예산식과 5벌 기준안의 구성 D, §3.3·3.4 실측 전송값, §3.5 경계(재사용 없는 대역폭 741트랙, 막전위 832트랙), 부록 A.
2. **부분 상주 예시(40모델 L1 = 600 KiB = 142.5 타일)**는 구성 B(138 타일)에는 4.5 타일 모자라고 구성 D(160 타일)에는 들어간다. P3.6에서 저장 정책을 비교할 때 이 예산을 쓴다.
3. P3.5 시뮬레이터 비용 모델에 §3.5의 DDR3 값과 §4.2의 PCIe 분포를 넣는다. PCIe는 호스트 소프트웨어 경로가 지배하므로 "묶음 크기 → 지연" 표로 넣는다.
4. P3.9에서 MIG 주소 매핑(ROW_BANK_COLUMN), 레인 배치(출력 고정)와 DDR3 가중치 형식 v2, 요청 전달 방식(MMIO / 묶음 DMA), 시각 재동기화 주기를 정한다.
