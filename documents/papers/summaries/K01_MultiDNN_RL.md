# K01: 강화학습 기반 온디바이스 다중 딥러닝 모델 스케줄링

원문: `K01_MultiDNN_RL_JKIICE2025.pdf`
박현빈, 김명선(한성대학교), "강화학습 기반 온디바이스 다중 딥러닝 모델 스케줄링", 한국정보통신학회논문지 29(7), 2025, pp. 919–928, DOI 10.6109/jkiice.2025.29.7.919
읽은 범위: 원문 전체(10쪽)

## 한 줄 요약

GPU 메모리보다 큰 DNN 3개를 layer 단위 task로 나눠 필요할 때만 GPU에 적재하고 강화학습으로 적재(H2D)와 연산을 겹치는 실행 일정을 오프라인에서 만들었다. 2 GB로 제한한 GPU에서 세 모델을 돌렸고 평균 추론 시간이 약 30% 줄었다(초록, §4).

## 설계

| 항목 | 내용 |
|---|---|
| 문제 | 여러 모델을 함께 쓰면 모델 전체를 GPU 메모리에 둘 수 없다. 나눠 적재하면 CPU–GPU 전송 지연이 추론 시간을 늘린다(§II-2.2) |
| 방법 | 오프라인 profiling: 모델을 H2D, Compute, D2H 중 한 종류만 담은 task로 나눈다. Task마다 의존성, WCET(여러 번 실행한 최댓값), 추가 GPU 메모리를 잰다(§3.2) |
| 방법 | 강화학습: Compute, H2D, D2H agent 3개가 각자 task를 자기 CUDA stream(csh·csl, h2d, d2h)에 넣을지 정한다. 상태는 stream 사용 여부, 남은 시간, 메모리 예산, queue 빈 여부다. 메모리 예산을 넘으면 학습 loop를 끝낸다. 학습은 DQN이다(§3.3, Fig. 4·5) |
| 방법 | 실행: 학습한 정책으로 task ID, stream, 시작 시각(ST), 끝 시각(FT = ST + WCET)을 담은 일정표를 만든다. 온라인 low-level scheduler는 시각이 되면 표대로 task를 CUDA stream에 보낸다. 메모리가 일정 값을 넘으면 실행을 마친 layer를 해제한다(§3.4, §3.5, §4.2) |
| 가정·조건 | GTX 1650, i7-10510U, RAM 16 GB, 쓸 수 있는 VRAM 2 GB. 모델은 ResNet-152, VGG16, ViT-B이고 세 모델을 함께 추론하는 시나리오 하나다(§IV). 주기적 추론 요청, 같은 모델의 여러 stream, deadline은 원문에 없다 |

## 결론

- 평균 추론 시간: 적용 전(Org.) 940.89 ms, 적용 후 666.09 ms(약 30% 감소). 일정표가 예상한 끝 시각은 622 ms다(§4.1.1, Fig. 7)
- 첫 추론: 1,677.84 → 904.58 ms. 첫 실행을 빼면 평균 632 ms다(§4.1.2, Fig. 8)
- 메모리: 세 모델을 2 GB에 함께 올리면 실행할 수 없었고 적용 후 최대 사용량은 약 1.45 GB였다(§4.2, Fig. 9). Task WCET 차이를 20배 안으로 맞추면 666.09 ms, 100배 넘게 두면 724.52 ms였다(§4.3, Fig. 10)
- 평가 방식: GTX 1650 PC 실측

## 이 연구와 비교

| 같은 점 | 다른 점 | 이 연구가 나은 점 |
|---|---|---|
| 모델 weight 합이 가속기 메모리보다 커서 필요할 때 적재하고 적재를 연산과 겹친다. 이 연구는 weight 4.97 MiB가 BRAM 약 1.6 MiB보다 크고 연산 중 다음 batch 모델을 prefetch한다 | 박현빈·김명선은 구조가 다른 DNN 3개를 layer 단위로 나눠 적재한다. 이 연구는 구조가 같은 SNN 모델 40개를 모델 한 벌 단위로 entry 4개에 적재한다 | 없음. 모델 하나가 entry보다 큰 경우(layer 단위 분할)는 다루지 않는다 |
| 적재와 실행 순서를 정해 지연을 줄인다 | 박현빈·김명선은 WCET로 만든 일정표를 오프라인에서 정하고 온라인에서는 시각대로 실행한다. 이 연구는 트랙 1,024개의 추론 요청이 32 ms마다 오고 도착이 Host 처리 지연만큼 흔들린다 | [구조] PNU-Count가 queue, 모델 그룹 지연 G(m, k)와 추론 요청별 지연 j(i, k) 분포, n_expect로 다음 사용을 예측해 실행 중에 내보낼 모델을 고른다 |
| | 박현빈·김명선은 모델마다 추론을 한 번씩 돌린다. 이 연구는 같은 모델 트랙이 여럿이다 | [구조] Offset Assignment와 Grouping으로 같은 모델 추론 요청을 batch로 묶어 적재 한 번에 여러 트랙을 처리한다 |

## 인용할 때

- 박현빈·김명선이 먼저 했다: 메모리가 작은 장치에서 다중 DNN을 task로 나눠 필요할 때 적재하고 강화학습으로 적재·연산 중첩 일정을 정했다. 부분 상주, prefetch, 적재와 연산 겹치기 자체는 신규성으로 주장하지 않는다([09_RELATED_WORK §3](../../design_references/09_RELATED_WORK.md#3-신규성-경계))
- 국내 선행연구로 쓸 문장: "박현빈·김명선은 GPU 메모리보다 큰 DNN 3개를 layer 단위 task로 나눠 필요할 때만 적재하고 강화학습(DQN)으로 적재와 연산을 겹치는 실행 일정을 오프라인에서 정했다. VRAM 2 GB에서 세 모델을 함께 실행했고 평균 추론 시간이 적용 전보다 약 30% 줄었다고 보고했다. 이 방법은 모델마다 추론을 한 번씩 실행하는 경우를 다루며 같은 모델을 쓰는 주기 stream 여러 개의 weight 재사용은 다루지 않는다."
- 근거 위치: 문제 정의 §II-2.2와 Fig. 1, profiling §3.2, agent·보상 §3.3.2–3.3.6, 일정표 §3.4, 실행 §3.5와 Fig. 6, 결과 §4.1–4.3과 Fig. 7–10
- 주의: 초록과 서론은 embedded GPU를 말하지만 실험 장치는 GTX 1650이고 VRAM을 2 GB로 제한했다. 제한 방법은 원문에 없다. 원문이 "동적 스케줄링"이라 부르는 것은 오프라인에서 만든 일정표를 시각대로 실행하는 것이다
- 주의: §4.2는 해법 없이 세 모델을 2 GB에 올리면 실행할 수 없다고 쓰는데 Fig. 7·8의 적용 전(Org.)이 어떤 메모리 조건에서 잰 값인지 원문에 없다. Fig. 9에는 적용 후 곡선만 있다
- 비교군: 옮기지 않았다
