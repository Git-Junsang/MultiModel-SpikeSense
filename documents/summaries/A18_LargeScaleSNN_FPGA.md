# A18 · 대규모 SNN 가속기 — 상태와 가중치의 저장 위치

> rev.2 · 2026-09-16 개정  
> Kit Cheung, Simon R. Schultz, Wayne Luk · Imperial College London · ICANN 2012  
> A Large-Scale Spiking Neural Network Accelerator for FPGA Systems  
> 원문: `documents/papers/A18_LargeScaleSNN_FPGA_ICANN2012.pdf`

## 1. 이 논문은 어떤 문제를 푸는가

뉴런 수가 큰 SNN을 계산하려면 많은 시냅스 가중치와 뉴런 상태를 저장해야 한다. 모두 FPGA 안에 넣기는 어렵지만, 모든 데이터를 외부 메모리에서 읽고 쓰면 전송 시간이 길어진다.

이 논문은 **자주 갱신하는 상태는 온칩 BRAM에, 많은 공간을 차지하는 시냅스 가중치는 오프칩 DRAM에 두는 방식**을 사용한다. 목적은 대규모 생물학적 신경망 시뮬레이션을 가속하는 것이다. 저자들은 FPGA 하나로 뉴런 64K개의 시뮬레이션을 실시간보다 약 2.5배 빠르게 수행할 수 있다고 추정했다.

우리 연구에서는 성능 수치보다 **어떤 데이터를 가까이 두고, 어떤 데이터를 필요할 때 가져오는가**라는 설계 원칙이 중요하다.

## 2. 가속기는 어떻게 동작하는가

### 뉴런 계산과 가중치 전달을 나눈다

가속기는 크게 뉴런을 갱신하는 모듈과, 발화에 따른 가중치를 전달하는 모듈로 나뉜다. 한 타임스텝의 흐름은 다음과 같다.

1. 뉴런 모듈이 이전 단계에서 누적된 전류를 이용해 뉴런 상태를 갱신한다.
2. 발화한 뉴런의 번호를 가중치 분배 컨트롤러에 전달한다.
3. 컨트롤러가 해당 뉴런의 시냅스 가중치를 DRAM에서 읽는다.
4. 가중치 분배 모듈이 연결된 뉴런들의 전류를 BRAM에 누적한다.
5. 누적된 전류를 다음 타임스텝의 뉴런 계산에 사용한다.

가중치는 **연결의 출발점인 뉴런이 발화했을 때만** 읽는다. 발화가 드물면 가중치 전달 작업도 줄어드는 이벤트 기반 처리다. 실제 처리량은 연결 수와 메모리 배치의 영향도 받는다.

여기서 온칩에 보관하는 주요 값은 **누적 시냅스 전류 I**다. 우리 설계의 막전위와 같은 변수는 아니지만, 반복해서 읽고 갱신하는 상태를 가까이 둔다는 점은 공통이다.

### 동시에 들어온 가중치가 같은 메모리로 몰리지 않게 한다

여러 시냅스 가중치를 한 번에 받으려면, 각 가중치가 갱신할 메모리 위치도 병렬로 접근할 수 있어야 한다. 논문은 전류 저장 공간을 여러 분기로 나누고, 각 분기에 가산기와 BRAM을 둔다.

DRAM에서 가져오는 시냅스 패킷은 32비트다. 가중치 16비트, 어느 분기로 보낼지를 나타내는 번호 6비트, 분기 안의 저장 위치 10비트로 구성된다.

**한 번에 읽은 패킷 두 개가 같은 분기에 도착하지 않도록** DRAM의 데이터를 배치한다. 그래야 두 갱신이 하나의 메모리 포트를 두고 기다리지 않는다. 다만 이 배치를 맞추기 위해 빈 공간이 생길 수 있으며, 가장 바쁜 분기에 따라 처리 시간이 결정될 수 있다.

## 3. 어떤 결과를 보였는가

실험 플랫폼은 Virtex-6 SX475T FPGA와 DDR3 메모리를 갖춘 Maxeler 시스템이다. 시스템에 FPGA가 네 개 있지만 이 설계에는 하나를 사용했다. 플랫폼의 DRAM 대역폭은 38.4 GB/s, FPGA 하나의 BRAM은 4.6 MB이며 동작 클럭은 100 MHz다.

| 항목 | 논문이 보고한 값 |
|---|---|
| 구성 | 가중치 분기 48개, 뉴런 모듈 2개 |
| 구현 자원 | LUT 80,212개, FF 90,669개, BRAM 268개, DSP 20개 |
| 자원 사용률 | LUT 27.0%, BRAM 25.1%, DSP 1% |
| 추정 스파이크 전달률 | 32K / 64K 뉴런에서 각각 1.39G / 1.17G spikes/s |
| 추정 시뮬레이션 속도 | 32K 뉴런은 실시간의 6배, 64K 뉴런은 2.5배 |

논문은 성능이 **메모리 대역폭에 제한되므로 클럭만 높여도 큰 개선을 기대하기 어렵다**고 설명한다. 위 처리량은 논문에서 추정값으로 제시한 결과다. 구현 자원 수치와 실제 장치에서 측정한 처리량을 혼동하지 않도록 구분해서 인용해야 한다.

## 4. 우리 연구에는 어떻게 적용할 수 있는가

### 온칩 상태와 오프칩 가중치의 역할을 설명한다

| 구분 | 온칩에 보관하는 주요 데이터 | 오프칩에 보관하는 주요 데이터 |
|---|---|---|
| A18 | 누적 시냅스 전류 | 시냅스 가중치 |
| 우리 설계 | 트랙별 막전위와 일부 모델 캐시 | 전체 모델의 가중치 |

우리 설계도 자주 갱신하는 상태를 온칩에 두어 DRAM의 읽기·쓰기를 줄인다. 이 분담 방식은 이미 선행연구에 있으므로, 우리 연구의 새 기여는 여러 모델의 캐시 사용과 트랙별 처리 순서를 정하는 데서 찾아야 한다.

A18의 대역폭은 우리 설계가 가정한 실효 2.0 GB/s보다 훨씬 크다. 따라서 두 시스템의 처리량을 직접 비교하기보다는, 메모리 이동이 성능을 제한하는 사례로 인용하는 것이 적절하다. DSP 사용률이 낮다는 사실만으로 우리 설계의 병목까지 입증되지는 않는다.

### 메모리 제어기가 차지하는 자원도 측정한다

저자들은 메모리 인터페이스와 주변 장치가 자원의 상당 부분, 전체의 절반 이상을 사용한다고 설명한다. 이것을 ‘BRAM 사용량의 절반 이상’이라고 특정해서 읽어서는 안 된다.

우리 제안서는 DDR3 메모리 제어기인 **MIG**와 기타 로직에 100 KiB를 배정하고 있다. 이 예산이 맞는지는 실제 구현으로 확인해야 한다. MIG가 예상보다 많은 BRAM을 사용하면 모델 캐시가 작아지고, 스케줄러가 얻을 수 있는 재사용 효과도 달라진다.

따라서 초기 메모리 테스트에서는 **실효 대역폭과 MIG의 BRAM·LUT 사용량을 함께 기록**할 필요가 있다.

### 상태가 온칩에 다 들어가지 않는 경우를 검토한다

A18은 상태 전체를 BRAM에 둘 수 없으면, 일부만 온칩에 남기고 나머지는 주 메모리에 두는 확장 방향을 제시한다. 대신 추가 메모리 인터페이스가 필요하다는 비용도 언급한다.

우리도 트랙 수를 늘려 막전위가 BRAM 예산을 넘으면 같은 선택을 검토해야 한다. 이때 비교할 것은 저장 가능 여부뿐 아니라 **상태를 옮기는 추가 바이트 수, 전송 시간, 가중치 전송과의 경쟁**이다. A18은 이 확장 방향의 선례이며, 우리 조건에서 마감을 만족한다는 증거는 아니다.

### 메모리 충돌을 줄이는 배치를 참고한다

한 번에 읽은 데이터를 여러 BRAM 분기로 나누는 방식은 모델 캐시의 메모리 분할을 설계할 때 참고할 수 있다. 특히 프리페치가 데이터를 쓰는 동안 연산 장치가 읽어도 충돌하지 않는지 확인해야 한다. 다만 A18의 시냅스 배치를 우리 가중치 배열에 그대로 적용할 수 있는 것은 아니므로, 포트 수와 접근 순서에 맞춰 다시 설계해야 한다.

## 5. 적용 범위와 원문 확인 위치

A18은 단일 신경망의 시뮬레이션을 다룬다. 여러 모델의 캐시 교체, 요청별 마감 시간, 추론 정확도를 평가하는 논문은 아니다. 축삭 지연과 시냅스 가소성도 지원하지 않는 한계로 제시한다.

| 다시 확인할 내용 | 원문 위치 |
|---|---|
| 자주 접근하는 상태를 온칩에 두는 이유 | §1 |
| 상태 저장과 가중치 분배 구조, 오프칩 상태 저장 확장 | §3 |
| 구현 플랫폼과 메모리 배치 | §4 |
| 자원 사용량, 성능 추정, 메모리 대역폭 병목 | §5 |
