# A16 · SNN 데이터플로우 — 막전위를 고려한 계산 순서

> rev.2 · 2026-09-16 개정  
> Deepika Sharma, Aayush Ankit, Kaushik Roy · Purdue · ISLPED 2022  
> Identifying Efficient Dataflows for Spiking Neural Networks · DOI: 10.1145/3531437.3539704  
> 원문: `documents/papers/A16_IdentifyingDataflows_SNN.pdf`

## 1. 이 논문은 어떤 문제를 푸는가

같은 신경망을 계산하더라도, 어떤 데이터를 가까운 메모리에 두고 어떤 계산을 먼저 하느냐에 따라 데이터 이동량이 달라진다. 이렇게 **계산 순서와 데이터 배치를 정하는 방식**을 데이터플로우라고 한다.

일반적인 ANN에서는 입력, 가중치, 출력을 주로 고려한다. SNN에는 여기에 **막전위**가 더해진다. 막전위는 뉴런이 이전 입력에서 누적한 상태이므로, 현재 타임스텝이 끝나도 다음 타임스텝을 위해 유지해야 한다.

이 논문은 막전위와 시간축까지 고려하면 좋은 데이터플로우의 조건이 달라진다는 점을 보인다. 핵심은 **가중치만 재사용할 것이 아니라 막전위를 옮기는 비용도 줄여야 한다**는 것이다.

## 2. 계산 순서를 어떻게 바꾸는가

### 시간축이 하나 추가되면 선택지도 늘어난다

합성곱은 입력·출력 채널, 커널 위치, 출력 위치, 배치 등의 축을 따라 반복 계산한다. SNN에는 타임스텝 축이 추가된다. 논문은 한 저장 단계에서 가능한 루프 순서가 ANN의 7! = 5,040개에서 SNN의 8! = 40,320개로 늘어난다고 설명한다.

이 숫자가 전체 탐색 공간은 아니다. 각 메모리에 데이터를 얼마씩 나누어 담을지도 정해야 하기 때문이다. 따라서 기존 ANN의 계산 순서에 시간 반복만 덧붙이는 방식으로는 좋은 설계를 놓칠 수 있다.

### 세 가지 규칙으로 데이터 이동을 줄인다

**규칙 1은 한 작업의 여러 타임스텝을 연속으로 처리하는 것이다.** 어떤 출력 블록을 한 타임스텝만 계산하고 다른 블록으로 이동하는 대신, 그 블록의 여러 타임스텝을 계산한 뒤 이동한다. 막전위를 가까운 메모리에 둔 채 반복해서 사용할 수 있다.

**규칙 2는 연산 장치 옆의 작은 버퍼를 더 잘 활용하는 것이다.** 연산 장치 수를 늘리지 않고, 버퍼에 담을 계산 범위를 조정해 데이터를 더 많이 재사용한다.

**규칙 3은 시간축의 작업 일부를 연산 장치에 더 가까운 저장 단계로 옮기는 것이다.** DRAM 접근은 줄어들 수 있지만 온칩 공용 버퍼 접근이 늘어날 수 있다. 한 메모리의 비용이 줄었다고 전체 비용도 줄어드는 것은 아니므로, 남은 버퍼 용량과 전체 에너지를 함께 확인해야 한다.

| 규칙 | 기대하는 효과 | 적용할 때 확인할 점 |
|---|---|---|
| 1. 여러 타임스텝을 연속 처리 | 막전위의 반복 이동 감소 | 해당 타임스텝의 입력을 사용할 수 있는가? |
| 2. 작은 버퍼의 활용도 개선 | 가까운 메모리에서 데이터 재사용 | 어떤 계산 범위까지 버퍼에 담을 수 있는가? |
| 3. 시간축 작업의 저장 위치 조정 | 먼 메모리 접근 감소 | 다른 메모리의 접근 비용이 더 커지지 않는가? |

## 3. 어떤 조건에서 평가했는가

논문은 데이터 이동과 연산 비용을 분석하는 도구인 **Timeloop**를 사용했다. SNN의 1비트 스파이크를 반영하도록 일부 비용을 보정하고, 기준 데이터플로우 대비 에너지·지연의 곱인 **EDP**를 비교했다. 따라서 결과는 FPGA 실측값이 아니라 모델 기반 분석이다.

하드웨어 구성도 세 가지로 나눴다. Arch1은 작은 버퍼와 기본 연산 장치를 사용하고, Arch2는 버퍼를 키우며, Arch3는 버퍼와 연산 능력을 함께 늘린다. 워크로드는 일반 합성곱, 깊이별 합성곱, 1×1 합성곱이며 타임스텝 수는 100이다.

이 비교에서 **모든 작업과 하드웨어에 공통으로 가장 좋은 데이터플로우는 없었다.** 무엇을 메모리에 고정해 재사용할지에 따라 결과가 달라졌고, 일부 조건에서는 기준 대비 EDP가 최대 98% 감소했다. 이는 특정 구성의 최대 개선값이며, 모든 SNN에서 기대할 수 있는 수치는 아니다.

## 4. 우리 연구에는 어떻게 적용할 수 있는가

### 막전위와 모델 캐시가 공간을 나누는 이유를 설명한다

우리 모델은 트랙마다 뉴런 706개의 막전위를 유지한다. 막전위를 16비트로 저장하면 트랙 512개에 필요한 공간은 다음과 같다.

> 512트랙 × 706뉴런 × 2 B = 722,944 B = **706 KiB**

현재 BRAM 예산의 약 43%다. 같은 모델을 쓰는 트랙끼리 가중치는 공유해도, 입력 이력이 다르므로 막전위는 공유할 수 없다. **트랙 수가 늘면 막전위 공간은 늘어나고 모델 캐시 공간은 줄어든다.** A16은 이 비용을 SNN 데이터플로우의 일부로 다뤄야 한다는 근거가 된다.

### 시간축 재배치에는 우리 입력 조건의 제약이 있다

규칙 1과 규칙 3의 시간축 최적화는 여러 타임스텝의 작업을 묶을 수 있을 때 유용하다. 그러나 우리 입력은 32 ms 간격으로 도착한다. 아직 오지 않은 다음 입력을 앞당겨 계산할 수 없으므로, 이 시간축 재사용을 그대로 적용하기 어렵다.

대신 현재 설계는 막전위를 온칩에 보관하면서 여러 트랙을 번갈아 처리한다. 이는 상태를 매번 DRAM으로 내보냈다가 읽는 비용을 줄이려는 선택이다. **시간축 배칭이 어렵다는 사실만으로 온칩 보관이 유일한 방법이라고 결론낼 수는 없다.** 일부 상태를 오프칩에 둘 경우의 추가 대역폭과 지연도 비교할 수 있다.

### 캐시 크기를 바꾸는 실험의 근거로 삼는다

A16은 버퍼 크기를 바꾸면 유리한 데이터플로우도 달라질 수 있음을 보여준다. 우리도 모델 캐시를 5개·4개·3개 분량으로 줄이면서 같은 스케줄러를 평가할 필요가 있다.

이 실험에서는 캐시 크기별 가중치 전송량, 마감 위반율, 지연을 함께 본다. 트랙 수를 늘리는 실험과 분리하면, 성능 변화가 작업량 증가 때문인지 캐시 공간 감소 때문인지 구분하기 쉽다.

## 5. 적용 범위와 원문 확인 위치

우리 트랙 배칭은 한 모델의 가중치를 캐시에 유지하고 여러 트랙에 쓰는 방식이다. 이 점에서는 가중치를 고정해 재사용하는 **weight stationary**와 비슷하다. 다만 A16이 다루는 연산 장치 내부의 데이터플로우와, 우리가 다루는 모델·트랙 단위 스케줄링은 범위가 다르다.

또한 ‘막전위가 추가 저장 공간을 요구한다’는 사실은 이미 이 논문이 다뤘다. 우리 연구에서 검증할 부분은 여러 트랙의 상태와 여러 모델의 캐시가 같은 메모리를 나눠 쓸 때 발생하는 성능 변화다. 규칙 2의 버퍼 최적화 역시 후보가 될 수 있지만, 현재 구조에서의 이득은 별도로 측정해야 한다.

| 다시 확인할 내용 | 원문 위치 |
|---|---|
| 막전위가 추가 데이터 구조라는 문제 제기 | 초록, §2 |
| 세 가지 데이터플로우 최적화 규칙 | §3.3 |
| Timeloop를 이용한 평가 조건 | §4 |
| 규칙별 효과와 작업·구조별 최적 데이터플로우 | §5 |

관련 연구에는 ‘A16은 SNN의 막전위와 시간축을 고려한 데이터플로우 최적화가 필요하며, 최적 방식은 작업과 하드웨어 자원에 따라 달라짐을 보였다’고 요약할 수 있다. 이는 원문의 직접 인용이 아니라 내용 요약이다.
