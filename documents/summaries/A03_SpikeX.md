# A03 · SpikeX — 가중치를 덜 옮기는 SNN 가속기

> rev.2 · 2026-09-16 개정  
> Boxun Xu, Richard Boone, Peng Li · UC Santa Barbara · arXiv:2505.12292, 2025  
> 원문: `documents/papers/A03_SpikeX_2025.pdf`

## 1. 이 논문은 어떤 문제를 푸는가

SNN의 입력 스파이크는 0 또는 1이지만, 가중치는 여러 비트로 표현된다. 입력이 1이면 가중치를 더하고, 0이면 해당 연산을 생략할 수 있다. 곱셈이 단순해지는 만큼, **가중치를 메모리에서 반복해서 가져오는 비용**이 중요해진다.

SpikeX는 이 비용을 줄이는 가속기다. 한 번 읽은 가중치를 여러 계산에서 재사용하고, 스파이크가 없는 구간에서는 관련 가중치를 읽지 않는다. 여기에 학습 방법까지 맞춰, 하드웨어가 처리하기 좋은 스파이크 패턴을 만들도록 한다.

우리 연구와 연결되는 질문은 간단하다. **가중치를 한 번 가져왔을 때, 다시 가져오기 전에 얼마나 많이 쓸 수 있는가?**

## 2. 가중치 이동을 어떻게 줄이는가

### 가까운 메모리에 두고 여러 번 사용한다

가중치는 오프칩 DRAM에서 온칩 공용 버퍼(GLB), 작은 지역 버퍼(LBUF)를 거쳐 연산 장치(PE)로 이동한다. 평가 구성은 8×8 PE 배열이며, GLB는 54 KB, LBUF는 2 KB다.

버퍼는 두 공간을 번갈아 사용하는 **더블버퍼링**을 지원한다. 한 공간의 데이터를 계산에 쓰는 동안 다른 공간에는 다음 데이터를 채운다. 이렇게 전송과 연산을 겹쳐 대기 시간을 줄인다.

### 여러 타임스텝을 하나의 작업으로 묶는다

SpikeX의 기본 작업은 ‘뉴런 하나를 일정한 시간창 동안 계산하는 것’이다. 논문은 이를 NTWU라고 부른다. **시간창(TW)** 은 여러 타임스텝을 묶은 구간이고, 그 안의 타임스텝 수가 **TWS**다.

예를 들어 TWS가 4라면, 한 뉴런의 연속된 네 타임스텝을 묶어 처리한다. 네 계산에 필요한 가중치가 같으므로 한 번 읽은 가중치를 반복해서 쓸 수 있다. SpikeX는 이 재사용을 세 단계로 확장한다.

| 재사용 범위 | 같은 가중치를 다시 쓰는 방법 |
|---|---|
| 한 시간창 안 | 여러 타임스텝이 공유한다. |
| 여러 시간창 사이 | 같은 뉴런의 다른 시간창을 PE 배열에 나누어 배치하고 공유한다. |
| 여러 뉴런 사이 | 합성곱에서 같은 필터를 쓰는 출력 뉴런들이 공유한다. |

스파이크가 많으면 한 뉴런의 시간창들을 병렬로 처리한다. 스파이크가 적어 연산 장치가 비면 여러 뉴런의 작업을 섞어 배치한다. 논문의 ‘유연한 작업 배치’는 이렇게 입력의 활동량에 맞춰 배열을 채우는 방식이다.

### 스파이크가 없는 구간은 읽기부터 생략한다

입력 블록마다 ‘스파이크가 하나라도 있는가’를 나타내는 **활동 태그**를 붙인다. 여러 작은 블록의 태그를 합쳐 큰 블록의 활동 여부도 판단한다. 태그가 0이면 그 블록과 관련된 가중치를 하위 버퍼로 가져오지 않는다.

즉, 계산만 건너뛰는 것이 아니라 **계산에 쓰이지 않을 데이터의 이동도 생략**한다. 논문은 이 기법을 activation-induced weight tailoring이라고 부른다.

### 학습도 하드웨어 비용을 줄이는 방향으로 바꾼다

정확도만으로 학습하지 않고, 에너지와 지연의 곱인 **EDP**도 손실함수에 반영한다. EDP는 작을수록 좋다. 매 학습 단계에서 하드웨어를 시뮬레이션하기는 어렵기 때문에, 시뮬레이션 결과로 만든 근사 모델을 사용한다.

또한 레이어마다 적절한 시간창 크기를 탐색한다. 시간창을 크게 하면 가중치 재사용은 늘지만, 입력이 드문 상황에서는 다른 손해가 생길 수 있다. 따라서 모든 레이어에 같은 크기를 쓰는 것이 항상 최선은 아니다.

## 3. 어떤 결과를 보였는가

| 평가 항목 | 논문이 보고한 결과 | 해석 |
|---|---|---|
| 완전연결층의 에너지 구성, TWS=4 | 메모리 62%, 연산 38% | 이 조건에서는 데이터 접근 비용이 연산 비용보다 크다. |
| 같은 실험의 용도별 구성 | 가중치 접근 40.1% | 가중치 이동을 줄일 이유를 정량적으로 보여준다. |
| 같은 실험의 DRAM 비중 | 전체 에너지의 1.7% | 메모리 비용의 대부분은 온칩 접근에서 발생했다. |
| 매우 낮은 발화율에서 작업 배치 개선 | 발화율 0.01%에서 지연 약 7.11배 개선 | 희소한 작업을 배열에 잘 채우는 효과다. |
| PTB 대비 최종 EDP | 15.1~150.87배 개선 | 논문이 평가한 네트워크와 공동 최적화 조건의 결과다. |

**‘가중치 접근 40.1%’와 ‘DRAM 접근 1.7%’는 다른 분류다.** 가중치는 온칩 메모리에서도 읽으므로, 가중치 접근 비용을 모두 DRAM 비용으로 해석하면 안 된다. 이 비율이 우리 다중 모델 시스템에서도 그대로 나타난다고 볼 수도 없다.

## 4. 우리 연구에는 어떻게 적용할 수 있는가

### 시간창 대신 같은 모델의 트랙을 묶는다

SpikeX는 여러 타임스텝의 작업을 묶어 가중치를 공유한다. 우리 시스템에서는 다음 입력이 32 ms 뒤에 도착하고, 현재 입력도 32 ms 안에 처리해야 한다. 미래 입력을 충분히 모아서 시간창을 만드는 방법은 현재 지연 조건에 맞지 않는다.

대신 같은 모델을 사용하는 트랙을 연속 처리할 수 있다. 센서 A와 B가 같은 모델을 쓰면 A를 처리한 가중치를 캐시에 둔 채 B를 처리한다. **재사용 대상이 ‘한 입력의 여러 타임스텝’에서 ‘같은 모델을 쓰는 여러 트랙’으로 바뀌는 것이다.** 두 방식은 재사용 원리를 공유하지만, 작업의 도착 시점과 마감 제약은 다르다.

### 버퍼 구성과 프리페치를 참고한다

SpikeX의 계층적 버퍼와 더블버퍼링은 우리 설계의 `DDR3 → 모델 캐시 → 연산 장치` 경로를 구성할 때 참고할 수 있다. 다만 SpikeX의 지역 버퍼와 우리 모델 프리페치 버퍼는 역할과 배치가 완전히 같지는 않다. 가져올 원칙은 **현재 계산에 필요한 데이터를 유지하면서 다음 전송을 겹친다**는 점이다.

### 활동 태그는 추가 최적화로 검토한다

우리 입력의 특정 채널에 스파이크가 없다면, 첫 레이어에서 그 채널에 해당하는 가중치 384 B를 읽지 않는 방식을 검토할 수 있다. 실제 절감량은 DDR3의 전송 단위와 가중치 배치에도 영향을 받는다.

이 기법은 평균 전송량을 줄일 수 있지만, 모든 입력 채널이 활성화되는 최악의 경우에는 도움이 되지 않는다. 따라서 32 ms 마감 가능 여부는 읽기 생략이 없는 조건으로 먼저 계산하고, 태그의 효과는 별도로 측정하는 편이 적절하다.

## 5. 적용 범위와 원문 확인 위치

SpikeX는 여러 모델의 캐시 경쟁이나 요청별 마감 시간을 해결한 논문은 아니다. 우리 연구가 참고할 부분은 가중치 재사용과 데이터 이동을 줄이는 구조다. 캐시 계층, 활동 태그, 더블버퍼링 자체를 새 기법으로 주장해서는 안 된다.

하드웨어 비용을 학습에 넣는 방법도 확장 아이디어가 될 수 있다. 다만 현재 연구의 중심은 스케줄러이므로, 학습까지 바꾸는 작업은 별도 과제로 두는 것이 적절하다.

| 다시 확인할 내용 | 원문 위치 |
|---|---|
| 스파이크와 가중치의 비트 수 차이, 가중치 이동을 줄이는 이유 | §II-B |
| 발화율에 따라 달라지는 작업 배치와 시간창 크기의 효과 | §VI-A |
| 메모리 62%, 가중치 접근 40.1%의 에너지 분석 | §VI-B |

이 논문을 관련 연구에 서술할 때는 ‘SpikeX는 시간·공간 방향의 가중치 재사용과 활동 기반 읽기 생략으로 데이터 이동을 줄였다’고 요약할 수 있다. 이는 원문의 직접 인용이 아니라 내용 요약이다.
